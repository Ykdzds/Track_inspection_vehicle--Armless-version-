# 13号屏：历史回复过期、基础区未更新分析与复测

日期：2026-10-16。仅修改13号屏；F4、08号及F103参考工程不修改。

## 一、可以由现场证据确定的结论

1. 本次屏发送流中有210条完整03H请求：0000H/64字53条，0460H/64字157条。全部CRC正确；没有0200H元数据或0050H/0070H/0090H/00B0H辅助请求。
2. 主控发送流中可提取68条完整133字节响应：基础区17条，控制状态51条，全部CRC正确。抓包头还有6字节不能构成完整响应；保留为前缀，不作为完整帧或固件启动报文。
3. 三次F4诊断依次为1171/1171、1294/1294、1358/1358请求/响应；CRC、UART错误、发送错误均为0。基础区响应计数265→290→303，控制状态906→1004→1055，元数据和其余旧区始终为0。
4. 因此不能再把现象解释成“F4不回复”。屏端已接受过至少一条回复，但没有把基础区成功发布给主页；请求调度也未覆盖所需区域。这是两个需要分别验证的环节，不是改主页文案就能解决。
5. 元数据缺失使正式协议身份、boot及R2能力无法建立，旧页处于未知，运动授权也不应放行。当前主控回复中两轴online均为0，控制状态有效位也未表示有效速度，不能开展带速验收。
6. 两方向是分开采集且无逐帧时间戳，210与68不能相减推导丢包率，也不能用该文本证明100/200ms时效已达标。

## 二、为什么通信文案交替

主页原判定为：基础区尚未提交且全局有效RX大于0时，显示“已收到回复，基础区未更新”；距离最后一次被屏脚本接受的回复达到500逻辑ms后，改显示“历史回复已过期”。新回调又可能更新该时间，文案便来回切换。

这是屏本地业务缓存新鲜度，不等于主控停止发送。F4发送计数正常也不能反向证明屏物理RX、厂商回调字段、在途匹配和缓存提交全部正确。

## 三、本轮代码变更与证据边界

- 调度不再使用`hSelected=0-1`及`hSelected<0`，改用明确的非负空闲值8；区域0仍为合法基础区索引。
- 初始化和发送时，八个区域的上次请求时间改为固定索引逐项赋值，消除`vals[48+hSelected]`这条运行时动态寻址路径；基础区、元数据和辅助区继续分别限频，未降低目标/状态优先级。
- 解析旧区时把寄存器地址计算拆成各区域固定基址；区域标志使用本地索引。站号、索引、起始地址、数量、读写类型仍必须全部匹配，不把拒收改成无条件接收。
- B0与B7都是133字节，03H响应不携带原请求地址。增加已知载荷身份排错：B7必须为534DH/修订2；B5必须为5249H/主版本1；B0不得接收带B7身份的载荷。该检查不能声称解决所有等长迟到包关联问题。
- P2增加回调总数、基础区成功数、元数据成功数及保留的最近B0回调现场，避免最新B7事件覆盖B0拒收证据。
- 所有运动授权、会话、boot、目标有效期、停车关联及断线清零规则保留。未增加屏端密码、长按或二次确认。

**重要：现场已证实“调度缺区和B0未提交”，但尚未证实厂商运行时究竟在哪条表达式或回调字段上产生偏差。上述改动是消除可疑实现路径并增强定位，不宣称已在真屏复现并根治；最终以下载本版后的回调读数和抓包复测闭环。JS等价测试不会模拟厂商虚拟机或物理接收。**

## 四、P2新诊断怎么读

P2每2秒交替显示主控统计与带`HMI`前缀的屏本地统计。请至少连续拍摄/录像5秒。

| 显示 | 含义与正常预期 |
|---|---|
| HMI服务 / 回调 | 服务及厂商回调累计次数，均应持续增长 |
| HMI有效RX / B0 / B5 | 通过全部匹配并提交的响应、基础区和元数据次数，B0/B5均应增长 |
| HMI B0：C I A N | 最近B0相关回调：成功C=1，I=0，A=0，N=64；C=2为原生读失败 |
| HMI B0拒因 / 忙 / 类 | 正常拒因0，忙1、类1；拒因1无在途、2站号错、3索引错、4地址错、5数量错、6类型错、7载荷身份错 |
| HMI失配 / 无回调 / 超时 | 累计失配、本地80ms逻辑看门狗、原生失败次数；不要与F4串口错误计数混淆 |

若B5/B0发出了但回调总数不增长，检查屏RX和厂商接收；若有回调但拒因非0，保存上述实际字段，不能删掉匹配条件“强行打通”。若仍只发B0/B7，先核实下载文件哈希、工程路径和完整断电重启，再提供新抓包。

## 五、下载后先只读，不直接测速度

1. 下载本轮重新编译的`13_轨道巡检车.pix.bin`，记录下方版本记录中的新SHA-256，完整断电重启。F4不需要因本问题重新刷写。
2. 屏TX接PD2，屏RX接PC12，共地；115200/8N1，确认接口电平；断开F103发送端，USB监听器只接RX与地，不并入另一个TX。
3. 不授权，检查线上出现0200H、0460H、0000H及四个辅助区请求，元数据53字节和状态133字节完整。
4. 同时拍P2新诊断和主页，保存相隔10秒的两次`hmi status`。屏端B0/B5成功数增长，页面才算真实接受成功；电脑看到回应不替代该条件。
5. 未接伺服或伺服反馈无效时，应显示主控已回复但伺服状态无效/断开，不应伪造速度0或允许运动。正常通信不以电机是否连接为前提。
6. 通信连续10分钟、旧页面逐页正常、反馈有效后，再按原联调说明做主动授权零速、取消/急停确认，最后才放行架空低速±50/±100rpm。
