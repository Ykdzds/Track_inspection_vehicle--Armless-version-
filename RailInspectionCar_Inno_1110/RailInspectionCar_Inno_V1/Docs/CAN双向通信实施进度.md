# CAN双向通信实施进度

日期：2026-10-09

## 当前结论

固件已接入CAN双向通信业务，可以开始CAN分析仪及RK3588实物联调。
这不表示实物链路已验收；当前没有CAN分析仪或RK接线实测记录。
本阶段只支持通信，不支持CAN运动控制、使能、停车或里程清零。

## 当前已实现

- CAN1使用PA11/PA12，APB1为42 MHz，分频6、BS1=11、BS2=2、SJW=1，速率500 kbit/s；生成代码和CubeMX `.ioc`已同步。
- BSP实现过滤器、四路中断、64条普通RX队列、`0x080`独立优先接收、三邮箱及非阻塞Bus-off恢复。
- CAN任务优先级3、栈768 word，每轮有界处理，持续流量下主动让出CPU；不等待邮箱或发送完成。
- 协议实现显式小端编码、CRC32、最大256字节扩展记录及200 ms重组期限，包含重复、乱序、缺段和Tick回绕处理。
- 实现boot握手、会话邀请/确认、三个递增健康心跳门禁、失联及上层重启后的会话重建。
- 上传基本状态、能力、当前配置、控制权、健康、恢复、双轴位置、里程、同步及通信统计；未接入的数据发送未知值。
- 接收上层能力及任务、采集、存储、定位、相机等只读状态；完整记录校验后才原子发布。
- 支持`0x08`读取记录、`0x0A`读取能力配置，实施去重、限频及接受/完成区分；其他控制请求明确拒绝。
- 配置直接读取当前工程宏和快照，使用指纹管理配置版本；Flash扇区11追加日志保存跨复位身份及通信编号块，不运行期擦写。
- 九个生产源已登记Keil，程序区限制为前896 KiB；新增配置一致性、链接区域和任务静态栈检查。
- USART1调试使用静态日志队列和现有DMA通道，限频并预留CLI空间；提供`can status`、`can stat`、`can upper status`。

## 软件验证

- CAN专项测试已通过，包括协议、握手、身份日志、上层缓存、状态编码、APP调度、日志预算及BSP寄存器模拟。
- 完整主机回归已通过；主机模拟结果不能替代实际总线及驱动器验证。
- 三种轴配置各自调试开关0/1共六组、CAN关闭、只读及最终当前配置共九组Keil全量编译均为0错误、0警告；最终产物已恢复为原工作区配置。
- 九组配置一致性、Flash链接边界及任务静态栈检查均通过。日志位于本机临时目录，名称为`can_matrix_1_0.log`至`can_matrix_3_1.log`、`can_disabled.log`、`can_readonly.log`及`can_final_current.log`。
- 当前配置链接末端为`0x0802BEEC`，低于日志区起点`0x080E0000`；CAN任务保守静态栈深度1040字节，分配3072字节，仍需实测高水位。
- `Docs/CAN_V1_编码测试向量.md`由生产代码生成，覆盖握手、配置、查询、拒绝及上层状态，不是分析仪实测记录。
