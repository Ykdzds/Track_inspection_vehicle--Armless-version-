# 轨道巡检车车载屏界面与通信协议设计方案

**文档版本：** V1.0  
**编制日期：** 2026年9月23日  
**适用项目：** 同济大学1435轨道巡检车  
**适用屏幕：** WS-VS10-04M-R，10寸串口屏-S系列  
**屏幕分辨率：** 1024×600，横屏  
**屏端工程基线：** `用户代码\04_轨道巡检车启动页`  
**本阶段范围：** 仅定义车载屏界面和屏端通信协议，不修改STM32工程

## 1. 设计目标

车载屏用于显示轨道巡检车底盘、伺服、电源和诊断信息，并向STM32发送经过权限限制的操作事件。

本设计遵循以下原则：

1. 车载屏只提供人机交互，不直接操作定时器、GPIO或伺服寄存器。
2. STM32是运动安全和控制决策的唯一执行主体。
3. 屏幕显示采用周期读取方式，保证断线、重启和通信恢复后状态能够重新同步。
4. 所有运动相关操作必须经过STM32状态机、安全门禁和速度限制检查。
5. 启动页不提供运动、使能、模式切换和参数写入按钮。
6. 屏幕通信异常时不得自动恢复运动，也不得自动发送上一次未完成的命令。

## 2. 硬件和通信边界

### 2.1 屏幕和主控角色

车载屏建议作为 **Modbus RTU主站**，STM32作为 **Modbus RTU从站**。

原因如下：

- 屏幕需要主动周期读取状态，适合由屏幕统一发起轮询；
- STM32不需要主动向屏幕推送异步数据，降低协议并发和缓存复杂度；
- 屏幕重启后可以自行重新读取全部状态；
- 屏幕通信异常不会阻塞底盘运动任务；
- 后续由UART直连切换为RS485时，页面寄存器和事件协议无需改变。

### 2.2 当前联调方式

第一阶段屏端先按已确认参数配置：

| 项目 | 参数 |
|---|---|
| 逻辑协议 | Modbus RTU |
| 屏幕角色 | 主站 |
| STM32角色 | 从站 |
| STM32从站地址 | `1` |
| 波特率 | `115200` |
| 数据位 | `8` |
| 校验 | 无校验 |
| 停止位 | `1` |
| 屏幕轮询周期 | `200 ms` |
| 读状态功能码 | `03H` |
| 默认响应超时 | `50 ms` |
| 最大连续失败判定 | 10次 |
| 物理层 | 先按UART5直连联调，后续切换RS485 |

当前项目已确认车载屏侧后续使用UART5连接RS485收发器。STM32侧UART5的已知引脚为TX=`PC12`、RX=`PD2`，收发器采用硬件自动流向控制。由于通信距离较近，暂不设置120欧姆终端电阻；正式整车布线后仍需根据波形和总线拓扑复核。

### 2.3 屏端禁止事项

屏端不得直接实现以下动作：

- 直接写TIM9、TIM11；
- 直接控制PC8、PC9；
- 直接控制PB0、PB1；
- 直接写AIMtor伺服寄存器；
- 绕过STM32状态机发送使能、速度或位置命令；
- 在通信恢复后自动恢复运动；
- 用软件页面逻辑替代急停、STO、硬件限位或主回路分断。

## 3. 屏幕整体界面结构

建议采用以下页面结构：

```text
P0 启动诊断页
 ├─ 正常完成后自动进入 P1 主运行页
 ├─ 通信超时后进入 P1，但保持 OFFLINE 和运动锁定
 └─ 初始化异常后进入 P1，但保持 SAFE/FAULT/OFFLINE

P1 主运行页
 ├─ 实时状态和双轴数据显示
 ├─ 停止按钮
 ├─ 故障复位按钮
 └─ 页面导航

P2 伺服与通信诊断页
 ├─ 左右伺服在线、故障和状态字
 ├─ Modbus通信统计
 └─ 只读参数查看

P3 维护测试页
 ├─ 需要权限或维护开关
 ├─ 低速单轴测试
 ├─ 速度模式、位置模式、脉冲位置模式测试
 └─ 所有命令由STM32二次校验

P4 系统信息页
 ├─ 软件版本
 ├─ 协议版本
 ├─ 复位原因
 ├─ 诊断故障
 └─ 任务和通信健康信息
```

第一阶段优先实现P0启动诊断页。P1至P4先保留界面和协议边界，具体控件可以分阶段增加。

## 4. 界面视觉规范

### 4.1 颜色

| 用途 | 建议颜色 | 说明 |
|---|---|---|
| 页面背景 | `#0B1117` | 深黑蓝，减少夜间眩光 |
| 主文字 | `#FFFFFF` | 产品名称和关键数据 |
| 辅助文字 | `#B8C2CC` | 单位、说明和次要信息 |
| 正常 | `#35D07F` | 在线、完成、允许 |
| 初始化 | `#3FA7FF` | 启动中、检测中 |
| 警告 | `#F2C94C` | SAFE、参数未确认、等待 |
| 故障 | `#FF5C5C` | 故障、离线、通信失败 |
| 分隔线 | `#263442` | 区域分隔 |
| 数据面板 | `#111B24` | 与页面背景形成轻微层次 |

红色只用于故障和异常提示，不使用大面积红色背景。

### 4.2 字体和排版

- 产品名称使用大号粗体，建议32至40像素；
- 页面标题建议24至30像素；
- 关键状态建议24至32像素；
- 普通状态和辅助信息建议18至22像素；
- 数值和单位分开显示，避免动态数值变化造成布局跳动；
- 所有中文文本使用屏端已配置的GBK字体资源；
- 页面边距建议24至32像素，状态卡片之间保留16至24像素间距；
- 控件文字不得超出父控件，动态故障信息需要预留足够宽度。

## 5. P0启动诊断页设计

### 5.1 页面用途

启动页只显示控制器初始化过程和安全诊断，不提供运动控制。

### 5.2 布局

屏幕尺寸为1024×600，建议布局如下：

```text
┌──────────────────────────────────────────────────────────────┐
│ 1435轨道巡检车                         软件 V1.0.0  协议 V1 │ 0~90
│ 底盘控制系统                                                     │
├──────────────────────────────────────────────────────────────┤
│                         系统启动中                             │
│                    正在初始化控制器                            │ 110~390
│                 [================----] 80%                       │
├──────────────────────────────────────────────────────────────┤
│ 控制器通信  正常   左伺服通信  等待   右伺服通信  等待          │
│ 安全状态    SAFE                                                │ 420~540
│ 复位原因：上电复位                         故障：无             │ 540~600
└──────────────────────────────────────────────────────────────┘
```

### 5.3 显示字段

启动页至少包含：

- 产品名称：`1435轨道巡检车`
- 子标题：`底盘控制系统`
- 软件版本：例如`V1.0.0`
- 协议版本：例如`V1`
- 主状态：`系统启动中`、`初始化完成`、`初始化异常`
- 当前阶段：硬件初始化、RTOS初始化、通信初始化等
- 初始化进度：0至100%
- 控制器通信：正常、异常、断开
- 左伺服通信：在线、离线、等待
- 右伺服通信：在线、离线、等待
- 安全状态：`SAFE`、`READY`、`RUNNING`、`FAULT`、`OFFLINE`
- 最近复位原因
- 当前主故障码和简短故障描述

### 5.4 启动阶段编码

| 编码 | 阶段 | 进度建议 | 颜色 |
|---:|---|---:|---|
| 0 | BOOT | 0% | 蓝色 |
| 1 | 硬件初始化 | 20% | 蓝色 |
| 2 | RTOS初始化 | 40% | 蓝色 |
| 3 | 通信初始化 | 60% | 蓝色 |
| 4 | 伺服状态检测 | 75% | 蓝色 |
| 5 | 安全门禁检查 | 90% | 黄色 |
| 6 | 初始化完成 | 100% | 绿色 |
| 7 | 初始化故障 | 保持当前进度 | 红色 |

### 5.5 自动跳转规则

启动页至少保持2秒。满足以下条件后跳转P1：

1. 已收到至少两次连续有效的STM32状态响应；
2. 初始化阶段为`6`；
3. 没有阻止系统显示的致命通信故障。

启动页最多等待10秒。10秒内无有效响应时：

- 显示`控制器通信失败`；
- 系统状态显示`OFFLINE`；
- 自动进入P1；
- 所有运动相关操作保持锁定；
- 不发送任何自动恢复或运动命令。

伺服离线、参数未确认或安全门禁未满足，不阻止进入P1，但P1必须明确显示`SAFE`或`OFFLINE`，运动操作保持禁用。

## 6. P1主运行页设计

### 6.1 页面用途

主运行页用于驾驶员查看车辆整体状态和执行有限的安全操作。第一阶段建议只开放停止和故障复位，速度、位置和模式控制放在维护页并增加权限门禁。

### 6.2 布局建议

```text
┌──────────────────────────────────────────────────────────────┐
│ 轨道巡检车运行状态                         [SAFE] [时间]      │
├──────────────────────┬──────────────────────┬────────────────┤
│ 左轮                 │ 车辆状态             │ 右轮           │
│ 速度：0.00 m/s       │ SAFE                 │ 速度：0.00 m/s │
│ 命令位置：0.00 m     │ 通信：正常           │ 命令位置：0.00m│
│ 伺服：离线           │ 门禁：未满足         │ 伺服：离线     │
├──────────────────────┴──────────────────────┴────────────────┤
│ 复位原因：上电复位    最近故障：无            Modbus：正常     │
├──────────────────────────────────────────────────────────────┤
│                         [停止] [故障复位] [诊断] [系统信息]     │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 主运行页按钮

| 按钮 | 默认状态 | 屏端行为 |
|---|---|---|
| 停止 | 可用 | 发送停止事件，STM32决定正常停机或立即停机 |
| 故障复位 | 有故障时可用 | 发送故障复位事件，STM32检查条件后执行 |
| 诊断 | 可用 | 跳转P2 |
| 系统信息 | 可用 | 跳转P4 |

屏端不根据自身页面状态判断是否可以运动，所有按钮可用性只作为提示；最终权限必须由STM32决定。

## 7. P2伺服与通信诊断页

建议显示：

- 左伺服：在线、状态字、故障码、实际速度、实际位置、当前模式；
- 右伺服：在线、状态字、故障码、实际速度、实际位置、当前模式；
- Modbus请求数、响应数、重试数、超时数、CRC错误数、异常响应数；
- 控制器最近心跳年龄；
- 安全门禁未满足的具体项目；
- 当前通信状态和最近一次错误。

P2默认只读，不提供参数写入。后续如需加入写入功能，必须增加维护权限、二次确认、写后回读和失败锁定。

## 8. P3维护测试页

### 8.1 使用条件

维护测试页必须同时满足：

- 维护权限已开启；
- 车辆动力断开或处于明确的台架测试条件；
- STM32状态机允许维护测试；
- 当前速度为零；
- 急停、STO和硬件安全回路状态正常；
- 测试速度不超过项目规定的低速上限。

### 8.2 测试模式

维护页预留三种伺服测试：

1. 速度模式；
2. 位置模式；
3. 脉冲位置模式。

屏端只发送“测试请求、目标参数和停止请求”，不直接决定脉冲频率、寄存器地址或运动许可。STM32应负责：

- 参数范围检查；
- 模式切换互锁；
- 伺服停止后切换模式；
- 双轴联停；
- 通信超时处理；
- 速度、位置和加速度限制。

### 8.3 维护测试按钮

建议控件：

- 进入维护模式；
- 退出维护模式；
- 选择轴：左轴、右轴、双轴；
- 选择模式：速度、位置、脉冲位置；
- 设置目标速度；
- 设置目标距离或目标位置；
- 开始测试；
- 正常停止；
- 立即停止；
- 故障复位。

这些控件默认锁定，只有STM32返回维护许可后才允许操作。

## 9. P4系统信息页

显示内容包括：

- 控制器软件版本；
- 屏幕工程版本；
- Modbus协议版本；
- 最近复位原因；
- 当前诊断故障位；
- 关键任务心跳状态；
- 关键任务栈余量；
- IWDG状态；

- 屏端工程编译日期。

## 10. Modbus寄存器设计

### 10.1 通用约定

- 从站地址：`1`；
- 寄存器地址按16位保持寄存器编号定义；
- 屏幕使用功能码`03H`读取状态；
- 屏幕使用功能码`06H`或`10H`发送事件和参数；
- 16位数据按Modbus高字节在前传输；
- 32位数据采用两个连续保持寄存器，默认高字在前；
- 有符号量使用二进制补码；
- 浮点量优先由STM32转换为工程单位的定点整数，避免屏端浮点兼容问题；
- 写命令必须带命令序号，STM32执行后返回结果和序号；
- 屏幕不得重复发送未确认的运动命令，除非用户明确再次操作。

### 10.2 系统状态寄存器`0x0000~0x001F`

| 地址 | 名称 | 类型 | 说明 |
|---:|---|---|---|
| `0x0000` | 系统状态 | U16 | BOOT、SAFE、READY、RUNNING、STOPPING、FAULT、OFFLINE |
| `0x0001` | 初始化阶段 | U16 | 见启动阶段编码 |
| `0x0002` | 初始化进度 | U16 | 0~100 |
| `0x0003` | 安全门禁状态 | U16 | 位定义见下表 |
| `0x0004` | 主故障码 | U16 | 当前系统主故障 |
| `0x0005` | 诊断故障低16位 | U16 | 故障位图低字 |
| `0x0006` | 诊断故障高16位 | U16 | 故障位图高字 |
| `0x0007` | 最近复位原因 | U16 | 上电、看门狗、断言、软件复位等 |
| `0x0008` | 左伺服在线 | U16 | 0离线，1在线 |
| `0x0009` | 右伺服在线 | U16 | 0离线，1在线 |
| `0x000A` | 左伺服故障 | U16 | 0无故障，非0为故障码 |
| `0x000B` | 右伺服故障 | U16 | 0无故障，非0为故障码 |
| `0x000C` | 参数核验状态 | U16 | 参数确认位图 |
| `0x000D` | 控制器软件版本 | U16 | 例如V1.0.0编码为0x0100 |
| `0x000E` | 协议版本 | U16 | 当前协议版本 |
| `0x000F` | 初始化完成标志 | U16 | 0未完成，1完成 |
| `0x0010` | 控制器通信心跳 | U16 | 每次状态刷新递增 |
| `0x0011` | 屏幕命令处理序号 | U16 | 最近已处理命令序号 |
| `0x0012` | 屏幕命令结果 | U16 | 成功、拒绝、参数错误、超时等 |
| `0x0013` | 最近命令类型 | U16 | 最近处理的事件类型 |
| `0x0014` | 最近命令错误码 | U16 | 最近命令拒绝原因 |
| `0x0015` | 屏幕通信允许 | U16 | 0禁止，1允许 |
| `0x0016` | 维护模式状态 | U16 | 0关闭，1请求中，2已进入 |
| `0x0017` | 运动操作锁定 | U16 | 0未锁定，1锁定 |

### 10.3 安全门禁位图

`0x0003`和`0x000C`采用以下位定义：

| 位 | 含义 |
|---:|---|
| bit0 | 输出极性已确认 |
| bit1 | 方向定义已确认 |
| bit2 | 伺服地址已确认 |
| bit3 | 脉冲格式已确认 |
| bit4 | 电子齿轮已确认 |
| bit5 | 伺服软件使能已确认 |
| bit6 | 维护停止条件已确认 |
| bit7 | 左右伺服均在线 |
| bit8 | 左右伺服均无故障 |
| bit9 | 允许进入READY |
| bit10 | 急停回路正常 |
| bit11 | STO状态正常 |
| bit12 | 硬件限位状态正常 |
| bit13~15 | 保留 |

只有STM32返回允许状态后，屏端才显示可操作，但最终执行权仍属于STM32。

| 地址 | 名称 | 类型 | 单位/说明 |
|---:|---|---|---|

| `0x0021` | 左轴控制模式 | U16 | 速度、位置、脉冲位置 |

| `0x0026` | 左轴实际位置高字 | U16 | 若驱动器提供 |
| `0x0027` | 左轴实际位置低字 | U16 | 若驱动器提供 |
| `0x0028` | 左轴故障码 | U16 | 0无故障 |
| `0x0029` | 左轴使能状态 | U16 | 0失能，1使能 |

| `0x0031` | 右轴实际位置低字 | U16 | 若驱动器提供 |
| `0x0032` | 右轴故障码 | U16 | 0无故障 |
| `0x0033` | 右轴使能状态 | U16 | 0失能，1使能 |
| `0x0034` | 当前车辆速度 | S16 | 单位0.001 m/s |
| `0x0035` | 当前车辆转向率 | S16 | 预留 |
| `0x0036` | 当前运动任务 | U16 | 空闲、速度、位置、维护测试 |
| `0x0037` | 运动剩余时间 | U16 | 单位ms，预留 |

### 10.5 通信和健康统计寄存器`0x0050~0x006F`

| 地址 | 名称 | 说明 |
|---:|---|---|
| `0x0050` | Modbus请求数 | 屏端请求被处理总数 |
| `0x0051` | Modbus响应数 | 正确响应总数 |
| `0x0052` | Modbus重试数 | 重试总数 |
| `0x0053` | Modbus超时数 | 屏端或控制器统计的超时数 |
| `0x0054` | CRC错误数 | CRC错误总数 |
| `0x0055` | 帧错误数 | 格式或长度错误总数 |
| `0x0056` | 异常响应数 | Modbus异常响应总数 |
| `0x0057` | UART错误数 | UART错误总数 |
| `0x0058` | 左轴状态刷新年龄 | 单位ms |
| `0x0059` | 右轴状态刷新年龄 | 单位ms |
| `0x005A` | motion任务心跳年龄 | 单位ms |
| `0x005B` | servo_comm任务心跳年龄 | 单位ms |
| `0x005C` | health任务心跳年龄 | 单位ms |
| `0x005D` | IWDG允许喂狗 | 0不允许，1允许 |
| `0x005E` | 最后失活任务 | 任务编号 |
| `0x005F` | 最小栈余量 | words |

32位累计计数可以从后续扩展寄存器读取高低字，第一阶段只要求页面显示16位低字和异常状态。

## 11. 屏端事件和写寄存器设计

### 11.1 事件原则

屏端按钮事件采用“命令序号+命令类型+参数”的方式发送。STM32必须返回处理结果。事件不会直接映射为底层寄存器写入。

建议事件区：

| 地址 | 名称 | 类型 | 说明 |
|---:|---|---|---|
| `0x0100` | 命令序号 | U16 | 屏端每次新命令递增 |
| `0x0101` | 命令类型 | U16 | 见命令类型表 |
| `0x0102` | 命令目标 | U16 | 0系统，1左轴，2右轴，3双轴 |
| `0x0103` | 命令参数1 | S16/U16 | 速度、模式或选项 |
| `0x0104` | 命令参数2 | S16/U16 | 位置、时间或停止方式 |
| `0x0105` | 命令参数3 | U16 | 保留 |
| `0x0106` | 命令校验标志 | U16 | 固定魔数或协议版本 |
| `0x0107` | 命令提交 | U16 | 写入固定值后提交 |
| `0x0108` | 命令处理状态 | U16 | 由STM32返回 |
| `0x0109` | 命令错误码 | U16 | 由STM32返回 |
| `0x010A` | 已处理命令序号 | U16 | 由STM32返回 |

### 11.2 命令类型

| 编码 | 命令 | 第一阶段状态 |
|---:|---|---|
| `0x0000` | 无命令 | 默认 |
| `0x0001` | 页面心跳 | 允许 |
| `0x0002` | 请求正常停止 | 允许 |
| `0x0003` | 请求立即停止 | 需硬件安全条件确认 |
| `0x0004` | 请求故障复位 | 允许 |
| `0x0005` | 请求进入维护模式 | 需权限和零速 |
| `0x0006` | 请求退出维护模式 | 允许 |
| `0x0010` | 速度模式测试 | 维护专用 |
| `0x0011` | 位置模式测试 | 维护专用 |
| `0x0012` | 脉冲位置模式测试 | 维护专用 |
| `0x0013` | 停止维护测试 | 允许 |
| `0x0020` | 请求参数读取 | 只读 |
| `0x0030` | 参数写入请求 | 默认禁止 |

### 11.3 命令处理状态

| 编码 | 含义 |
|---:|---|
| `0` | 无结果 |
| `1` | 已接收 |
| `2` | 执行中 |
| `3` | 执行成功 |
| `4` | 被安全门禁拒绝 |
| `5` | 参数错误 |
| `6` | 当前状态不允许 |
| `7` | 通信超时 |
| `8` | 执行失败 |

### 11.4 命令提交建议

屏端发送命令时建议执行以下顺序：

1. 写入`0x0100~0x0106`；
2. 写入`0x0107`提交值；
3. 周期读取`0x0108~0x010A`；
4. 等待结果或超时；
5. 显示结果；
6. 不自动重发运动命令。

命令提交值建议固定为`0xA55A`。STM32收到后检查命令序号是否为新值，再执行一次并记录已处理序号。

## 12. 屏端通信状态机

```text
SCREEN_BOOT
    ↓
WAIT_CONTROLLER
    ├─ 连续2次有效响应 ─→ SHOW_BOOT_STATUS
    ├─ 连续3次失败 ────→ SHOW_COMM_WARNING
    └─ 连续10次失败 ───→ SHOW_OFFLINE

SHOW_BOOT_STATUS
    ├─ 初始化完成且保持至少2秒 ─→ P1_MAIN
    ├─ 伺服离线/参数未确认 ────→ P1_MAIN_SAFE
    └─ 初始化故障 ────────────→ P1_MAIN_FAULT

P1_MAIN
    ├─ 周期读取状态
    ├─ 处理按钮事件
    └─ 通信失败 ─→ P1_OFFLINE

P1_OFFLINE
    ├─ 持续显示OFFLINE
    ├─ 禁用运动操作
    └─ 恢复有效响应 ─→ 重新同步状态
```

通信恢复后只恢复显示，不恢复之前的运动命令、使能命令或模式切换命令。

## 13. 三种伺服模式的屏端适配

### 13.1 速度模式

屏端发送：

- 目标轴；
- 目标速度；
- 加速度；
- 减速度；
- 测试开始或停止。

STM32负责：

- 检查维护模式；
- 检查动力和急停条件；
- 检查速度上限；
- 设置AIMtor速度模式；
- 执行双轴联锁和停止；
- 返回命令状态。

### 13.2 位置模式

屏端发送：

- 目标轴；
- 目标位置或位移；
- 最大速度；
- 加速度；
- 减速度；
- 测试开始或停止。

STM32负责：

- 检查当前位置基准；
- 检查目标范围；
- 进行模式切换互锁；
- 等待伺服停止后改变模式；
- 返回完成、超时或故障状态。

### 13.3 脉冲位置模式

屏端发送：

- 目标轴；
- 方向；
- 脉冲数量或目标距离；
- 最大脉冲频率；
- 加减速参数；
- 测试开始或停止。

STM32负责：

- 输出脉冲和方向；
- 管理PC8/PC9和AM26C31使能；
- 执行方向切换前减速到零；
- 检查脉冲格式和电子齿轮；
- 在异常时同时停止两轴。

屏端不得把脉冲频率直接写入定时器，也不得绕过STM32发送底层脉冲控制命令。

## 14. 通信异常与安全策略

### 14.1 屏幕读取失败

- 连续1至2次失败：保持上一帧显示，并标记短暂异常；
- 连续3次失败：显示`控制器通信：异常`；
- 连续10次失败：显示`控制器通信：断开`，进入OFFLINE；
- 任何通信失败都不自动发送运动或复位命令；
- 恢复后重新读取状态，运动许可由STM32重新判断。

### 14.2 控制器返回故障

屏端必须显示：

- 故障级别；
- 主故障码；
- 左右轴故障码；
- 最近复位原因；
- 安全门禁未满足项目。

故障复位按钮只能发起请求，不能在屏端直接清除故障。

### 14.3 数据新鲜度

屏端应记录每类数据的最近成功读取时间。超过设定时间未更新的数据标记为`数据过期`，不显示为正常实时值。

## 16. 验收标准

### 16.1 页面

- 上电后能稳定显示P0启动页；
- 背景为深色，主文字为白色；
- 初始化阶段和进度显示正确；
- 控制器、左右伺服和安全状态区分明确；
- 故障状态使用红色提示，不出现整页误红；
- 初始化完成后能自动进入P1；
- 控制器无响应时进入OFFLINE；
- 屏端不提供启动阶段运动按钮。

### 16.2 协议

- 屏端作为Modbus RTU主站；
- STM32从站地址为1；
- 03H状态读取周期约200ms；
- 数据地址和位定义固定；
- 写命令带序号并可读取处理结果；
- 通信失败、CRC错误、异常响应和超时能够显示；
- 通信恢复后不会自动恢复运动；
- 屏端不直接访问底盘硬件资源。

### 16.3 联调

- 可用模拟从站返回正常启动数据；
- 可模拟伺服离线和参数未确认；
- 可模拟控制器断线；
- 可验证停止、故障复位和维护请求的命令序号；
- 后续STM32适配时无需修改页面基本布局和协议定义。

## 17. 后续STM32适配边界

本文件只规定屏端设计。后续STM32工程需要实现：

1. UART5或RS485物理链路；
2. Modbus从站地址1；
3. `03H`状态寄存器；
4. `06H/10H`事件寄存器；
5. 命令序号去重；
6. 安全门禁和运动状态机；
7. 命令结果和错误码；
8. 伺服、脉冲、停止和故障联动；
9. 通信异常下的安全处理；
10. 与本方案一致的版本和诊断字段。

任何STM32侧实现如果无法满足安全门禁，屏端必须继续显示`SAFE`、`FAULT`或`OFFLINE`，不得仅通过屏端操作开放运动。
