# 伺服诊断参数采集与0x89回传实施说明

## 范围与寄存器依据

仅采集当前查询配置选中的轴，诊断数据不参与授权、同步补偿或停车判定。
现有控制协议与0x81～0x88字段不变，两端固件必须配套升级。

依据工程Modbus控制说明及《AIMtor低压产品使用说明书20260508》H0B监视表：

| 参数 | 地址 | 字数 | 原始单位 | 回传单位 |
| --- | --- | --- | --- | --- |
| H0B_02内部实时转矩 | 0x0B02 | 1，Int16 | 0.1% | 0.1% |
| H0B_12平均负载 | 0x0B0C | 1，Int16，非负 | 0.1% | 0.1% |
| H0B_24相电流有效值 | 0x0B18 | 2，Int32 | 0.01A | 0.1A |
| H0B_26母线电压 | 0x0B1A | 1，UInt16 | 0.1V | 0.1V |

参数编号24为十进制，地址为0x0B18，不是0x0B24。32位值按工程H0C_26=1配置，低16位在前；每个寄存器内部仍为大端字节。
电流1234表示12.34A，四舍五入至0.1A后回传123，显示12.3A；不是123.4A。负数对称四舍五入。
拒绝转矩超出±3000、负载超出0～5000、电流超出±120000、母线电压超出0～9999的原始值；保持末次缓存并标记陈旧。
地址、类型和缩放仍需对当前实物型号抓包并与驱动器面板核验，本次未进行实机采集。

## 采集优先级与缓存

`APP_SERVO_DIAGNOSTIC_POLL_MS=1000`：逐字段成功读取后约1秒再次读取。
`APP_SERVO_DIAGNOSTIC_RETRY_MS=200`：失败后后台补采，不在总线上自动重试。
共享现有RS485任务，顺序低于关键速度/故障、配置动作、位置和状态轮询；受控遥控停车及启动恢复期间不新增诊断轮询。人工停车完成后允许后台采集。
总线饱和时允许诊断延后，不能抢占关键事务；在途事务不能被瞬时抢断，最坏仍受现有50ms响应超时约束。
诊断失败只增加诊断失败计数、设置对应陈旧位，不改变关键反馈有效位、连续失败计数、关键反馈年龄或触发急停。
四字段各自保存有效位、采样tick和陈旧位。失败不清有效缓存，成功清对应陈旧位。采样超过3个正常周期时，回传附带陈旧位。
新增快照增大调用栈：LCD任务栈768→832字，HMI任务栈512→576字；需继续实测栈高水位。

## 0x89格式

32字节、大端、会话、全局序号、CRC和帧尾均沿用旧协议。

| 位置 | 含义 |
| --- | --- |
| 3 | 0x89 |
| 7 | 原有轴选择标志 |
| 10 / 11 | A1 / A2逐字段陈旧位：bit0转矩、bit1负载、bit2电流、bit3电压；高4位保留0 |
| 12～19 | A1：转矩、负载、电流、电压，依次2字节 |
| 20～27 | A2：同上 |
| 28～31 | 现有CRC及帧尾 |

每字段bit15表示存在有效缓存，低15位为数值。转矩/电流为15位二进制补码（符号bit14），负载/电压为无符号。
未选轴、首次未采集和超出15位范围的字段编码无效，不发送伪零。
只有0x89允许字节10/11承载陈旧位，0x81～0x88仍要求两字节为0。
`APP_NRF_SERVO_DIAGNOSTIC_PERIOD_MS=1000`控制回传周期，快速状态/告警优先；采集失败时继续回传缓存，并明确OLD。

## 遥控器DRV页面

新增第8页，不改变原1～7页顺序；K7/K8在8页中循环。

```text
DRV 8/8 RX A0/00
A1 T:12.3% L:45.6%
A1 I:12.3A U:325.0V
A2 T:10.1% L:40.2%
A2 I:11.8A U:324.8V
AGE:1234ms
S:A1/A2 LAST
T/L:% I:A U:V
```

A1为轴0/前轮组，A2为轴1/后轮组。未选轴NC，选中但首次未读成功--。
LAST表示末次有效参数正在回传，不表示四项同一瞬间采样。
任一缓存字段陈旧或参数帧超3秒且无线在线时OLD；断链LOST但保留历史值。
同会话恢复及其他状态帧不清诊断末次缓存；会话变化/初始化清除，避免跨设备残留。
AGE为最后收到0x89的帧年龄，非驱动器原始采样年龄；持续重发旧采样时仍通过陈旧位显示OLD。
全部整数定点格式化，每行≤21字符；极限负电流时省略I/U字段间空格避免截断。
第6页继续km/h，0x88协议继续mm/s；本次不改加减速、限速、机械传动或按键映射。
