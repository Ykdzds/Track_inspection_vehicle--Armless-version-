# NRF24L01主控状态回传非阻塞实施说明

日期：2026-10-06

## 1. 实施范围与依据

本轮实现主控PRX、遥控器PTX，主控通过ACK Payload返回固定32字节状态。应用层依据协作资料`6.方案设计/主控发送遥控器状态显示通信协议_V1.md`的遥控端开发冻结版V1.1，特别是第21章冻结补充。

实现包含SPI2双向DMA、异步初始化和故障恢复、原控制帧接收、状态编码与调度、CLI诊断、主机测试和Keil配置编译。仅回传已有状态，不写伺服寄存器，不修改共同速度斜坡、同步P参数、启动门禁或急停规则。

**软件测试不等于射频和实时性验收。遥控端改造、实物链路、DMA时序和通信压力测试仍须完成。**

## 2. 开关与最终配置

`APP/app_config.h`：

```c
/* 同时改为1后重新编译下载，遥控端须同步支持动态载荷和ACK载荷。 */
#define APP_NRF_TELEMETRY_ENABLED   (1U)
#define APP_NRF_ACK_PAYLOAD_ENABLED (1U)
```

| 状态回传 | ACK载荷 | 行为 |
| --- | --- | --- |
| 0 | 0 | 不组状态帧，使用固定32字节控制接收；SPI仍采用非阻塞DMA |
| 0 | 1 | 配置动态载荷与ACK能力，不生成周期状态 |
| 1 | 1 | 开启状态回传 |
| 1 | 0 | 编译错误，禁止不完整配置 |

当前交付保留BOTH、两个宏均为`1U`，与已支持ACK载荷的遥控端配套使用。现有同步、调试、待机和位置监控参数保留，不因本轮改造重新整定。

ACK开启时，FEATURE核验失败最多尝试一次ACTIVATE，仍失败或DYNPD不匹配则保持CE低，500 ms退避后重新初始化，不降级伪装成功。ACK关闭时写入并核验FEATURE/DYNPD为0，不执行ACTIVATE。

## 3. 本机硬件与DMA

以下引脚来自当前`Core/Inc/main.h`及`Core/Src/spi.c`，不是通用遥控器原理图：

| 信号 | 本机引脚 |
| --- | --- |
| CE | PE13 |
| CSN | PE14 |
| SPI2 SCK | PB10 |
| SPI2 MISO | PB14 |
| SPI2 MOSI | PB15 |

主控驱动轮询无线FIFO，不依赖NRF IRQ外部中断。SPI2独占本模块；其他调用者不得并行操作SPI2或其DMA句柄。

| 资源 | 配置 |
| --- | --- |
| SPI2 RX | DMA1 Stream3 Channel0 |
| SPI2 TX | DMA1 Stream4 Channel0 |
| DMA模式 | Normal、Byte、内存递增、Low、FIFO关闭 |
| DMA中断 | 优先级6、子优先级0 |
| USART2 DMA | 保持DMA1 Stream5/6 |
| USART1 TX DMA | 保持DMA2 Stream7 |

`.ioc`同步增加SPI2_RX/SPI2_TX请求，总请求数为5。SPI2 DMA采用专用短中断入口；重新生成CubeMX后，必须核查这些入口仍调用`NRF24L01_DmaRxIsr()`和`NRF24L01_DmaTxIsr()`，不能误换为带错误关流等待的通用HAL入口。

无线参数保留地址`11 22 33 44 55`、Pipe0、信道2、2 Mbps及硬件1字节CRC。应用层控制帧仍固定32字节。回传开启时，两端必须支持动态载荷和ACK载荷，不能仅修改主控宏。

## 4. 非阻塞执行边界

1. `nrf_task`独占驱动服务和ACK入队，优先解析控制帧、更新遥控事件，再调度状态回传。
2. 每次驱动服务最多启动一条SPI DMA命令，不等待无线应答、不轮询DMA完成或SPI BSY。
3. DMA使用静态33字节收发缓存，传输期间不复用；软件接收队列最多3包，应用每轮最多搬运3包。
4. 中断仅清标志、更新完成或错误状态、通知任务，不格式化、不打印、不执行运动动作。
5. SPI BSY、DMA关闭及恢复由任务逐次检查。启动100 ms等待、上电2 ms稳定等待、2 ms事务超时和500 ms恢复退避均使用时间戳，不占用CPU等待。
6. DMA完成通知可唤醒无线任务，无通知时最多等待原有5 ms轮询周期。该等待仅挂起无线任务，不挂起运动或Modbus任务。
7. 状态快照最多每50 ms采集一次，大快照放静态区，NRF任务栈为768字。读取来源失败时跳过发布，不能把半份或清零快照当作正常状态。

SPI启动存在短临界区，因此“非阻塞”不表示绝对零CPU开销或实时性已得到证明。现场仍须测量中断、任务运行时间和控制通信增量。

无线模块损坏或SPI恢复期间可能无法继续接收控制帧；原有合法帧失联计时与停车门禁继续独立生效。不能承诺无线故障时遥控仍可正常控制。

## 5. ACK时序与缓存策略

主控预装载状态，由后续控制帧触发ACK，不保证状态与某一控制帧严格同步。遥控器没有持续发送控制帧时，主控也不能主动保证状态送达。

- 软件只保留最新待装载状态，不排队历史状态。
- 正常仅向硬件ACK FIFO保留一帧；存在待装载状态时最多连续搬运一个RX包，随后安排ACK，避免持续RX饿死回传。
- ACK已装载100 ms仍未消费或TX FIFO异常时，先CE拉低、按时间戳等待2 ms，再清TX FIFO并继续接收；不顺带清正常控制RX。
- DMA正在装载时新状态到达，不修改正在发送的缓冲，代次比较确保新帧保留。
- W_ACK返回TX_FULL不计装载成功，保留软件帧待清理后重试。
- DMA或SPI错误进入退避恢复，不在中断或任务中等待关流。

必须区分三件事：**主控已生成、已提交软件队列、已装载硬件ACK**。均不等于遥控器已收到、已校验或已显示。本阶段没有遥控器应用层收讫确认。

## 6. 状态帧与调度

固定32字节，大端，CRC16-CCITT-FALSE覆盖0～27字节；帧头`5A A5`、版本`01`、有效长度22、帧尾`0D 0A`。字段偏移、帧类型和保留字节遵循冻结协议，不在此文档重新定义。

| 帧类型 | 内容 | 目标调度间隔 |
| --- | --- | --- |
| 0x81 | 快速系统、授权、模式和转速状态 | 50 ms |
| 0x82 | 双轴状态、故障和反馈年龄 | 200 ms |
| 0x83 | 原始位置、相对差和轮转估算里程 | 1000 ms |
| 0x84 | 双轴速度同步诊断 | 200 ms |
| 0x85 | 电池、定位等整机扩展 | 暂不调度，无真实数据源 |
| 0x86 | 机械换算参数 | 5000 ms |
| 0x87 | 告警事件 | 限频200 ms |

快速状态有优先级和最迟100 ms的调度检查，告警限频，后台从到期项目中轮询。以上是主控生成调度目标，不是远端接收周期保证；总线忙、遥控控制帧缺失或恢复会延后实际回传。

### 冻结单位与显示

- 转速：整数rpm，实际反馈来源为有效USART2伺服快照。
- 原始位置：有符号32位计数。
- 相对位置差：有符号16位毫米。
- 启动净位移：有符号16位，100 mm/LSB。
- 启动和分段采样累计行程：无符号16位，100 mm/LSB。
- 传动比：电机转数/车轮转数，编码为比值×1000。
- 距离仍为轮转估算量，不能显示为已校验真实车辆里程。
- 必须结合有效标志和类型解释字段，不能把失效的零值或历史值当作当前有效值。
- 非遥控、非使能零速待机时，没有可信最终速度命令来源的字段使用`0x7FFF`，不发送历史遥控命令冒充当前命令。
- 电池、定位、机械臂、照明和采集尚未接入，不显示正常或0%电量；扩展编码接口保留未知值，电量`0xFF`、有效bit6清零。
- 告警解除后快速帧的告警等级会更新为0；遥控端不能仅收到一次0x87就永久锁住告警显示。

### 当前协议限制

V1.1文字提到位置基准代次、参数版本提示，但当前32字节字段表没有相应传输字段。本实现不占用保留字节，**不能传输位置基准代次或独立参数版本号**。遥控端暂不能实现依赖它们的提示，需后续双方明确修订协议，不得自行猜测。

会话号为8位，由本机UID、复位原因和启动时间混合生成，不依赖RTC或跨复位存储，可能重复。它有助于清理旧显示缓存，但不提供永不重复的启动身份。遥控端还须结合序号回绕、帧类型、有效标志和本地接收超时判断数据新鲜度；状态帧不是安全授权或运动指令。

## 7. CLI诊断解释

`remote servo status`追加无线DMA、ACK和状态生成摘要。下表也包括`NRF24L01_GetStats()`和`nrf_status_telemetry_get_stats()`提供的详细字段；CLI中的`fail`为ACK异常与软件入队失败之和，详细接口可分别读取：

| 字段 | 含义 |
| --- | --- |
| initialized / ack_supported | 本机硬件配置核验结果及ACK能力 |
| dma_started / dma_completed | SPI命令启动、任务确认完成次数，不是无线包数 |
| dma_timeouts / spi_errors | SPI事务超时或启动、DMA、SPI异常 |
| rx_packets / rx_dropped | 已搬运到软件队列的包数及队列满丢弃数 |
| invalid_widths | 动态载荷长度不等于32的次数 |
| ack_queued | 软件接受ACK帧次数 |
| ack_loaded | W_ACK命令未返回TX_FULL的装载次数 |
| ack_replaced / ack_flushed | 软件待装载帧替换、硬件旧ACK清理次数 |
| ack_failures | ACK路径异常次数，不是已证实的远端丢包数 |
| generated / generated_by_type | 应用状态帧生成次数和各类型计数 |
| queue_failures | 软件ACK入队失败次数 |
| session / last_sequence / last_type | 本次状态会话及最近生成帧标识 |

## 9. 实物联调与验收

1. 先两个宏0验证原遥控帧接收、授权、K1、失联停车及CLI行为。
2. 升级遥控端PTX动态载荷/ACK接收，主控两个宏1，检查`initialized=1`、`ack_supported=1`。
3. 抓取遥控端收到的32字节帧，核对长度、字节序、CRC、类型、会话和序号；不能仅以主控`ack_loaded`增加认定远端成功。
4. 核对0x81目标与实际转速、0x82使能和故障、0x83正反向位移与100 mm单位、0x84同步状态、0x86机械参数。
5. 失效和未接入值必须显示`--`或未知；未选轴不显示伪零速正常。清除报警后确认显示不永久残留。
6. 遥控关闭/重开、主控复位、重复帧、丢ACK、模块断线、干扰、非法长度下验证恢复和旧授权不会恢复。
7. 持续双轴运行、USART1同步调试开启、CLI查询和位置采集并行，记录控制合法帧接收率、最大接收间隔、USART2错误增量、速度有效配对率、USART1丢弃、任务栈剩余及运行时。
8. 示波器或逻辑分析仪观察SPI CSN/SCK、CE及DMA错误恢复，确认没有等待循环占用运动任务时间，CE清旧ACK间隔对接收的影响可接受。

现场记录至少区分宏0基线与宏1版本，列出运行时长、负载、合法帧/ACK帧计数、各类型年龄和所有错误增量。实时性与无线可靠性只有完成这些测试后才可验收，当前不填写未测得的性能结论。

## 10. 主控热启动与独立供电恢复修复

### 10.1 初始化与接收就绪

GPIO及CubeMX配置统一为CE默认低、CSN默认高，其他GPIO输出不变。无线任务关闭SPI/DMA，异步确认DMA流关闭后复位句柄，不使用等待循环。完整初始化顺序：

```text
100 ms启动等待
→ CONFIG=0x08断电模式及回读
→ 通信配置逐项写入/核验
→ FEATURE及DYNPD核验
→ 清TX/RX FIFO及IRQ
→ CONFIG=0x0B PRX模式及回读
→ 2 ms稳定等待
→ initialized=1（仅配置完成）
→ 回传开启时等待新鲜0x81装载
→ 拉高CE、radio_ready=1（接收就绪）
```

首ACK等待期限为100 ms，覆盖装载、TX_FULL重试和清FIFO全过程，不因重试延长。超时保持CE低并退避。首0x81可以报告未授权、启动未完成，不等待伺服就绪。0/0与0/1组合不等待状态首帧。

软件CONFIG断电模式不等于模块真正掉电复位，不依赖模块寄存器、FIFO或FEATURE锁为冷启动状态。

### 10.2 运行公平调度与恢复

- 存在待装载ACK时，最多连续搬运一个RX包后安排ACK；硬件旧ACK占用时继续处理RX，并按已有待机清TX机制获得装载空间。
- 每轮服务最多启动一个SPI DMA事务；装载中静态DMA缓存不被最新状态覆盖。
- 配置巡检约每1000 ms启动，沿用初始化配置表和FEATURE/DYNPD期望值，分事务回读。正常巡检不拉低CE、不清RX。
- 到期巡检在完整事务边界插入回读，保留原RX/ACK处理状态，目标每20 ms获得一次机会；任务延迟及实际间隔仍须实测。
- 合法控制帧持续到达时，待装载超过100 ms执行一次ACK FIFO清理；再100 ms没有装载进展则完整重初始化。普通遥控关机不因无控制帧反复重建。
- 最新帧替换不重置装载停滞计时；成功装载才算进展。最大ACK等待统计包括清理前后的等待，不等于远端接收延迟。
- 配置失配、SPI/DMA异常、非法载荷和FIFO异常均进入500 ms统一退避；模块独立断电后恢复供电可自动重新配置。
- 完整恢复后优先生成新鲜0x81，保留本次启动会话、递增状态序号和累计诊断统计，不发送残留状态。

### 10.3 安全衔接

无线未接收就绪时立即发布`link_up=0`，不等待300 ms。恢复代次在驱动失效和重新初始化时变化，运动任务即使未观察到短暂离线快照，也必须撤销授权、取消旧批次及消费历史按键事件。

统一待机适用时沿用现有斜坡零速保持路径，包含各类复位安全恢复成功后的待机；待机不适用时沿用失联停车后失能路径，不由无线驱动直接操作电机。恢复首控制帧只建立事件基准，重复旧K1长按不能重新授权。停车完成后仍需新的K1长按、摇杆回中和全部运动门禁通过。迟到速度应答不能恢复取消的批次。

### 10.4 新增诊断

`remote servo status`追加`nrf_recovery`：

| 字段 | 含义 |
| --- | --- |
| config_ready | initialized，通信配置已核验 |
| radio_ready | 已装载必需首ACK并进入PRX接收 |
| generation | 本次启动内恢复代次，不是跨复位历史计数 |
| failure | 最近失败原因；恢复成功后保留，不能单凭非零判定当前失败 |
| feature / dynpd | 最近实际回读值 |
| verify_fail | 初始化配置核验失败累计次数 |
| ack_timeout | 首ACK或运行装载超时累计次数 |
| ack_max_wait | 已成功装载帧的最大软件等待时间，ms |
| check / mismatch | 完整巡检次数及失配累计次数 |

`failure`编码：0无记录、1 SPI/DMA错误、2 DMA事务超时、3普通配置核验、4 FEATURE、5 DYNPD、6 FIFO、7非法载荷长度、8首ACK超时、9运行ACK装载停滞、10巡检失配。

`config_ready=1`不代表接收已经开放；`ack_loaded`只代表主控装载结果；`valid_frames`才表示主控收到并解析合法控制帧。以上均不是遥控端已收到状态的证明。
