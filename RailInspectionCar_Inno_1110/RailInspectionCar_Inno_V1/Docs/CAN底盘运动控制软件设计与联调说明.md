日期：2026-10-12。开发基线：d4b786986cdb952ef7552f5bd1a25ad5f69b83a4。

当前接入修订：2026-10-19。以下参数与遥测规则以本次修订为准；2026-10-12验证记录仍保留当时事实，不能当作本次实物CAN验收。详见《CAN遥测补齐与上位机低速测试接入记录_20261019.md》。

## 1. 交付边界

接入CAN底盘速度控制生产路径、独立同步与停车状态，不开放机械臂动作。正式关闭配置使用APP_CAN_CONTROL_ENABLED=0U、APP_CAN_STOP_PARAMETERS_APPROVED=0U；HMI保持既有启用配置，不再要求关闭。CAN测试配置必须在独立临时工程显式开启，不自动烧录，不提交或推送Git。注意：当前工作区已有用户将CAN控制和停车批准改为1的未提交变更，本次不回退；直接编译当前Keil工程不是正式CAN关闭构建。

构建通过不能证明车辆运动安全。当前输出属于软件实现和验证交付，真实保持能力、方向、停车时间、DI3/STO与30分钟实物稳定性仍待验收。详细结果见同目录《CAN底盘运动控制软件验证记录_20261012.md》。

## 2. 数据流与职责

CAN ISR静态队列 -> CAN任务会话/格式/去重 -> app_can_control邮箱 -> servo_comm_task安全检查及仲裁 -> AIMtor异步请求 -> 单活动USART2 Modbus事务 -> 回显/回读和实际反馈 -> CAN状态/结果与HMI摘要。

| 模块 | 职责 |
|---|---|
| APP/app_can_control.c | 普通请求队列8项、最新速度邮箱、停止优先事件、令牌、租期、异步批次、停车与换向 |
| APP/HMI/app_control_arbiter.c | 8项申请队列、准备预约、所有权、停车锁、安全锁；每次伺服服务最多裁决4项 |
| Protocol/CAN/can_link.c | 握手1.0、会话令牌、32项请求结果缓存、重复请求、受理/执行结果 |
| Device/aimtor_servo.c | CAN专用运动与停车权限，保存代次/批次/写序号，取消未上线旧运动，匹配迟到应答 |
| APP/app_remote_servo_sync.c | 参数化P同步核心；原遥控包装继续使用原参数；CAN使用独立状态 |
| Protocol/CAN/can_identity.c | 扇区11每启动一条64字节日志，保留运动令牌块，CRC/提交标记不变 |
| APP/app_can_status.c | 显式线上来源/生命周期及0x11、0x13、0x23、0x180编码 |
| APP/HMI/app_hmi_state.c | CAN显示为既有AUTO=3，不改正式屏端字典与寄存器区 |

不新增运动任务及关键任务心跳。CAN任务不得直接访问伺服写接口。ISR不得打印、授权或等待。

## 3. 仲裁与授权

1. 申请提交时取得统一递增ticket。伺服任务串行裁决，首个满足条件的申请取得准备预约。
2. 已有所有者、停车锁或安全锁时拒绝其他申请，不排队等待未来自动授权。
3. 预约期间暂停调试自动服务；遥控在预约后才能发模式/使能准备事务。CLI先返回受理并进入ENTERING。
4. CAN必须READY、RK有效能力声明bit29、启动身份有效、选中轴新鲜在线无故障、实际零速、已核验速度模式和已使能，且使能反馈新鲜。
5. CAN不自动切模式、使能、清锁或清故障。无合适速度模式时由现有人工维护流程准备，随后退出维护授权再申请CAN。
6. 授权发放新的motion_token，进入首零速等待。1000ms内收到新序号零速且所有选中轴零写核验完成，才开放非零目标。
7. 重复申请由链路缓存返回原结果，不分配新令牌，不续租。

软件提交顺序不等同于不同设备物理按键先后。安全接管改变代次，旧排队申请不得在清锁后自动授权。

## 4. 启动身份与令牌

原64字节日志offset24/26保存运动域first/last，offset28为schema 0x4D544B31。链路令牌与运动令牌各自独立递增；允许数值相同，但接口用途不相同。

每启动保留32个编号，末块避开FFFF。兼容旧保留字段为0的已提交记录；旧记录与掉电未提交槽都消耗对应编号块。运行不写Flash，不自动擦除。32次授权耗尽后拒绝新增授权，但停止/撤销仍可用。日志失败不发放身份。

配置指纹使用80字节机械配置和固定整数策略字段，附加申请/首零速/写确认/换向/停车期限、保持与倒车、正常/失联/快速减速度。线上0x10仍80字节，不增加布局。

## 5. 控制与停车

内部状态：未授权、准备、首零速、零速待命、运行、换向、事务收尾、减速、零速确认、保持确认、完成、故障。线上生命周期经显式映射，不能直接使用内部枚举。

速度租期从报文接收时间计算。最新合法目标可替换待消费目标，不替换活动批次。重复不执行、不续租；同序异载荷、旧序号、错误令牌、过期或超范围均拒绝。接收与执行分别保存原子快照，消费时再次检查代次和限速。

车速单位mm/s，轮径/方向/传动比来自底盘参数。先检车速，再向零量化RPM并显式复核选中轴上限；当前统一电机上限1600rpm，轮径185mm、减速比8/3，对应派生整数限速5811mm/s，不是独立配置常量。上位机应读取同会话0x10配置及0x11限速，不能只用显示范围判断可发目标。会话降限速不提高底盘上限，新授权恢复底盘派生限速。

每批选中轴使用同一目标和同步补偿；各轴异步写确认全部完成才开启下一批。未选中轴不写。普通斜坡统一按 `APP_DESIGN_ACCELERATION_MPS2` 和 `APP_DESIGN_DECELERATION_MPS2` 的物理加速度积分，周期上限由 `APP_MOTION_RAMP_MAX_DT_MS` 保护。底层保存来源、代次、批次和速度写序号。撤权取消未上线动作，在途旧应答仅归档实际执行事实，不继续旧给定回读和新动作。

双轴反馈转换为左轴等效RPM，独立P状态使用50ms周期、100ms新鲜度、40ms配对差。配对无效补偿归零；只用相同配对计算整车速度。未开启超差保护时不自行开启。CAN独立状态不污染遥控同步。停车仍采集配对诊断，禁止补偿运动。

反向先写零，各轴在零写完成后收到两次不同新序号实际零速，才执行反向。新速度不重置确认期限。撤权立即清待反向目标。

停车先作废令牌、清目标、建停车锁，在伺服调度前阻止旧运动。以确认指令及实际速度建立期限，事务收尾后建立不增速、不换向的减速锚点。即使本地零给定也重新写零。零写后两次新鲜零速、无故障、参数/模式有效、真实使能保持、无pending才报告完成并释放所有权。

正常停止与断线停止保持既有零速使能；通信/真实故障或停车失败进入既有安全路径，不能保证仍使能。K1从遥控传播到CAN停车，使用原K1减速度并接入原人工保持确认；K2/看门狗仍走原安全行为。软件锁存不冒充实体DI3。

0x080按当前所有者分派：CAN使用本模块，REMOTE沿用原人工停机，CLI走off和原模式停止/恢复，HMI走释放停车。跨来源不调用CAN速度写，不套用CAN速度斜坡；完成须核验原所有者已结束、无安全锁及两次新鲜实际零速。故障或期限届满升级安全接管，不能仅靠owner=NONE报告成功。

## 7. 协议字段映射

500kbit/s、标准ID、握手主/次版本1/0、format=1、LE和CRC保持。

| ID/类型 | 长度与布局 | 语义 |
|---|---|---|
| 0x110 | seq8,cmd8,p1 i16LE,p2 i16LE,link_token16LE | 04申请p1=1/撤销0；05普通本源停车p1=0；06只降限速；07模式2；p2=0 |
| 0x111 | seq16LE,target i16LE,motion_token16LE,lease16LE | 连续最新速度；必须当前许可及首零速 |
| 0x080 | stop_seq16LE,link_token16LE,strategy8,reason8,reserved16 | strategy0；reason0至3；reserved0；跨源停止 |
| 0x120 | 原基础布局 | 仅受理/拒绝，不代表动作完成 |
| 0x121 | 原基础布局 | phase1受理、2执行中、3成功、4失败；按cmd解释 |
| 0x11 | 40字节 | 下表 |
| 0x13 | 40字节 | 停车代次、原因/阶段/零速/失败轴、命令、时刻与剩余期限 |
| 0x23 | 32字节 | 按真实owner选择HMI、CAN或REMOTE同步来源、实际配对、补偿、命令、序号与诊断序号 |
| 0x53 | 原布局 | 无机械臂许可，permit_mask仍0 |

0x11：offset0 generation32；4 motion_token16；6 source；7 life；8 mode；9 drive；10许可mask；11 gates；12 flags32；16剩余许可32；20 speed_seq16；22 age16；24 limit16；26 detail16；28 CLI session32；32最近合法stop_seq16；34 phase；35 result；36 uptime32。

停车phase0/resultFF；phase1/2/3/result0均未完成；phase4/result0终成功；phase5实际失败码。无速度的序号/年龄FFFF，但首序号FFFF本身仍合法。无许可token0。0x05/撤销/超时不伪造stop_seq。旧0x080重复不能停新授权，不重置期限。

内部CAN owner5映射线上source4；安全执行器线上5。HMI寄存器中的AUTO3是其独立显示映射，不能用于CAN线上owner编码；照明00A9与机械臂00A8不改变。能力6/21/22/29按实现及配置；实体能力7保持0，data_sources.bit29=0。

2026-10-19补齐：CAN线上控制源显式映射为NONE=0、REMOTE=1、CLI=2、HMI=3、CAN=4；安全执行流程=5，无法确认=255，绝不复制内部owner枚举。HMI持权及停车时发布owner=3，准备life=2、运行life=3、停车life=4；历史记录不生成owner=5。0x180授权位、0x11.flags.bit7及0x188.B7.bit7表示真实HMI授权。0x11.motion_token/speed_seq/stop_seq仍为CAN专用字段，HMI session和32位请求序号不塞入这些槽位。0x23.flags.bit6仍只表示手柄、bit7仍只表示支持同步能力的CAN来源；HMI来源由0x11/0x188.owner=3识别。

## 10. 尚需联合核验

本轮生产模块及既有来源专项回归不能替代四个控制源联合输入测试。遥控申请在伺服服务解析长按时进入仲裁，其他来源在邮箱提交时进入仲裁；软件ticket顺序不等同于物理事件先后，尚未实现“各设备完整接收入口同时排序”的统一时间口径。跨来源0x080已有分派/失败/零速监控测试，但CLI/HMI/REMOTE与真实异步伺服事务共同运行仍需整体验收。

不同轮径、右轴反向和不同传动比已用主机预包含测试头覆盖，正式参数没有修改；该验证不能替代实体方向和速度标定。代码没有实体DI3输入能力声明，机械臂0x53始终无许可。仍需补充RK同会话配置修订变更的失效传播、所有控制源同一生产场景安全抢占、各源停车0x13统一描述与长时间运行高水位证据。在这些联合项与实物项目未关闭前，不标记整个实施计划全面完成，不批准现场宏开启。
