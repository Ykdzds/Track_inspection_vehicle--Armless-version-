# F407高速瞬停分级停车修复与验收

## 1. 结论与范围

现场 `S:5`、两轴失能而伺服故障码为零，更符合软件故障锁存后的主动失能。照片不能确定首个触发异常，也不能排除供电、干扰或驱动器保护的先后关系；应以新增故障证据与实物记录完成归因。

本次只修改F407软件及其主机测试、构建脚本，不修改F103、遥控器固件、车载屏工程、HMI寄存器地址、CAN帧和NRF控制帧。`SERVO_CONTROL_RS485_VELOCITY = 2`，LCD的 `M:2` 是RS485速度模式，不是内部多段位置模式。

代码复核定位到两条需要同时处理的路径：

1. 速度/故障反馈过期、离线或控制事务异常，被调用方统一升级为全局立即失能。
2. 连续速度写入时，使能回读可能因轴长期处于 `ACTION_SPEED` 而得不到调度；HMI要求的使能反馈过期后触发停车。此次允许关键使能回读插入速度事务，且不打断已开始的左右轴同步速度回读对。

此外，运行中的使能回读失败或回读零值，原先也会经 `s_emergency_pending` 立即失能。本次改为独立待处理反馈停车请求；K5静止保持核验失败仍保留原保护行为。驱动器已经自行失能的轴不能靠软件恢复转矩，此修改只避免同时无条件切断另一轴，不自动重新使能。

## 2. 分级停车行为

| 类别 | 行为 |
| --- | --- |
| 正常停车 | 沿用原控制源的减速度、零速确认、授权释放与保持流程 |
| 反馈过期、通信离线、运行中使能反馈异常 | 锁住新的运动提交，撤销运动授权，保持当前伺服使能，执行受控减速 |
| 有效伺服故障、输出故障、受控停车写持续失败、停车超时、不支持的模式 | 升级原立即停车与故障锁存路径 |
| 人工安全停车、看门狗、关键任务失活、MCU故障 | 保留原立即安全动作和复位保护；不能保证软件减速 |

### RS485速度模式

- 从最近成功写入的速度命令开始；尚无成功写入记录时，使用现有实际转速作为后备。
- 按 `APP_DESIGN_DECELERATION_MPS2`（当前0.30 m/s²）及原车轮/减速比参数，以经过时间生成递减指令；不修改正常运动的0.12 m/s²加速度和各控制源原停车参数。
- 专用停车事务轮流写速度、读实际速度、读故障码；不需要普通运动授权，不等待已过期的普通写门禁。
- 写零成功后，要求每个选中轴至少两次新的零速反馈，且速度、故障反馈仍新鲜，才进入原故障锁存和失能流程。
- 写连续失败达到 `APP_SERVO_OFFLINE_FAILURES`、真实故障或停车期限到达时升级立即安全动作。期限为理论减速时间加5000 ms；脉冲模式至少25000 ms。
- 总线完全断开时，写请求无法保证到达驱动器，软件不承诺受控停车成功。

按当前185 mm轮径、总减速比3×16/18计算，1600 rpm约为5.812 m/s；若实际能维持0.30 m/s²恒减速度，理论停车时间约19.37 s、距离约56.30 m（未计检测延迟、打滑、坡度及控制误差）。这是参数计算，不是实测制动性能；“平滑减速”不等于“停车距离安全”，必须留足隔离距离，后续单独评估制动参数与独立安全链路。

### 脉冲位置模式

- 先通过原运动规划器减速到零，保留原脉冲模式减速度。
- 定脉冲测试转入减速时取消剩余定数目标，避免计数中断先于减速完成直接截断PWM。
- 本地命令归零及新鲜实际零速反馈确认之前，不主动切断使能。

### 内部多段位置模式

当前没有经过核实的专用减速停机寄存器实现，不把速度寄存器写零冒充位置模式受控停车。该模式会以原因6升级立即安全路径；实物确认寄存器和停机行为前，不应使用本修复宣称内部位置模式已具备平滑故障停车能力。

### 禁止自动续跑

停车开始后取消排队事务、旧批次及旧目标，HMI/CAN/遥控/CLI服务停止提交普通运动指令。通信恢复不能恢复原目标；停车完成后仍需满足原有静止、无故障、失能确认、人工解锁、回中/首零和控制源互斥规则。

## 3. 诊断读取

### LCD

首行新增 `C`（停车类别）和 `R`（故障原因）。原首行 `P/M` 被替换，但两轴模式、参数核验等轴状态行仍保留。

| C | 含义 |
| --- | --- |
| 0 | 无 |
| 1 | 正常停车 |
| 2 | 受控安全停车 |
| 3 | 立即安全停车 |

| R | 含义 |
| --- | --- |
| 0 | 无 |
| 1 | 反馈过期或运行中使能反馈异常 |
| 2 | 伺服离线，连续失败达到阈值 |
| 3 | 真实伺服故障 |
| 4 | 输出/停车写失败 |
| 5 | 受控停车超时 |
| 6 | 不支持的控制模式 |
| 7 / 8 | 预留的任务心跳超时/看门狗复位原因；现有看门狗诊断仍使用原独立字段 |

### CLI

原状态查询增加 `safety` 行，记录首次原因、最终原因、控制源、触发轴、时间、期限、完成/升级状态，以及两轴触发时RPM、最近命令RPM、速度/故障快照年龄、故障码、最近Modbus结果/地址、连续失败及停车写失败次数。

记录保存在RAM；复位或成功人工清除锁存后清空，不是跨复位黑匣子。缺失样本年龄为 `UINT32_MAX`。控制源编码：0无、1遥控、2HMI、3CAN、4CLI。

### 车载屏

复用现有告警字段新增 `0x0404`（主控分级停车），参数高16位为停车类别、低16位为故障原因。原停车结果失败字段保留。

本阶段没有修改车载屏工程，因此不能保证现有屏幕已经把新告警翻译为中文文本。可通过既有告警码/参数读取原因；若屏幕尚未支持 `0404` 的文本映射，需后续独立批准屏工程显示适配，不能声称已经替换其原“停车失败”文案。

## 4. 软件验证方法

- `Tests/run_safety_stop_tests.ps1`：LEFT/RIGHT/BOTH × 待机开/关，覆盖正负1600 rpm指令递减、单次/两次超时、CRC、年龄过期、运行中使能回读失败/回读零、脉冲减速、新鲜零速、真实故障、停车写失败、期限、Tick回绕、旧目标禁止和人工抢占。
- `Tests/run_cli_session_tests.ps1`：CLI开关/只读/三轴配置及HMI真实驱动联动；HMI联动验证反馈过期不会过早失能、通信恢复不续跑、实际零速后才锁存。
- 原核心生产测试覆盖CRC/取消、上电停车、看门狗恢复、K5保持、模式门禁、双轴轮询、公平性、CAN事务取消及位置监控。
- HMI/CAN单元及联合、CAN K5恢复、共享斜坡、HMI状态、统一快照和快照传输测试需一起执行。
- `Tests/build_controlled_stop.ps1`：三轴配置 × 待机开/关 × 普通/只读，共12组，另加双轴同步关闭和当前正式配置，共14组。只读配置关闭CAN运动。使用独立临时工程和输出目录，检查0错误0警告、Flash边界、静态栈预算，并保存源码和产物SHA256；退出时恢复RTE生成文件，不改正式工程宏，不烧录。

### 已发现的原回归入口限制

- `Tests/run_tests.ps1` 当前在伺服诊断子脚本编译中断入口时，使用 `APP_CAN_ENABLED=0` 但未关闭默认CAN运动，且主机HAL桩缺少UART事件宏，导致编译失败；它后续的非法CAN配置列表也仍把当前合法的 `APP_CAN_CONTROL_ENABLED=1` 当作非法组合。此次不修改这些无关旧入口，不能把完整入口标为通过。
- `Tests/run_k5_repeat_tests.ps1` 在 `axis=1 sync=0 hold=0` 的既有速度上限断言失败；使用 `HEAD:APP/app_remote_servo.c` 对照编译也在同一断言失败。此次不删除或放宽断言，不宣称完整K5专项入口通过；核心生产K5保持与CAN/HMI K5回归单独验证。
- `Tests/check_irq_dma_integration.ps1` 仍要求UART5接收为 `DMA_NORMAL`，而现有CubeMX与生产驱动已经使用 `DMA_CIRCULAR`。相关工程/驱动本次未修改；已通过的HMI生产DMA链路测试不能被这个旧静态规则替代。USART2的115200/8N1静态检查通过，运行时错误计数仍需实物采集。

最终源码已通过分级停车六组矩阵、CLI十二组和HMI真实驱动六组矩阵、核心生产回归、HMI控制、CAN控制、CAN/HMI联合、CAN K5恢复、遥控按键宏兼容、共享斜坡、HMI状态及DMA链路、统一快照、CAN快照传输、RX/LOST端到端回归，以及看门狗健康模块开/关两组（含心跳超时与Tick回绕）。RX/LOST脚本同时调用遥控器原测试，但未修改遥控器工程。

主机日志：系统临时目录中的 `rail_safety_final_host.log`、`rail_safety_rxlost.log`。Keil日志和源码/产物SHA256由矩阵脚本输出到 `D:\CodexBuild\RailInspectionCar\controlled_stop_时间戳\`，以最终整轮完成的目录为准，不能把中途主动停止的旧构建目录作为完整通过证据。

## 5. 实物验收与放行

软件回归和Keil静态报告不是现场安全认证，也不能还原图片之前的电气瞬态。本修复未执行烧录、驱动器参数修改或实车高速试验。

固定车辆或抬轮，确保人员隔离和独立急停，按零速、200、600、低于1200、高于1200、1600 rpm逐级试验；每一级先验证正常授权、正反转、正常停车、各控制源切换与重新授权，再注入单次丢帧、短时阻塞、CRC、真实驱动故障、断线及人工安全停车。

记录实际转速曲线、实际减速度、停车时间/距离、母线过压、驱动器报警、双轴同步误差、USART2错误增量、Modbus队列、每任务实际栈高水位及F407故障证据。只有新鲜零速确认后才允许受控停车转入锁存；真实故障/硬件急停必须能抢占，通信恢复不得续跑。

驱动器 `H02_05`、速度减速时间、通信超时及故障动作必须先读取核验；本阶段不自动写入这些现场参数。总线断线、HardFault、掉电、看门狗或MCU停止执行时，必须依赖经验证的驱动器失联停车、独立STO/安全回路和必要的机械制动。**未完成1200～1600 rpm的隔离实测和上述旧回归入口问题评估前，不得宣称安全问题最终闭环或恢复载人/有人区域高速运行。**

## 6. 回退边界

保留原可追溯固件与现场参数备份。新版本若触发非预期保护，停止台架验证并读取证据，不通过取消故障锁存、延长新鲜度、屏蔽真实故障或强制重新使能规避。回退旧固件不能视为解决高速瞬停，回退后仍应限制到隔离低速调试。
