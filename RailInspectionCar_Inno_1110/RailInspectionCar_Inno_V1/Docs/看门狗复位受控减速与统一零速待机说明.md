# 看门狗复位受控减速与统一零速待机说明

日期：2026-10-08。

## 1. 行为与范围

正常上电、按键复位、软件复位、IWDG及WWDG复位，在各自安全流程成功后，选中轴均进入RS485速度模式、使能零速待机。待机不代表允许运动；不恢复复位前遥控授权、CLI会话、速度或位置目标，仍需新授权。

只有真正POR执行H05_30=6当前位置设零。按键、软件及看门狗复位不清伺服位置。待机开关关闭或只读配置时不新增自动使能。单轴不操作未选轴。

本次仅看门狗复位增加带速内部斜坡恢复；按键和软件复位仍先执行原启动安全停车，再进入统一待机。不是所有复位都会执行本次减速流程。

## 2. 独立参数

| 宏 | 默认值 | 含义 |
| --- | --- | --- |
| `APP_WDG_RECOVERY_DECEL_MS` | `10000U` | H06_06：1000rpm降至0的时间，ms；允许1～65535 |
| `APP_WDG_RECOVERY_STOP_MARGIN_MS` | `2000U` | 实际停车确认余量，ms，必须为正且满足Tick范围 |
| `APP_WDG_RECOVERY_TIMEOUT_MS` | `3000U` | 读取、核验及零目标提交准备期限，不含实际减速 |
| `APP_SERVO_STARTUP_HOLD_ENABLED` | `1U` | 各类复位安全流程完成后统一待机开关 |

看门狗恢复仍保持独立的 `APP_WDG_RECOVERY_DECEL_MS` 策略；正常H06_05/H06_06分别由 `APP_SERVO_SPEED_ACCELERATION_RAMP_MS` 和 `APP_SERVO_SPEED_DECELERATION_RAMP_MS` 根据物理加速度换算。遥控失联、K1和CAN停车仍由各自状态机使用独立减速度，停车过程中不动态切换H06寄存器。

按驱动器参数定义，600rpm默认理论减速约6秒。写零成功后确认期限：

```text
max(abs(当时实际速度), abs(复位后回读原指令)) × 减速参数 / 1000 + 确认余量
```

最低2000ms；64位中间计算，结果限于Tick安全比较范围。600rpm默认约8000ms。复位、任务启动和通信准备时间不包含其中；这些是参数计算值，不是整车实测停车保证。待机10秒期限在前置安全流程完成后独立启动。

## 3. 异步每轴恢复

全部流程复用伺服通信任务和单活动Modbus事务，不增加阻塞等待或并行控制器。两轴轮转，各轴准备完成即写零，不等另一轴全部准备完成。

```text
关闭本地脉冲、撤销授权
→ 新读实际速度、故障、使能控制配置、控制模式、H06_02、H06_00、H06_03
→ 核验在线、新鲜、无故障及已确认接线/寄存器门禁
→ 带速且使能配置成立、RS485速度模式/来源成立
→ 写H06_06独立减速时间
→ 回读H06_06完全匹配
→ 保持原使能写H06_03=0
→ 驱动器内部减速，持续查询实际速度、故障、使能配置
→ 两次新零速应答间隔至少20ms，且故障新鲜无故障
→ 失能，原模式/来源及零目标清理，恢复正常加减速，再次失能
→ 回读速度0、故障0、失能配置0，恢复完成
→ 原启动安全停车及配置核验
→ 仅POR设零（看门狗路径跳过）
→ 写0、使能、新鲜反馈核验
→ 未授权零速待机
```

减速前不失能、不切模式、不改来源、不重新使能。零目标写入应答只表示指令确认，绝不把RAM实际速度改成0。重复或旧事务应答不能推进状态或重复计零速样本。

已零速或已失能的正常轴直接走原清理，不带速重新使能；实际零速未确认不能进入后续待机。安全清理和参数恢复期间可能短暂失能，不承诺全程保持力。

## 4. 异常边界

带速但模式/来源不支持、参数回读不匹配、真实故障、反馈过期、通信失效、停车超时或人工急停：关闭本地脉冲，尽力失能并锁存失败，禁止自动使能。查询可用，普通运动与重新授权不可绕过恢复失败。

原复位前任务心跳失活急停保留。若它已经使驱动器失能，复位后不撤销其效果，不能保证再次获得内部斜坡机会。

可通过可选的遥控器K2短按测试制造真实IWDG超时复位，默认关闭。该测试同样先执行急停失能，不保证覆盖带速内部斜坡分支；详见`Docs/遥控器K2短按看门狗复位测试说明.md`。

H03_03回读仅表示当前接线约定下的软件使能控制配置，不是独立硬件SON状态。DI3急停及原故障门禁不得被绕过。若外部DI持续强制使能或通信失效，软件失能应答不足以保证机械安全，须使用DI3、硬件安全回路或机械制动；内部斜坡不替代这些措施。

## 5. CLI诊断

发送`status`，分别检查：

```text
wdg_recovery state=... ready=...
L/R wdg_state=... eligible=... attempts=... zero=... disable=... verify=... failure=...
  ramp=适用/已核验 start=... command=... decel=... elapsed=... timeout=... zeros=... stopped=... cfg=模式/选择/来源 son=...
startup_stop ready=...
boot_zero ready=...
startup_hold ready=...
```

诊断字段以实际CLI输出标签为准。`decel/elapsed/timeout`单位ms；`start/command`单位rpm；`son`是配置回读而非硬件使能证明。阶段包括`wait_online`、`write_decel`、`verify_decel`、`writing_zero`、`decelerating`、`confirm_zero`、`disabling`、`verifying`、`done`、`failed`。

| 失败码 | 含义 |
| --- | --- |
| 1 | 准备或安全清理超时 |
| 2 | 驱动器故障 |
| 3 | 模式、来源、使能或配置门禁不满足 |
| 4 | 写事务失败 |
| 5 | 减速参数核验失败 |
| 6 | 通信或反馈新鲜度失效 |
| 7 | 实际停车确认超时 |
| 8 | 人工急停抢占 |

`zero_written`、`stopped`、`verified`与`startup_hold ready`依次表示零目标确认、实际停稳确认、安全恢复完成、使能待机完成，不能互相替代。详见`Tests/看门狗复位受控减速测试.md`。
