# CAN遥测补齐与上位机低速测试接入记录

日期：2026-10-19。源码基线：`0b1d630`；本轮未提交、未推送、未烧录。

## 1. 边界与状态

本轮修改CAN只读采集、遥测编码、发布调度、测试及独立构建工具。未修改HMI、遥控、CLI、CAN运动控制器、仲裁器或底层伺服的生产控制逻辑，车载屏21号工程保持原样。既有重复急停、空闲误急停、单次/重复K5跨源停车修复继续保留。

软件回归、Keil编译、CAN无运动实物联调、真实低速运动是不同验收层级。现场CAN证据未提供，`PhysicalCommunicationVerified=false`、`MotionVerified=false`；既有HMI实物通过记录不能替代CAN实物验收。

## 2. 当前参数

| 参数 | 当前值 | 用途与边界 |
|---|---:|---|
| CAN链路健康心跳 | 100ms周期，1000ms失联期限 | 只约束CAN上位机健康会话；普通CAN失联不停止独立HMI/遥控/CLI |
| 目标刷新/租期 | 建议100ms刷新；每帧100～300ms | 必须递增新序号，心跳/读查询/重复帧不续目标租期 |
| 首零目标期限 | 1000ms | 新授权后必须先发送新序号0目标 |
| CAN授权准备期限 | 2000ms | 不是运动保活期限 |
| 停车确认余量 | 2000ms | 加到按当前速度和减速度计算的停车期限中 |
| 停车最大期限 | 30000ms | 单次停车绝对上限；不是每次均固定等待30秒 |
| 普通CAN停车 | 0.30m/s² | CAN撤权或本源正常停车 |
| CAN失联/目标过期停车 | 0.40m/s² | 两种失效触发条件独立 |
| CAN快速停车 | 关闭 | 不借本轮遥测修复开放 |
| 电机统一范围 | −1600～+1600rpm | 首轮实物只测试±50/±100rpm |
| 0x111目标单位 | mm/s，i16小端 | 当前185mm轮径、8/3减速比，±1600rpm约为±5811mm/s |

换算：`v_mm_s = rpm × π × 185 × 3 / (60 × 8)`；轴方向还须读取配置记录。±50rpm约±182mm/s、±100rpm约±363mm/s。当前整数限速5811mm/s，靠近边界应向零取整并遵守实际上传限速；协议不改为rpm。

原500ms CAN链路期限、20000ms停车上限和5555mm/s旧机械限速仅保留在历史资料中，不再作为当前运行参数。注意HMI目标500ms期限是另一套既有规则，不能误改为CAN1000ms。

## 3. 遥测实现与字段约定

- 采集使用HMI只读快照以及真实仲裁owner、代次、轴掩码、安全锁和当前停车事件；不向控制模块写状态。
- 线上控制源：0无人、1遥控、2CLI、3HMI、4CAN、5真实安全执行、255未知；内部枚举单独转换。
- HMI准备/运行/停车生命周期分别为2/3/4，授权零速待命为1；停稳释放后owner=0，历史停车记录不冒充当前安全执行器。
- `0x180`：HMI授权位与共同目标正确，目标转换为mm/s；停车开始目标失效，不继续发布旧非零值；实际速度使用新鲜伺服反馈。
- `0x185/0x188`：来源、生命周期、驱动模式与停车原因一致；实体许可位不由报文授权伪造。`0x188.B7`原bit0～6含义保留，原保留bit7用于HMI已授权；停车事务通过life=4及bit5运动批次活动反映，不复用bit3本地脉冲。
- `0x11`：HMI授权通过flags.bit7及授权轴掩码表示，控制代次取仲裁器；motion_token、speed_seq、speed_age、CAN限速、stop_seq仍保留CAN语义。HMI session不塞入CLI session，HMI32位请求序号不截断为CAN16位序号。HMI许可剩余时间使用已采集租期。
- `0x13`：HMI停车使用统一事件号，关联HMI已发布事件及代次，跨源K5原因映射为线上人工停车5。完成需结果成功、当前事件关联、零速/使能掩码、新鲜零速与使能反馈、无安全锁且控制权已释放。不具备首命令/零速时刻证据时发送全1未知，不推算伪造。
- 停车来源按实际观察的新事件、CAN停车代次及遥控停车代次更新，活动流程优先；当前快照优先于旧记录。该跟踪仅在CAN快照中，不改变仲裁器。启动号变化重置来源历史。
- `0x23`：按真实owner选择HMI/CAN/遥控同步快照，配对按样本序号和100ms新鲜度/40ms错时核验；HMI输出受output_mask约束。HMI诊断序号取其32位最后请求序号，不称为底层伺服批次。原来源bit6手柄、bit7CAN不改，HMI不占用保留同步位。
- 活动授权/准备/运行/停车时`0x11`目标调度100ms，空闲500ms；HMI停车历史继续请求`0x13`。分段事务仍受既有带宽与队列约束，调度周期不等同线上完整记录到达保证。

保持现有V1.1 CAN ID、记录长度、小端编码和命令语义；HMI协议不变。未知/过期信息发送未知或清有效位，不把主页缓存当安全证据。

## 4. 构建策略与工作区提醒

正式基线原则为CAN控制关闭、停车批准关闭，HMI启用。当前用户未提交工作区已把`APP_CAN_DEBUG_ENABLED`、`APP_CAN_CONTROL_ENABLED`、`APP_CAN_STOP_PARAMETERS_APPROVED`改为1，本轮不回退、不覆盖；当前Keil项目和选项文件也保留用户改动。因此不能声称直接编译当前工程是CAN关闭固件。

`Tests/build_can_control.ps1`用独立临时项目显式定义不同配置，原项目文件哈希不得变化，输出独立目录，`CreateHexFile=0`。包含正式CAN关闭、CAN开启/HMI共存、左/右/双轴、启动保持开关、CAN禁用和只读配置。脚本恢复RTE生成文件，检查Flash身份区边界及静态任务栈余量不少于256字节。

本轮不生成/覆盖正式HEX。待真实上位机无运动联调通过，再明确选择匹配双轴CAN测试配置生成下载固件；不混用旧HEX或矩阵单轴固件。

## 6. 上位机接入与放行

1. 固定车辆、准备独立硬件停机措施，核对经典CAN500kbit/s、PA11/PA12及收发器/终端接线。
2. 先无运动握手到READY，保持100ms健康心跳；双方能力记录确认bit29报文授权策略及实际运动能力。
3. 读取boot、配置版本、0x10机械与租期参数；验证HMI运行时owner=3、授权/停车正确，CAN不得误判无人。
4. 确认全部控制源释放、两轴新鲜零速、使能有效、无故障/安全锁；发送CAN申请，等待命令完成及新motion_token两项证据。
5. 在1000ms内发送首个新序号0目标；确认受理后先±182mm/s，再±363mm/s。界面可保留±1600rpm范围，现场首轮不得直接满量程。
6. 验证主动撤权、停止心跳、仅停目标、跨源K5/屏急停、重复按键和各源互斥；不能恢复旧token/旧目标。
7. 留存带时间戳CAN原始抓包、上位机日志、`can status`、`can control status`、`hmi status`、实际速度和停车证据。

只通过软件测试和编译时，结论仅为软件准备完成；未取得无运动CAN联调及低速实测证据前不作运动放行或验收完成声明。

### 7.2 全量入口未通过的边界

原样运行`Tests/run_tests.ps1`失败：当前用户CAN控制宏已开启，而旧入口部分编译命令单独关闭CAN传输，触发合法的编译期门禁；同时旧UART测试桩缺少`HAL_UART_RXEVENT_HT/TC`常量。

另使用临时编译器包装显式补齐测试默认宏和HAL事件常量后补跑，仍在既有`Tests/check_irq_dma_integration.ps1:48`失败：该检查要求UART5 RX为`DMA_NORMAL`，而当前已验证的生产RX配置为`DMA_CIRCULAR`。该检查、生产UART配置及CubeMX文件本轮均未修改。包装未改变测试断言，未跳过失败检查；本轮不宣称全量入口通过，也不以专项通过替代它。

相关CAN、HMI、遥控专项结果独立记录。既有IRQ/DMA静态检查与当前接收实现的统一属于后续测试维护事项，不通过退回RX模式来消除失败。
