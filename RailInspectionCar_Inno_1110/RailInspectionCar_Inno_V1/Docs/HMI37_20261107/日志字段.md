# USART1 HLD日志字段（2026-11-07）

采集设置：USART1，PA9 TX / PA10 RX，115200、8N1、无流控。上电前开始保存完整文本；停车后继续保存至少10秒，让37号屏上传两页冻结记录。本文件对应 `APP_HMI_LINK_DIAG_ENABLED=1`；设0时不输出这些自动行，原CLI仍可用。

## 公共格式、时间与编号

所有自动行以 `HLD <T> <B> <I> <类型>` 开头，空格分隔。公共头三个数一律为**无0x前缀的十六进制**：

| 字段 | 含义 |
|---|---|
| T | 本次主控启动的HAL毫秒时钟。事件行是记录事件时刻；周期行、FIRST和SCREEN是格式化输出时刻。FIRST内另有原始停车时刻at。 |
| B | 主控boot ID。不能把不同B的时间/会话直接合并。 |
| I | E行是全局诊断记录序号；FIRST和S行是主控停车event ID；SCREEN是屏端event ID；其余为0。这三种编号使用独立命名空间。 |

例如 `HLD 6DDD00 F1234567 2A E1 ...`：主控运行7200000ms、boot为0xF1234567、诊断序号42、类型为RX_REQUEST。公共头不是十进制。HAL毫秒约49.7天回绕，差值用uint32无符号运算。

E、S、UART、RXERR、DMA、QUEUE、TIMING、QUIET采用固定CSV，CSV数字也**全部为十六进制**。带 `key=value` 的FIRST、MEM、STACK、GAPS、LOGGER、BOOT、PREV、SCREEN保留下文标明的进制。signed16转换：值>=0x8000时减65536；signed32转换：值>=0x80000000时减4294967296。

DWT周期数在168MHz下约25.6秒回绕。两个周期数可在确定间隔短于一次回绕时以uint32差值/clock换算，必须结合毫秒与boot判断。DWT捕获时刻是DMA缓冲捕获/软件处理证据，不是线路最后一位的精确物理时间。

记录序号在FIFO已满时仍递增，因此E行跳号应结合LOGGER检查。不同优先级使文本输出顺序可能不同于时间顺序：FIRST优先，SCREEN和周期摘要也可能插入积压的E行。分析先按boot、T及具体事务关联，不能把相邻文本当成物理先后。

## 固定事件行E

格式为 `HLD T B I E<K> a,b,c,d,e,f`，六个负载保留完整uint32位形，K也是十六进制。`EA`表示第10类TX_COMPLETE。

| K / 名称 | a | b | c | d | e | f |
|---|---|---|---|---|---|---|
| 1 RX_REQUEST | 请求寄存器start | Modbus功能码 | 请求寄存器quantity | 本帧最后一次字节捕获DWT周期 | 解析成功处DWT周期 | 解析处HAL毫秒 |
| 2 MAILBOX | 请求session | 请求sequence | command | 目标低16位，按signed16解释 | 请求TTL，ms | 复制入邮箱时HAL毫秒 |
| 3 CONSUME | 请求session | 请求sequence | command | 按RTOS邮箱年龄换算的接收HAL毫秒 | 邮箱至消费的等待ms | 初始validate错误码 |
| 4 REJECT | 结果session | 结果sequence | command | 拒绝错误码 | 结果接收HAL毫秒 | 结果完成HAL毫秒 |
| 5 TX_SUBMIT | 请求start | 请求功能码 | 响应字节数 | 本地响应入队是否成功：1成功/0失败 | 本帧最后一次字节捕获DWT周期 | 提交调用后的DWT周期 |
| 6 STOP_FIRST | 主控停车event ID | 首次reason | 高16位owner、低16位requester | 请求sequence | 高16位command、低16位减速度mm/s² | 高16位result、低16位error |
| 7 STOP_UPGRADE | 同一停车event ID | 此次升级请求reason | 高16位owner、低16位本次requester | 本次请求sequence | 高16位本次command、低16位新减速度mm/s² | 高16位result、低16位error |
| 8 STOP_COMPLETE | 停车event ID | 当时最终reason | 高16位owner、低16位原记录requester | 原记录请求sequence | 高16位原command、低16位最终减速度mm/s² | 高16位最终result、低16位最终error |
| 9 SCREEN | 预留枚举，本版无该类E输出；屏端记录用独立SCREEN行 | — | — | — | — | — |
| A TX_COMPLETE | 高16位UART响应region、低16位响应长度bytes | 累计完成数：正常响应+异常响应 | 最近完成HAL毫秒 | 最近完成DWT周期 | 自上次任务观察后完成数增量 | 0，预留 |

RX_REQUEST表示完整帧已通过解析，未解析的CRC/帧错误由每秒UART摘要体现；不代表邮箱已消费或运动目标已接受。MAILBOX、CONSUME和REJECT分别反映复制、控制任务消费和结果拒绝。CONSUME中的初始错误为0仍可能在后续序号/会话/命令分支被拒绝，必须继续看REJECT与状态。

TX_SUBMIT只证明本地提交结果；TX_COMPLETE只证明本地UART完成回调被任务观察到，不证明屏端已收到或接纳。完成增量>1时只保留其中最近一次的region/长度/完成时刻，不能据此还原每个完成回调；地址和功能码应与提交顺序关联，不将后一个请求元数据误配给前一帧。

region来自现有UART分类：0=0x0000..0x003F；1=0x0050..0x006F；2=0x0070..0x008F；3=0x0090..0x00AF；4=0x00B0..0x00CF；5=0x0200..0x0217；6=其他（包括0x0460状态、0x0100控制邮箱、0x0700诊断）。整个读写范围必须落在对应窗口才属于该region。

## 首次停车FIRST与100ms状态S

FIRST格式：`FIRST at=... owner=... requester=... reason=... seq=... cmd=... decel=... gen=...`。这些键值均为**十进制**，at为HAL毫秒，decel为mm/s²，gen为仲裁generation。FIRST采用独立固定存储；一次事件建立时冻结，升级及重新授权不覆盖；下一次新的停车event建立时更新。FIRST输出即使FIFO满仍可重试，不能把STOP_COMPLETE或S中的历史/最终reason当FIRST。

S行格式：`S owner,session,state,flags,age,lease,seq,target,out0,out1,reason,phase,result,error,zero,enable`，共16项，均为十六进制。

| 索引（从0） | 字段 | 含义 |
|---|---|---|
| 0 | owner | 采样时当前仲裁owner，见下表。 |
| 1 | session | 当前HMI会话ID；0表示无HMI会话。 |
| 2 | state | 0空闲；1准备；2授权零目标；3运行；4减速；5零速确认；6故障。 |
| 3 | flags | bit0控制功能启用；bit1有会话且未停车；bit2停车结果RUNNING；bit3已停车且允许重新授权；bit4反向处理；bit5/6故障态；bit7现有协议能力标记。 |
| 4 | age | 当前目标年龄ms，uint32；FFFFFFFF可能表示无有效目标。 |
| 5 | lease | HMI租约剩余ms。 |
| 6 | seq | 最后应用的目标/控制序号。 |
| 7～9 | target/out0/out1 | 目标和两个轴输出，均为signed16原始值；本项目控制单位mm/s，不能直接当作屏幕rpm。 |
| 10 | reason | 当前保留的停车reason，可能属于历史事件，可能已被升级。 |
| 11 | phase | 0无停车阶段；1减速；2已写零目标；3确认零速；4停车成功；5停车失败。 |
| 12～13 | result/error | 当前保留停车记录的结果/错误码。 |
| 14～15 | zero/enable | 停车记录的零速确认/使能确认轴位图，bit0轴0、bit1轴1。 |

owner和lease分别读取当前仲裁值与当前租约，其余来自已发布控制快照，因此转换瞬间存在采样差；S用于观察趋势和状态，不替代FIRST及事务证据。重新授权后仍保留历史停车event/reason/result，是设计行为。

owner/requester：0 NONE或现有内部封装未标明来源；1 HMI；2遥控；3 AUTO；4 CLI；5 CAN。requester=0不能解释为“没有触发源”。K5/K3应结合requester、command、sequence和操作时刻区分。

command：1 ACQUIRE，2 HEARTBEAT，3 RELEASE，0x10 STOP，0x11 RECOVER，0x21 SPEED。带键值的FIRST中分别输出十进制1、2、3、16、17、33；E中为十六进制1、2、3、10、11、21。外部来源可能有自己的command命名空间。

HMI停车reason：1 RELEASE，2 STOP，3目标TTL超时，4租约超时，5外部/恢复停车入口，6反馈异常，7其他安全异常。不同控制来源可能复用reason值，应结合owner/requester及command解释，不能只看reason=2判断首因。

result按0～6：NONE、ACCEPTED、RUNNING、SUCCEEDED、REJECTED、FAILED、EXPIRED。error按0～15：NONE、READ_ONLY、BOOT、SESSION、EXPIRED、BUSY、SAFETY、FEEDBACK、RANGE、MODE、CONFLICT、SEQUENCE、QUEUE、TIMEOUT、STOP、COMMAND。

## 每秒摘要与启动记录

每秒摘要拆为10行依次输出，不要求同一毫秒同时发出。MEM阶段缓存UART/运行统计及12任务栈，后续行输出该次缓存；行头T是各行格式化时刻。

| 类型 | 正文字段及顺序 | 进制/单位 |
|---|---|---|
| BOOT | build=编译日期_时间；diag=宏值；lease=配置租约；ttl=配置目标上限；reset=RCC复位标志 | lease/ttl十进制ms；reset十六进制 |
| PREV | type=0上一启动首故障、1上一启动异常；valid；boot；at；code；detail；task；pc；lr；cfsr；hfsr | code/pc/lr/cfsr/hfsr十六进制；其他十进制；at为上一启动ms |
| MEM | free/min=FreeRTOS当前/历史最小空闲堆；reset；diag；wdg；failed；fresh | free/min十进制B；reset/diag十六进制；其他十进制 |
| STACK | bytes=12任务历史最小空闲栈，顺序见下 | 十进制B；NA为任务句柄/缓存无效 |
| UART | requests,responses,crc_errors,frame_errors,partial_timeouts,rx_overflow,tx_busy,tx_errors,rx_errors | 全部十六进制累计计数 |
| RXERR | ore,fe,ne,pe,last_error,dma_rx_error,rx_armed,rx_pending,rx_reason | 全部十六进制；前4项计数、last/dma为位图，armed/pending布尔 |

| TIMING | service_max_ms,response_delay_max_cycles,parse_max_cycles,capture_max_cycles,clock_hz | 全部十六进制；单位分别ms、周期、周期、周期、Hz |
| GAPS | us=motion,servo,health,modbus,CLI,HMI的历史最大服务间隔 | 十进制µs；FFFFFFFF原始无效值显示4294967295，不当作实测阻塞 |
| QUIET | quiet_early_count,quiet_elapsed_min_cycles,raw_last_cycles,tx_complete_cycles | 全部十六进制；计数、周期、周期时间戳、周期时间戳 |
| LOGGER | fifo_lost,uart_drop,screen_conflict,screen_replaced,screen_reused | 十进制累计计数，见下 |

STACK顺序：0 motion，1 servo_comm，2 health，3 key，4 status，5 CLI，6 LCD，7 IWDG，8 NRF，9 CAN，10 HMI，11 Modbus。历史最小空闲栈低于256B时单独分析。48KiB FreeRTOS堆已计入静态ZI，MEM/STACK不应再与map中的全部RAM占用重复相加。

RXERR recovery reason：0 NONE，1 ARM，2 STATE，3 ERROR，4 TIMEOUT，5 SUBMIT。ORE/FE/NE/PE依次为过载、帧、噪声、奇偶校验错误；计数增长说明本地UART观察到异常，仍需事务与首因关联。

QUIET用于首轮观测静默边界：early增加表示TIM2静默中断时距本次quiet定时器启动尚未达到既有quiet周期；min_cycles为所观察最小启动至中断间隔，FFFFFFFF表示尚未形成有效样本。它不改变本轮既有分帧或定时行为，也不能仅凭early增长断言帧被截断。

LOGGER解释：fifo_lost为固定32项事件FIFO溢出时丢失的普通记录数；uart_drop为整行UART入队失败或格式长度异常的次数，重试可能多次计数，不等于丢失事件数；screen_conflict为未输出页覆盖/相同ID冲突等拒绝次数；screen_replaced为上一事件缺页但已输出时由新ID替换次数；screen_reused为完整旧双页已输出后，同ID变化page0开启新一代的次数，覆盖屏单独重启后计数从1重来的场景。

本轮HLD自动输出每1000ms窗口限6000B，单行小于256B，使用USART1既有DMA整行非阻塞接口并预留512B。FIRST/屏页/普通FIFO在发送成功后才确认消费；周期行在拥塞时可能跳过本期；预算耗尽本身不增加uart_drop。普通事件过载允许丢失且计数；不要将缺失周期行或E跳号当作设备复位。CLI手动输出属于原接口，不包含在HLD的6000B自动预算内。

PREV valid=0表示该种上一启动记录无效，不等于已证明从未复位。掉电/BOR可使SRAM保留区失效；记录B、复位标志、时间回退并结合FIRST判断。BOOT的build使用本诊断模块编译时的 `__DATE__` / `__TIME__`，需与本次正式构建日志对应；它不是固件唯一身份，交付清单另有SHA256和Git基线。

## 37号屏冻结两页SCREEN

格式：`SCREEN page=<0/1> mask=<1/2/3> incomplete=<0/1> words=<24个4位hex>`。page/mask/incomplete为十进制；words一律十六进制。公共头I是屏事件ID。mask=3表示两页已被主控接收；同一代两行都保存后才能完整解析。先打印的page0可以显示mask=1/incomplete=1，后收到page1补齐正常。

FC0x10写0x0700共24寄存器；公共word0=0x4844，word1=0x0100|page，word2/3=32位屏event ID高/低字。所有32位量高字在前。上传不进入控制邮箱、不刷新TTL、不刷新会话租约，仅停车确认、owner释放、没有STOP/授权待办时调度；新授权暂停上传。

|---|---|---|
| 0 | 4 | 原因位图，见下 |
| 0 | 5 | 原34事务服务分支行号；对照37工程运行核验中的首因分支JSON |
| 0 | 6 | 有效性位图，见下 |
| 0 | 7 | 原始Modbus返回码，按signed16解释 |
| 0 | 8/9/10 | 回复addr / function / rxLen |
| 0 | 11/12/13 | 请求start / quantity / 屏当前页面 |
| 0 | 14～15 | 调度计数uint32 |
| 0 | 16～17 | 期望主控boot uint32 |
| 0 | 18～19 | 期望session uint32 |
| 0 | 20～21 | 最后发送目标sequence uint32 |

| 1 | 4～21 | 关键状态区前18个寄存器，原样冻结；见下一段 |
| 1 | 22～23 | gap，signed32，ms |

页1中word4..21对应原0x0460..0x0471，顺序：magic、version、boot高/低、publishSeq高/低、主控now高/低、owner、selected、state、flags、session高/低、lease、targetAge、appliedSeq高/低。状态身份期望magic=0x534D、version=2。状态区owner采用现有线协议编码：NONE=0、HMI=1、REMOTE=2、AUTO和CAN均为3、CLI=4、无效=FFFF；它与S/E的C枚举不同，尤其不能把屏状态owner=3直接当作AUTO。

有效性word6：bit0=本次地址/功能码/长度/读字节数或写echo与请求形状一致；bit1=本次0x0460回复至少提取出前18words；bit2=本次状态magic/version/boot匹配；bit3=发布序号相对上次接纳快照向前推进；bit4=页1使用上次缓存fallback。bit1不保证身份或整帧有效；raw返回失败时addr/fc/rxLen可能是驱动旧值，必须结合这些位，不能把上一有效快照解释成本次失败回复。

多个门禁可以同时置位；具体执行分支见word5。启动识别主控boot正常进入状态6不会冻结运行故障。冻结后直到双页ACK完成，后续故障不覆盖；最近已上传记录仍保留到下一运行会话异常。

同ID、同页、相同内容重试只ACK，不重复输出；冲突页拒绝。仅当前代两页均完整且已输出后，同ID但内容变化的page0允许开启新代，并增加screen_reused；page1变化不能开启新代。出现复用时按SCREEN输出顺序及新page0划分代，不能跨代拼页。尚未输出的页不会被新ID或复用覆盖；已输出但缺页的旧事件可由不同ID替换，screen_replaced累计计数，先前的incomplete行仍明确表示缺证。

边界：若旧事件尚缺一页，屏单独复位后又从相同event ID开始，新page0会持续被拒绝，screen_conflict增长。该保护不影响停车和授权，但该次屏记录不能完成上传；先保存现有串口日志，再在后续受控测试中重新启动主控与屏。screen_reused仅覆盖旧双页完整且已输出的情况。

## 软件预算验证范围

专用host回归同时编译宏0/1，覆盖首因不被STOP升级覆盖、FIFO满/串口拥塞、6000B限流、双页校验/冲突/缺页、屏复位同ID、启动故障和堆栈字段。正常负载测试在uptime=7200000ms、boot=0xF1234567条件下持续10秒，模拟每秒20事务：10关键状态读、5 SPEED写、5普通读，并产生接收/入邮箱/消费/响应提交/本地完成五类共70条事件每秒；700/700条连续序号完整输出，峰值5690B/s，FIFO与UART丢失均0。另有每ms事件饱和负载测试，确认预算不会突破6000B/s。

这些是固定内存/格式/行为的host验证，UART物理时延、ISR/任务竞争、实物两小时堆与栈水位仍以正式Keil产物及现场日志为准。
