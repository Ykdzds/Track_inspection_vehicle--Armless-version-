# 02 双轴伺服整体设计与台架测试方案

日期：2026-09-20  
工程：RailInspectionCar_Inno_V1  
范围：第一阶段测试前的软件修复、参数配置、三模式接口及验收流程。

> 本文描述当前软件实现，不代表整车或功能安全认证。默认不自动使能、不自动运行。主机模拟测试及编译成功不代替驱动器实测。未经独立停机保护验收，不开放内部速度和多段位置带动力测试。

## 1. 结论

1. 正常底盘运行使用MCU脉冲加方向，驱动器处于位置模式。改变脉冲频率即可调速，这就是本项目所说的“脉冲速度模式”；它不是驱动器的另一种速度控制模式。
2. RS485内部速度和内部多段位置保留为单轴维护测试模式，不能与正常双轴脉冲运行并行。
3. PC8、PC9是同一AM26C31的共用门禁，不是左右独立伺服使能。软件失能任一轴时采取双轴联停。
4. 不再把参数宏设为1等同于实机验收。资料映射有效、期望参数已确认、驱动器回读成功、软使能接线验证、独立断线保护是不同条件。
5. 软件框架已可进行协议及无动力验证，尚不能判定第一阶段全部完成，更不能直接运行到20 km/h。

## 2. 依据与资料冲突处理

- 用户本轮确认的实际接线、机械参数和57600、8N1测试结果。
- 项目资料《MD130AIS_RS485_Modbus_RTU控制说明.md》。
- 厂家资料《AIMtor低压产品使用说明书.docx》；其中多项参数为图片，不能只依赖DOCX纯文本提取。
- 同目录厂家上位机参数库：AIMtor动态调试软件V20260417中的`my_file/AIMotor.db`，用于补充核对对象地址、枚举和单位。

项目旧控制说明写有8N2，本工程以实测的8N1为准。没有修改USART2为8N2，也不自动写驱动器串口参数。

H03_03本质是DI1输入逻辑，不是通用的软件使能位。仅在DI1功能确认为S-ON、物理DI未接且开路状态与实际驱动器输入电路匹配时，才可能通过0/1实现失能/使能。台架必须观察真实驱动器状态，不可仅凭06H应答或03H回读判定电机已经失能。

## 3. 硬件与配置

统一入口：`APP/app_config.h`。

| 项目 | 当前设置 | 说明 |
|---|---|---|
| 左PWM | TIM9_CH1 / PE5 | 500 kHz计数时基 |
| 右PWM | TIM11_CH1 / PB9 | 500 kHz计数时基 |
| 共用差分门禁 | PC8=1、PC9=0开放；反之禁止 | GPIOC BSRR一次更新互补电平 |
| 左右方向 | PB0/PB1，高正低反 | GPIO及.ioc同步，上电高 |
| 左右站号 | 1、2 | 两轴必须分别设置，避免重复地址 |
| USART2 | 57600、8N1 | 自动流向RS485，不新增DE/RE |
| RX / TX DMA | Circular / Normal | 256字节DMA、512字节软件环 |
| 轮径 | 0.185 m | 左右相同 |
| 减速比 | `APP_GEAR_REDUCTION_RATIO=1` | 定义为电机转数/车轮转数 |
| 电机每转指令脉冲 | 10000 | 上位机已将电子齿轮调整为10000 pulse/rev |
| 脉冲形式 | PUL/DIR正逻辑 | H05_15=0 |
| 电子齿轮 | 131072/10000 | 32位低字在前，先核验H0C_26 |
| 滤波 | 保持出厂值 | 软件不主动写滤波对象 |
| 台架速度 / 距离 | 0.1 m/s / 单次0.1 m | 非20 km/h运行许可 |
| PWM范围 | 100～100000 Hz | 低于100 Hz的非零请求拒绝，不强行抬升到100 Hz |
| 内部模式速度上限 | 600 rpm | 与当前RS485速度模式调试量程一致 |

换算关系：

```text
轮周长 = π × 0.185 = 约0.581195 m
每米指令脉冲 = 10000 × 减速比 / 轮周长 = 约17205.94 pulse/m
电机rpm = 车速m/s × 60 × 减速比 / 轮周长
PWM频率Hz = 车速m/s × 每米指令脉冲
```

600 rpm对应100000 Hz。当前软件允许的RS485速度范围为-600～600 rpm，
外部脉冲范围为100～100000 Hz；这只是接口量程，不代表已经完成满量程实物安全验收。

当前TIM9/TIM11使用500 kHz计数时基：100 Hz约为5000计数，
100 kHz约为5计数，均落在16位ARR范围内；ARR=period-1、CCR=period/2。
TIM9/TIM11和.ioc已同步。若修改系统时钟，必须同步核验PSC、
`APP_PULSE_TIMER_TICK_HZ`和实际波形。

## 4. 三种控制模式

| 模式 | 驱动器配置 | 运动接口 | 执行者 |
|---|---|---|---|
| MCU脉冲位置/调速 | H02_00=1、H05_00=0 | `motion_set_velocity`、`motion_move_distance`、`motion_stop` | motion_task每5 ms推进 |
| RS485速度 | H02_00=0、H06_00=0、H06_02=0 | `aimtor_set_velocity_rpm` | servo_comm_task异步执行 |
| RS485单段位置 | H02_00=1、H05_00=2、H11_00=0、H11_01=1、H11_04=0 | `aimtor_run_segment` | servo_comm_task异步执行 |

内部位置当前仅封装“相对、单周期、单段”维护测试，未开放绝对位置、循环运动或任意多段编排。位置参数单位为指令脉冲，速度单位rpm，加速度参数单位为零到1000 rpm的毫秒数。

模式配置前两轴均需失能、没有待执行配置或脉冲，目标轴反馈速度为零。内部模式还要求维护开关及独立停机确认。内部模式只允许一轴使能。

切换模式不在运动中执行。设置模式返回`SERVO_OK`仅代表请求接受；必须等待快照`busy=0、last_result=SERVO_OK、parameter_verified=1`。写入ACK后还会读取同一对象并逐字比较，失败即联停锁存。

## 5. 参数序列与设零

### 5.1 公共配置

1. 只读核验H0C_26=1，即低16位字在前；不盲目改写字序。
2. H03_03=0并回读，再设置H03_02=1，即DI1功能为S-ON。
3. H02_05=1，即零速后自由停机；不是保持转矩或机械制动保证。
4. 配置控制模式、正PUL/DIR及电子齿轮，逐项回读。
5. 内部速度模式先把H06_03清零，再配置来源及斜坡，防止遗留速度给定导致突然启动。
6. 内部位置模式先将触发逻辑清零，配置DI2功能28及相对单段方式。每次配置只允许一次位置触发，实际到位状态核验后才考虑开放连续触发。

所有动作写入默认不自动重试；读请求最多重试2次。触发写入可能已生效但应答丢失，因此不以“再写一遍”处理超时。EEPROM保存和报警复位对象未完成有效性/副作用核验，接口明确返回`SERVO_UNSUPPORTED`。

### 5.2 上电当前位置设零

- 对象H05_30，地址0x051E，使用值6“记录当前位置为原点”。
- 禁止用值4、5代替，它们会触发回零运动。
- 在本次MCU启动内，每轴最多尝试一次；超时或回读失败不自动重复。
- 两轴静止失能、目标轴脉冲位置参数已核验后，通信任务自动执行；也保留`aimtor_zero_once`接口。
- 写入6后读取H0B_07位置双字并核验为0；不假定H05_30动作对象自身可按普通参数读回。
- 默认软使能门禁关闭时不会发送设零写入。因此“上电设零”是安全初始化阶段的一次性动作，不是main内无条件写。
- 软件无法保证这等于驱动器完整绝对位置原点重建。必须在实机上确认H05_30行为、H0B_07单位/更新时序、掉电与MCU单独复位的区别。

## 6. 停机、断线与看门狗

### 6.1 正常停止

- 脉冲模式按运动规划减速到零，停PWM。
- 内部速度模式给定0，等待实际速度降至0后才能进行失能和模式切换。
- 内部单段位置停止使用失能流程；H02_05的具体制动行为必须实机确认。
- CLI `motion stop`与按键2短按统一调用模式相关停止入口。若正在处理动作而不能可靠插入停止，则升级双轴联停，避免停止被BUSY静默丢弃。

### 6.2 故障与断线

你提出的“停PWM、关AM26C31、RS485失能”方案作为软件层措施是合理的，但不是完整失效保护：

1. 立即清除双轴规划目标，关闭PWM及AM26C31共用门禁。
2. 撤销未执行Modbus请求，阻止尚未开始的TX，锁存两轴失能状态及参数失效。
3. 通信任务尽力发送两轴H03_03=0并回读。在线路上已经发出的字节无法撤回，断线时更不能保证驱动器收到。
4. 通信恢复不自动使能、不恢复旧给定。失能回读、速度为0且两轴状态新鲜无故障后，通过`servo clear`人工解锁并重新配置。
5. 若失能时断线导致失能回读失败，恢复通信后可再次执行`servo emergency`，等待两轴`off_verify=1`再清锁。

外部脉冲被切断并不能停止内部速度/位置模式。建议优先核实并实测驱动器通讯超时H0C_30的时间单位、触发条件和停机动作，同时落实独立于MCU和RS485链路的急停、适用的使能切断/STO或主回路分断。只有驱动器确实支持且正确接线的STO才能称为STO，AM26C31门禁不是STO。

软件定义了H0C_30地址，但未猜测单位或自动写入。`APP_SERVO_MAINTENANCE_STOP_CONFIRMED`默认0，在独立停机保护验收前拒绝内部模式带动力运行。正常脉冲模式同样需要独立急停，尤其考虑惯性、斜坡和脉冲停止后的残余运动。

在线判据使用实际速度与故障码的独立更新时间，任一超过500 ms或连续失败达到3次即失效；参数写入ACK不能替代反馈保活。该阈值不等于精确的硬件停机时间，仍有调度和在途通信延迟。20 km/h下500 ms已对应约2.78 m行程，后续高速设计必须重新做风险评估。

### 6.3 心跳和异常

motion_task、servo_comm_task、health_task三个心跳都在500 ms窗口内，iwdg_task才每250 ms刷新IWDG。通信无从站不等于任务失活：有限超时事务返回后仍更新心跳。

关键心跳失效时先本地联停再停止喂狗。断言、栈溢出及硬故障路径也增加本地停脉冲处理，但CPU完全失控或中断永久屏蔽时，软件不能保证立即执行停机；需硬件保护。LCD/CLI不是喂狗必需条件。

未接伺服、未投入运动时保持SAFE，不因上电只读轮询超时而自动进入运动。故障后READY不会自动恢复。

## 7. 加减速建议

### 7.1 当前台架

脉冲规划使用0.1 m/s²，在0.1 m/s时约1秒加速；停止也使用当前规划加速度。内部速度/位置斜坡参数不是到当前目标速度的总时间，而是零到1000 rpm的毫秒数。

减速比1下，要实现0.1 m/s²理论需要约96866 ms/1000rpm，超过16位上限。因此内部模式默认饱和到65535，实际约0.148 m/s²，10 rpm约0.655秒到达目标。不能宣称三种模式的加速度完全相同。

### 7.2 整车设计建议，尚未开放

配置中预留设计加速度0.3 m/s²、减速度0.5 m/s²。在20 km/h目标下：

- 理想加速时间约18.52秒。
- 理想减速时间约11.11秒。
- 理想停车距离约30.86 m，不含通信延迟、负载变化、滑移及坡度。
- 对应驱动器斜坡约32289 ms/1000rpm、19373 ms/1000rpm。

这是以低冲击为目标的初始建议，不是安全停车能力结论。实际选型需结合整车质量、坡度、轮轨黏着、机械制动、伺服峰值转矩及回馈过压测试。更短停车距离可能要求机械制动或重新限定最高速度，不能简单加大软件减速度。

## 8. 在哪个任务调用

```text
CLI / 后续上位机 / 独立测试入口
  -> 一次性提交封装接口
  -> motion_task推进MCU脉冲规划
  -> servo_comm_task提交并执行唯一Modbus事务、处理回读和轮询
  -> health_task汇总安全条件
```

不在main、ISR、LCD、看门狗任务中调用带运动动作的接口。不在任务每次循环里重复设模式、使能或触发位置段。

建议先使用现有CLI。需要自动测试时另建低优先级测试状态机，分为“请求配置、等待完成、请求设零/使能、等待完成、发送一次运动、观察反馈、停止、核验”等状态。测试任务只调用公共API，不调用HAL、`modbus_process`或直接写GPIO。

`motion_set_velocity(left_mps, right_mps)`支持单轴给定为0，但目前底盘READY仍要求两轴在线、已核验且已使能。仅接一台电机时不应绕过门禁；可先做只读及内部单轴维护测试，脉冲双轴门禁验收需要两轴接入。

## 9. 可执行测试顺序

### 9.1 无动力

1. 断开动力，保留控制电源，准备独立急停。
2. 烧录后确认LCD黑底白字稳定；CLI执行`status`、`comm stat`。
3. 示波器确认PC8低、PC9高，PE5/PB9无有效运动脉冲，PB0/PB1默认高。
4. 未接伺服时应保持SAFE、超时计数增长但关键任务心跳继续刷新，不应周期复位。
5. 分别暂停三个关键任务验证停止喂狗；暂停LCD或CLI不应单独导致IWDG复位。

### 9.2 只读及必要参数确认

1. 先逐台确认地址1/2，再接两轴总线，观察`online`、`rpm`、`fault`。
2. 上位机在动力断开时核实DI1=S-ON、H03_03两种逻辑对应的真实失能/使能、H0C_26低字在前和脉冲参数。
3. `servo verify left`，等busy=0，再`servo verify right`。该命令核验预期脉冲配置，不自动修正不一致值。
4. 核验失败会锁停。软使能门禁关闭时可以仅清锁后继续只读；软使能门禁开启后必须完成失能回读才能清锁。
5. 在独立安全措施已就绪且实测确认软使能行为后，再将`APP_SERVO_SOFT_ENABLE_CONFIRMED`改为1并重新编译；不能只为消除NOT_CONFIGURED就修改宏。

### 9.3 脉冲模式

每条异步指令之间都执行`status`检查完成，不能一次粘贴整串指令：

```text
servo mode left pulse
status
servo mode right pulse
status
servo enable left
status
servo enable right
status
motion velocity 0.02 0
motion stop
motion velocity -0.02 0
motion stop
motion distance 0.05 0.03 0.1
motion stop
servo emergency
```

模式配置后自动设零应最终显示zero=1/1；首次验证时必须观察零点正确且无回零运动。使能后等底盘READY，再发运动。

依次验证10 Hz附近起步、单轴正反转、两轴低速、受控停、联停与断线。方向改变必须看到旧脉冲停止、新方向稳定至少2 ms后才有新脉冲，本实现按5 ms任务周期等待。两个定时器由同一任务周期依次启动，不是硬件同步触发，需测量实际启动偏差。

`motion_move_distance`是开环命令轨迹，不是精确脉冲计数或编码器闭环定位。命令位置采用频率积分估计；10 Hz截止、频率取整、ARR更新延迟和调度抖动都会引入误差。精确定位需后续硬件边沿计数/反馈闭环及停止误差验收。

### 9.4 内部速度模式

先完成独立断线停机验收，才可将`APP_SERVO_MAINTENANCE_STOP_CONFIRMED`设1。两轴均失能、静止且已完成本次启动设零。

```text
servo emergency
status
servo clear
servo maintenance on
servo mode left speed
status
servo enable left
status
servo speed left 5
status
servo stop left
status
servo disable left
```

先确认真实速度降至0再失能。反转测试先停至0再给负rpm。软件不替代驱动器内部换向斜坡验证。

### 9.5 内部位置模式

同样先满足独立停机保护、软使能和零点条件：

```text
servo emergency
status
servo clear
servo maintenance on
servo mode left segment
status
servo enable left
status
servo segment left 50 5 65535
status
servo stop left
```

50指令脉冲理论对应约29.06 mm轮周行程，脱载测试先验证电机角位移。负值为反向相对位置。当前限幅约±172脉冲、1～10rpm、加速参数65535；单次配置只允许触发一次，不以速度暂时为0认定已经到位。

返回脉冲模式需停止、失能回读、清锁、维护关闭，再分别重新配置pulse并核验。不直接在使能状态切换模式。

### 9.6 故障测试

- 工作时断开485：检查PWM和共用门禁停止、状态锁存、链路恢复不续跑。
- 内部模式断线必须通过独立保护停止，不能仅检查MCU门禁。
- 注入CRC错、地址错、功能码错、异常响应、半帧、粘包、超过缓冲容量的连续数据。
- 核验写后读回不一致、设零无应答、位置触发无应答都不会自动重复动作或开放READY。
- 恢复通信后人工执行失能、回读、清锁及重新配置。

## 10. 诊断字段

- `state`：0 BOOT、1 SAFE、2 READY、3 RUNNING、4 STOPPING、5 FAULT、6 OFFLINE。
- `online`：速度/故障反馈满足新鲜度和错误阈值，不代表驱动器已使能。
- `enable`：本软件完成使能写入和回读；不是已解析的真实S-ON状态位。
- `verify`：当前模式期望配置已读回一致。
- `busy/result`：异步操作进行中及最近结果。result=0成功、1未配置、2参数错误、3入队失败、4未就绪、5忙、6不支持。
- `zero=a/b`：本次MCU启动已尝试/已确认设零。
- `latch`：联停锁存；`off_verify`：最近失能寄存器已读回。
