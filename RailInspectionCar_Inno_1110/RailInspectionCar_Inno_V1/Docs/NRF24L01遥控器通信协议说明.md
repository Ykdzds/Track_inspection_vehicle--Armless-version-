# NRF24L01 遥控器通信协议说明

> 2026-10-13按键迁移：物理K5短按受控停车、长按授权；K6短按看门狗测试（默认关闭）；K7/K8短按上一页/下一页。K1～K4无功能但三类事件仍上传。两端固件必须配套升级，升级期间禁止运行；协议无版本协商，旧新混用会功能错位。内部K1枚举/接口及旧文件名仅为兼容保留，实际由K5触发。

> 控制协议的物理键位定义保持不变：K1～K12对应bit0～bit11，不把K5转换成K1位。功能入口用K5=0x0010、K6=0x0020；本地翻页K7=0x0040、K8=0x0080，仅屏蔽上传位0x00C0。下面协议示例中的物理键位不做重编号。

## 2. 协议功能

遥控器每隔 10 ms 尝试发送一帧 32 字节控制数据，主要包含：

- 4 路摇杆数据：LH、LV、RH、RV；
- K1～K12 的短按事件；
- K1～K12 的长按事件；
- K1～K12 的双击事件；
- 帧序号和按键事件批次号；
- 状态标志；
- CRC16 校验；
- 固定帧头和帧尾。

摇杆数据表示连续控制量，接收端应始终采用最新合法帧中的数据。按键数据表示一次性事件，接收端必须根据事件批次号去重，避免无线重发导致同一个按键动作被执行多次。

## 3. NRF24L01 通信参数

### 3.1 射频参数

| 参数 | 当前配置 | 说明 |
|---|---:|---|
| TX 地址 | `11 22 33 44 55` | 5 字节地址 |
| RX Pipe 0 地址 | `11 22 33 44 55` | 与 TX 地址一致，用于自动应答 |
| 地址宽度 | 5 字节 | `SETUP_AW = 0x03` |
| 射频信道 | `RF_CH = 0x02` | 中心频率约 2.402 GHz |
| 空中速率 | 2 Mbps | `RF_SETUP = 0x0E` |
| 发射功率 | 0 dBm | `RF_SETUP = 0x0E` |
| Payload | 固定 32 字节 | 未使用动态包长 |
| 自动应答 | 开启 | `EN_AA = 0x3F` |
| 接收通道 | Pipe 0 | `EN_RXADDR = 0x01` |
| 自动重传延时 | 250 us | `SETUP_RETR = 0x03` |
| 自动重传次数 | 3 次 | `SETUP_RETR = 0x03` |
| NRF 硬件 CRC | 开启，1 字节 | `CONFIG` 中 EN_CRC=1、CRCO=0 |

> 本协议在 NRF24L01 自带的硬件 CRC 之外，又在 32 字节应用数据中加入 CRC16。硬件 CRC 用于无线链路检错，应用层 CRC16 用于验证完整协议帧。

### 3.2 MCU 接口参数

| 信号 | MCU 引脚 | 配置 |
|---|---|---|
| CE | PB11 | GPIO 推挽输出 |
| CSN | PB12 | GPIO 推挽输出 |
| SCK | PB13 | SPI2 SCK |
| MISO | PB14 | SPI2 MISO |
| MOSI | PB15 | SPI2 MOSI |
| IRQ | PA8 | 普通输入，当前未启用外部中断 |

SPI2 使用以下参数：

- 主机模式；
- SPI Mode 0，即 CPOL=0、CPHA=0；
- 8 位数据宽度；
- MSB First；
- 软件 NSS；
- SPI 时钟约 4.5 MHz；
- CSN 由 PB12 软件控制，一条命令传输期间始终保持低电平。

## 4. 发送周期与工作流程

TIM2 每 1 ms 产生一次定时中断，每累计 10 次设置一次发送到期标志。定时器中断只进行计数和置位，不在中断中组帧或访问 SPI。

主循环中的无线任务执行以下流程：

1. 提取并锁存新产生的按键事件；
2. 查询上一帧 NRF24L01 发送结果；
3. 若收到 `TX_DS`，认为自动应答成功，并确认当前按键事件批次已送达；
4. 若出现 `MAX_RT`、SPI 错误或发送异常，保留当前按键事件，等待后续帧继续发送；
5. 每到一个 10 ms 周期，更新摇杆数据并构造最新控制帧；
6. 启动 NRF24L01 非阻塞发送；
7. 若上一帧到下一个周期仍未结束，则中止旧发送，并立即发送包含最新摇杆数据的新帧。

因此，“10 ms”表示遥控器每 10 ms 尝试启动一帧最新控制数据，而不是保证接收端每 10 ms 必然收到一帧。实际接收周期会受到无线干扰、自动重传和接收端状态影响。

## 5. 32 字节数据帧

所有多字节整数均采用大端格式，即高字节在前。

| 字节偏移 | 长度 | 字段 | 当前值或格式 | 说明 |
|---:|---:|---|---|---|
| 0 | 1 | 帧头 1 | `0xA5` | 固定值 |
| 1 | 1 | 帧头 2 | `0x5A` | 固定值 |
| 2 | 1 | 协议版本 | `0x01` | 当前协议版本 |
| 3 | 1 | 帧类型 | `0x01` | 遥控控制数据帧 |
| 4 | 1 | 帧序号 | `uint8_t` | 每构造一帧加 1，自然回绕 |
| 5 | 1 | 有效数据长度 | `17` | 字节 6～22，共 17 字节 |
| 6～7 | 2 | LH | `uint16_t`，大端 | 左摇杆水平方向 |
| 8～9 | 2 | LV | `uint16_t`，大端 | 左摇杆垂直方向 |
| 10～11 | 2 | RH | `uint16_t`，大端 | 右摇杆水平方向 |
| 12～13 | 2 | RV | `uint16_t`，大端 | 右摇杆垂直方向 |
| 14 | 1 | 短按 K1～K8 | 位图 | K1 对应 bit0，K8 对应 bit7 |
| 15 | 1 | 短按 K9～K12 | 位图 | K9 对应 bit0，K12 对应 bit3 |
| 16 | 1 | 长按 K1～K8 | 位图 | K1 对应 bit0，K8 对应 bit7 |
| 17 | 1 | 长按 K9～K12 | 位图 | K9 对应 bit0，K12 对应 bit3 |
| 18 | 1 | 双击 K1～K8 | 位图 | K1 对应 bit0，K8 对应 bit7 |
| 19 | 1 | 双击 K9～K12 | 位图 | K9 对应 bit0，K12 对应 bit3 |
| 20～21 | 2 | 事件批次号 | `uint16_t`，大端 | 新按键事件批次建立时加 1 |
| 22 | 1 | 状态标志 | 位定义见下文 | bit0 表示本帧包含按键事件 |
| 23～27 | 5 | 保留 | 全部为 `0x00` | 后续扩展使用 |
| 28～29 | 2 | CRC16 | `uint16_t`，大端 | 字节 0～27 的 CRC16 |
| 30 | 1 | 帧尾 1 | `0x0D` | 固定值 |
| 31 | 1 | 帧尾 2 | `0x0A` | 固定值 |

### 5.1 状态标志

字节 22 当前定义如下：

| 位 | 名称 | 定义 |
|---:|---|---|
| bit0 | 按键事件有效 | 1：本帧携带至少一个短按、长按或双击事件；0：没有按键事件 |
| bit1～bit7 | 保留 | 当前固定为 0 |

接收端必须同时检查 bit0 和事件批次号。bit0 为 0 时，不应执行按键事件。

## 6. 摇杆数据编码

### 6.1 数据顺序

四路 ADC 数据在帧中的固定顺序为：

1. LH：左摇杆水平；
2. LV：左摇杆垂直；
3. RH：右摇杆水平；
4. RV：右摇杆垂直。

### 6.2 滤波算法

ADC 原始范围为 0～4095。每个 10 ms 发送周期更新一次滤波值，使用整数一阶低通滤波：

```c
difference = (int32_t)raw - (int32_t)filtered;
filtered = (uint16_t)((int32_t)filtered + difference / 5);
```

第一次采样时，滤波值直接等于 ADC 原始值，避免上电后从 0 缓慢爬升。

### 6.3 数值映射

滤波后的 ADC 数据映射到 0～2000：

```c
value = ((uint32_t)filtered * 2000U + 2047U) / 4095U;
```

典型对应关系：

| ADC 值 | 协议值 |
|---:|---:|
| 0 | 0 |
| 2048 | 约 1000 |
| 4095 | 2000 |

每路摇杆占两个字节。例如协议值 1000 等于十六进制 `0x03E8`，发送顺序为 `03 E8`。

## 7. 按键事件位图

短按、长按和双击各使用两个字节，共表示 K1～K12。三类事件采用完全相同的位映射。

| 按键 | 对应位 | 短按字节 | 长按字节 | 双击字节 |
|---|---:|---:|---:|---:|
| K1 | bit0 | 14 | 16 | 18 |
| K2 | bit1 | 14 | 16 | 18 |
| K3 | bit2 | 14 | 16 | 18 |
| K4 | bit3 | 14 | 16 | 18 |
| K5 | bit4 | 14 | 16 | 18 |
| K6 | bit5 | 14 | 16 | 18 |
| K7 | bit6 | 14 | 16 | 18 |
| K8 | bit7 | 14 | 16 | 18 |
| K9 | bit0 | 15 | 17 | 19 |
| K10 | bit1 | 15 | 17 | 19 |
| K11 | bit2 | 15 | 17 | 19 |
| K12 | bit3 | 15 | 17 | 19 |

K9～K12 所在字节的 bit4～bit7 当前固定为 0。

示例：

- K1 短按：字节 14 为 `0x01`；
- K8 短按：字节 14 为 `0x80`；
- K9 短按：字节 15 为 `0x01`；
- K12 短按：字节 15 为 `0x08`；
- K2 和 K5 同时长按：字节 16 为 `0x12`；
- K10 双击：字节 19 为 `0x02`。

## 8. 帧序号与事件批次号

### 8.1 帧序号

帧序号位于字节 4，宽度为 8 位：

- 每次构造新的 10 ms 数据帧时加 1；
- 范围为 0～255；
- 从 `0xFF` 加 1 后自然回绕到 `0x00`；
- 当前程序上电后的第一帧序号为 `0x01`；
- 可用于判断帧的新旧、统计丢帧和监测通信质量；
- 不可单独用于按键事件去重。

### 8.2 事件批次号

事件批次号位于字节 20～21，宽度为 16 位：

- 只有当待发送按键事件被转移为当前活动事件批次时才加 1；
- 同一批按键事件因未收到 ACK 而重复发送时，事件批次号保持不变；
- 同一批事件的重发帧仍会使用新的帧序号；
- 收到 `TX_DS` 后，发送端才清除当前活动事件；
- 发送期间产生的新事件进入等待区，不会混入正在重发的旧批次；
- 范围为 0～65535，溢出后自然回绕。

接收端应记录“最近已执行的有效事件批次号”。收到相同事件批次号时，可以更新摇杆数据，但不得再次执行按键动作。

## 9. CRC16 校验

### 9.1 算法参数

应用层校验使用 CRC16-CCITT-FALSE：

| 参数 | 数值 |
|---|---|
| 多项式 Poly | `0x1021` |
| 初始值 Init | `0xFFFF` |
| 输入反转 RefIn | false |
| 输出反转 RefOut | false |
| 输出异或 XorOut | `0x0000` |
| 校验范围 | 字节 0～27 |
| 存放顺序 | 高字节在前，低字节在后 |
| 标准校验向量 | ASCII `"123456789"` 的结果为 `0x29B1` |

帧尾字节 30～31不参与 CRC 计算，CRC 字节 28～29本身也不参与计算。

### 9.2 C 语言参考实现

```c
#include <stdint.h>

uint16_t protocol_crc16(const uint8_t *data, uint8_t length)
{
    uint16_t crc;
    uint8_t i;
    uint8_t bit;

    crc = 0xFFFFU;
    for (i = 0U; i < length; i++)
    {
        crc ^= (uint16_t)((uint16_t)data[i] << 8);
        for (bit = 0U; bit < 8U; bit++)
        {
            if ((crc & 0x8000U) != 0U)
            {
                crc = (uint16_t)((crc << 1) ^ 0x1021U);
            }
            else
            {
                crc <<= 1;
            }
        }
    }

    return crc;
}
```

接收端计算结果应满足：

```c
received_crc = ((uint16_t)frame[28] << 8) | frame[29];
calculated_crc = protocol_crc16(frame, 28U);
```

仅当 `received_crc == calculated_crc` 时，数据帧才可继续解析。

## 10. 完整示例帧

假设：

- 帧序号为 `0x01`；
- 四路摇杆值均为 1000，即 `0x03E8`；
- K1 发生短按；
- 事件批次号为 `0x0001`；
- 状态标志 bit0 为 1；
- 保留字段均为 0。

则字节 0～27 为：

```text
A5 5A 01 01 01 11 03 E8 03 E8 03 E8 03 E8 01 00
00 00 00 00 00 01 01 00 00 00 00 00
```

对字节 0～27 计算 CRC16-CCITT-FALSE，结果为 `0xC807`。完整 32 字节 Payload 为：

```text
A5 5A 01 01 01 11 03 E8 03 E8 03 E8 03 E8 01 00
00 00 00 00 00 01 01 00 00 00 00 00 C8 07 0D 0A
```

## 11. 接收端解析流程

接收端每收到一个 NRF24L01 Payload，建议严格按以下顺序处理：

1. 确认 Payload 长度等于 32 字节；
2. 检查 `frame[0] == 0xA5` 且 `frame[1] == 0x5A`；
3. 检查 `frame[30] == 0x0D` 且 `frame[31] == 0x0A`；
4. 检查协议版本 `frame[2] == 0x01`；
5. 检查帧类型 `frame[3] == 0x01`；
6. 检查有效数据长度 `frame[5] == 17`；
7. 计算字节 0～27 的 CRC16，并与字节 28～29比较；
8. 按大端格式解析 LH、LV、RH、RV；
9. 使用当前帧摇杆数据覆盖上一帧摇杆数据；
10. 检查状态字节 22 的 bit0；
11. 若 bit0 为 1，读取事件批次号并进行去重；
12. 仅在该事件批次号尚未执行时，解析并执行三组按键事件；
13. 保存本次已执行的事件批次号。

多字节字段解析示例：

```c
lh = ((uint16_t)frame[6] << 8) | frame[7];
lv = ((uint16_t)frame[8] << 8) | frame[9];
rh = ((uint16_t)frame[10] << 8) | frame[11];
rv = ((uint16_t)frame[12] << 8) | frame[13];

event_sequence = ((uint16_t)frame[20] << 8) | frame[21];
```

按键位图可合并为 12 位数据：

```c
short_events = (uint16_t)frame[14] |
               ((uint16_t)(frame[15] & 0x0FU) << 8);
long_events = (uint16_t)frame[16] |
              ((uint16_t)(frame[17] & 0x0FU) << 8);
double_events = (uint16_t)frame[18] |
                ((uint16_t)(frame[19] & 0x0FU) << 8);
```

## 12. 异常处理与可靠性要求

### 12.1 发送失败

出现以下情况时，发送端不会确认当前按键事件已经送达：

- NRF24L01 产生 `MAX_RT`；
- SPI 通信失败；
- 发送状态异常；
- 上一帧超过一个 10 ms 周期仍未完成而被中止；
- 没有收到接收端自动应答。

当前活动按键事件会保留，并在后续帧中继续携带相同的事件批次号，直到某次发送收到 `TX_DS`。

### 12.2 重复帧

由于 ACK 可能在空中丢失，接收端可能已经收到并执行某个事件，但发送端未收到 ACK，从而再次发送同一批事件。接收端必须依据事件批次号去重，不能仅依赖 NRF24L01 自动应答功能。

### 12.3 丢帧

摇杆数据属于状态量，少量丢帧时直接使用下一帧最新值即可，不需要补发历史摇杆值。

按键数据属于事件量，由发送端保持并重发，直到收到自动应答。接收端通过事件批次号保证同一批事件只执行一次。

### 12.4 失联保护

建议接收端维护“最后一帧合法协议数据”的接收时间。若连续 100～300 ms 未收到合法帧，应进入失联安全状态。具体超时时间和安全动作应根据车辆控制要求确定，例如：

- 摇杆控制量回到中值或零输出；
- 禁止继续执行运动指令；
- 触发受控停车；
- 上报遥控器通信失联状态。

只有通过帧格式和 CRC16 校验的数据帧，才可刷新失联计时器。

### 12.5 序号回绕

帧序号和事件批次号都会自然回绕。接收端如需比较新旧序号，应采用无符号差值或环形序号比较方法，不应简单使用数值大小判断。

对于事件去重，至少应保存最近一次已执行的事件批次号。若接收端可能重启，建议在重新建立控制链路时清空本地去重状态，并以首次收到的合法事件批次为新的同步起点。

## 13. 联调检查清单

### 13.1 基础链路

- 两端地址均为 `11 22 33 44 55`；
- 两端地址宽度均为 5 字节；
- 两端信道均为 `0x02`；
- 两端空中速率均为 2 Mbps；
- 两端 Payload 均为固定 32 字节；
- 接收 Pipe 0 已开启；
- 自动应答配置一致；
- 模块使用稳定的 3.3 V 电源，并在模块附近配置合适的去耦电容。

### 13.2 帧格式

- 帧头为 `A5 5A`；
- 协议版本为 `01`；
- 帧类型为 `01`；
- 有效数据长度为 `11`；
- 四路摇杆按大端格式解析；
- K1、K8、K9、K12 位映射正确；
- CRC16 计算范围为字节 0～27；
- 帧尾为 `0D 0A`。

### 13.3 可靠性

- 正常发送时能够检测到 `TX_DS`；
- 关闭接收端时能够检测到 `MAX_RT`；
- 发送失败后按键事件不会提前清除；
- 同一事件批次重复到达时，接收端只执行一次；
- 新按键事件不会与尚未确认的旧批次混合；
- 无按键事件时，状态字节 bit0 为 0；
- 连续失联后接收端能够进入预定安全状态；
- 恢复通信后摇杆和按键功能能够正常恢复。

## 14. 版本扩展约定

后续扩展协议时建议遵守以下原则：

- 不兼容修改必须增加协议版本号；
- 新增帧用途时使用新的帧类型；
- 优先使用字节 23～27 的保留区；
- 保留字段在发送端必须填 0；
- 接收端不应假定保留字段永远为 0，但在当前版本中不得依赖其内容；
- 修改 CRC 范围、字节序、Payload 长度或按键位定义时，必须同步更新收发两端和本文档。
