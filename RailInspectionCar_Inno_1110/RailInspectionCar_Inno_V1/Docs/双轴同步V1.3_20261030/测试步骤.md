# 双轴同步 V1.3 测试步骤

本文件给出复跑步骤。已完成的软件测试结果和原始日志见同目录《验证与交付.md》；以下实物步骤尚未执行。正式默认是线性/P，S 与 PI 均关闭。

## 1. 固定测试版本与默认配置

1. 保存当前源码、原 HEX、板卡/驱动器型号及接线映射。使用 `MDK-ARM/RailInspectionCar_V1.uvprojx`，目标 `RailInspectionCar_V1`，ARMCC 5.06 update 7、C99。
2. 检查 `APP/app_config.h`：`APP_DUAL_S_ENABLED=0`、`APP_DUAL_PI_ENABLED=0`，jerk/Ki/Kaw 均为 0；前后轴方向和传动比与机构一致。主工程 C 宏应为 `USE_HAL_DRIVER,STM32F407xx`，无矩阵测试覆盖宏。
3. 在 PowerShell 进入项目根目录：

```powershell
Set-Location -LiteralPath 'D:\wtzn_sx_\同济大学-轨道巡检车\同济大学轨道巡检车协作资料\5.工程代码\RailInspectionCar_Inno_V1'
```

本次交付默认 HEX 的 SHA256 为 `0F19EDC6E269E6FE43DD9849469B30588496FD68D0CF048041948E4712409569`。后续重新构建或修改参数后，应重新记录哈希，不继续沿用本值。

## 2. 主机自动测试

开发机已安装 MinGW GCC；脚本默认编译器为 `D:\Dev-C++软件--蓝桥杯比赛环境\Dev-Cpp\MinGW64\bin\gcc.exe`。换机时通过各脚本 `-Compiler` 指定实际路径。测试使用 mock，不连接或控制实车。

完整回归入口：

```powershell
& '.\Tests\run_tests.ps1'
```

预期：无编译错误、无断言失败；包含原有通信、授权、K5、失联、恢复、驱动和斜坡回归，以及新增算法和高频目标测试。新算法覆盖四配置，每配置 10000 组随机移动状态重规划；配置门禁共八组。三来源高频目标各连续积分 `5000/5000 ms`，模拟每轴 60 ms 串行写延迟。

需要单独定位新增功能或导出模型 CSV 时执行：

```powershell
$modelOutput = Join-Path $env:TEMP 'rail_dual_axis_v13_model'
New-Item -ItemType Directory -Path $modelOutput -Force | Out-Null
& '.\Tests\run_dual_axis_tests.ps1' -Output $modelOutput
& '.\Tests\run_dual_source_random_tests.ps1'
```

模型输出 `dynamic_model_0..3.csv`，分别为线性无同步、线性/P、S/P、S/PI。对比使用同一目标脚本；模型速度通过电机动态方程积分。模型收益不能作为实车放行依据。

单独复跑完整延迟矩阵及历史现场问题回归：

```powershell
& '.\Tests\run_normal_timing_tests.ps1'
& '.\Tests\run_field_regressions.ps1'
```

延迟矩阵预期 864 组通过。日常快速检查可给两个脚本加 `-Quick`；时序快速配置为双轴、同步开启，共 144 组。`field` 表示历史问题的主机复现，不能据此填写“现场通过”。同步优先时共同到速可放缓，同时核验服务时间不丢失、最终命令变化率及停车断言。

## 3. Keil 编译与静态资源

1. 打开原主工程，选择上述目标并执行 **Rebuild all target files**。通过条件为 `0 Error(s), 0 Warning(s)`，生成 HEX/AXF/map/htm。
2. 执行静态栈检查：

```powershell
Get-FileHash -LiteralPath '.\MDK-ARM\RailInspectionCar_V1\RailInspectionCar_V1.hex' -Algorithm SHA256
```

3. 完整构建验证可顺序执行以下脚本。运行期间不要同时在 GUI 保存工程或启动其他构建：

```powershell
& '.\Tests\build_remote_sync.ps1'
& '.\Tests\build_dual_axis_modes.ps1'
```

第一项构建轴选择 1/2/3 × 同步关闭/开启六配置；第二项构建 S/P、S/PI 测试配置。两项正常结束后均恢复工程并重新构建正式默认配置。若脚本失败或被终止，即使工程文本恢复，也须人工核验宏并 Rebuild 默认配置后再取 HEX，不能使用中途产物烧录。

通过条件：每配置均无错误和警告、内存区域未溢出、静态栈余量至少 256 字节。当前默认构建伺服通信任务静态余量 392 字节；运行时还要测栈高水位、最长周期和中断嵌套。测试模式 jerk/Ki/Kaw 仅供编译与算法验证，不作为实车参数。

## 4. 台架接线、读回与采集准备

1. 依现场已有操作规程固定车辆、支撑驱动轮组，确认急停、接管和机械防护可用；先在已验证的低速范围试验。
2. 登记固件哈希、板卡版本、驱动地址与前/后轮组对应关系、方向、传动比及轮径。逐轴读回驱动模式、H06_03 指令来源、H06_05、H06_06、限流和故障；本次软件未获取实物读回。
3. 用独立测速仪核验两轴方向及电机/轮轴约 8/3 的传动关系。名义 1 电机 rpm = 0.375 轮轴 rpm = 0.0392699 rad/s；185 mm 名义轮径下约 3.632 mm/s。
4. 使用已有遥控/HMI/CAN 下发方式，不用 CLI 直接速度命令替代正常业务路径。`ramp status` 可核验协调缓存；它不主动读总线，单靠人工查看不能代替动态数据记录。
5. 设置带单调时间戳的连续采集，至少包括：来源/授权代次/目标序号、目标接收时间、共同参考及加速度、最终两轴命令、批次提交/ACK、两轴原始 rpm 与样本时间/序号、配对/插值来源、有效性、补偿请求/实际和约束标志。外部测速同步记录；不得把 ACK 时间当作到速时间。
6. 固定正式性能阈值和试验速度范围。轮轴差 RMS/P95/峰值、到速时间差、超调、零速爬行和停车距离的实车阈值目前尚未确定，应根据基线与现场要求填写。

## 5. 台架正常运动与异常边界

每种正常控制来源都重复以下步骤；各阶段使用相同合法目标脚本和授权/保活机制，不绕过序号、租期或仲裁。

1. 从零加速至低速，保持匀速，再同向升速和降速，普通目标归零。正反方向各测一次，核验全过程轮轴差和共同跟踪误差。
2. 运行中非线性改变共同目标；分别测试重复保活、低于批次周期的目标更新、短时间连续更新。核验仅最新目标生效，服务积分没有因更新或等待 ACK 重置。
3. 正向运行请求反向，减速中依次测试目标归零、恢复原方向、改为另一反向目标。核验等待真实零速确认后才换向，无卡在零速、越零或已停轴被补偿唤醒。
4. 在允许范围内施加可控的不对称负载/摩擦；观察同步优先导致的共同到速放缓、饱和解除及稳态残差。不得用未经核验的 ±1600 rpm 软件上限扩大试验速度。
5. 单独测试 K5、快速停车、失联、租期到期、跨源接管和恢复授权，核验停车期限不延长，恢复后不复用旧运动目标。与无同步或原版采用同一条件比较停车表现。
6. 反馈过期/重复/乱序、串口延迟、单轴失败、半批次取消及迟到应答优先用主机故障注入复跑；物理断链测试按现场故障试验规程在支撑台低速进行。核验旧代次/旧批次不恢复运动，故障退出后不自动续权。

软件命令约束通过不等于轮轴实际动态同步通过。串行时间错位、噪声和量化须单独统计；只有有历史依据才按同一过去时刻插值，不能补造编码器同步采样。

## 6. 250 kg、360 kg 整车验证

1. 支撑台通过后，在现场已验证的直轨低速范围，以约 250 kg 空载进行相同目标脚本、普通归零和分级停车测试。记录坡度、轨况、轴荷及轮径。
2. 固定配重逐级增加，逐级核验同步、停车、电流、温升和黏着，最后到约 360 kg。不同配重使用同一脚本进行对照，不默认前后轴各分担一半牵引力。
3. 每组报告前后轮轴差 RMS/P95/峰值、共同误差、到速时间差、超调与持续时间、零速爬行、配对率/错时、命令批次间隔和停车距离。保存目标/命令/反馈原始数据及对应源码/固件哈希。
4. 未达到预先填写的指标或缺少数据时，该项继续标记“未验证/未通过”，按交付回退说明回到已验证版本。

## 7. S 与 PI 的后续独立验证

先完成线性/P 的台架和整车基线。保存该版本回退点后，单独标定 jerk 并只开启 S，重做途中重规划、超调、普通零/换向、安全停车及负载对照；通过后再评估是否有必要开启 PI。

PI 的 Ki/Kaw 根据持续残差与实测整定，测试饱和、反馈失效、近零、撤权和安全接管时的积分清理/回算。若收益不足，继续 Ki=0。任何阶段都不自动放开 S/PI、不延长租期、不用模型测试参数代替现场标定。
