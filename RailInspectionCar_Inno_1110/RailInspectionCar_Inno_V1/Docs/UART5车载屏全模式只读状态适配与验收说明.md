## 2. 字段适配表

| 区域/字段 | 当前规则 | 软件验证 |
|---|---|---|
| R0 0000/0001/0002/000F | 系统状态与初始化完成分开，完成锁存为阶段6、100% | 初始化完成、运行状态编码测试 |
| 0018/0019、0204/0205 | 共用持久化启动号，高字在前；失败为FFFFFFFF | 单次启动一次写入、掉电跳号、失败、六区编码 |
| 001C | 启动身份、健康、轴快照、启动、遥控、CLI和拥有者来源成功 | 来源失败清零 |
| 0029/0033 | 软件使能配置回读新鲜且与当前软件状态一致才为0/1；否则FFFF | 写应答不能冒充回读；过期测试 |
| 0034 | 单轴方向归一；双轴使用同一对样本及各轴轮径、传动比；方向未确认无效 | 历史配对与最新反馈不同测试 |
| R1 0050/0051、0060～0063 | 完全合法请求/正常响应TX完成计数；异常响应单独计数 | 非法范围、功能、CRC、广播、发送忙与失败 |
| 0053、0064 | 半帧断帧计数；合法请求年龄，非法流量不续期 | 帧间静默、残帧恢复 |
| 005E | 显式目录：0运动、1伺服通信、2健康、3NRF，FFFF无 | 编码映射 |
| R2 0070～007F、008C/008D | 左右位置独立有效；里程完整性及S32哨兵，保留原里程安全门禁 | 单轴、过期、不完整、边界 |
| 0080 bit2 | 实际速度差超过现有APP_REMOTE_SERVO_SYNC_ERROR_RPM阈值，不是联停开关 | 联停开关关闭也能显示超差 |
| 0081、0084～0086 | 故障显式映射4；活动补偿发布控制器误差，其余模式只读配对；未执行补偿为7FFF | CLI/遥控/单轴/故障 |
| 008E | 轴与遥控诊断来源获取成功；单轴完整表达不适用，无配对时字段为哨兵 | 源失败与单轴 |
| R3 0091/0092/0093/009D | 来源不足有效位0；无已知异常时等级/码/源FFFF；已知异常保留但不伪报完整 | 来源失败、已知告警、有效性事件变化 |
| 009A | 没有实体DI3反馈，固定FFFF，软件K1锁存不冒充硬件反馈 | K1与未知分离 |
| 009C、00CD | 摘要缺完整来源且无已知异常时FFFF；最高告警等级与0091一致 | 编码一致性 |
| R4 00B0/00B1/00B3 | 无来源FFFF及有效0；配置的摄像/存储记录完整时有效，过期重新无效 | CAN能力、未接入、过期 |
| 00CE/00CF | 分别依据诊断来源和拥有者/遥控/CLI/调试/K1来源完整性 | 独立无效测试 |
| 元数据0200～0217 | 标识5249、版本1、字典1、只读功能位1，HMI授权及允许轴/速度为0 | 六区响应与固定值 |

CAN上层能力位与可用数据源位分别解释：有能力但数据源不可用仍保留能力，并发布未知/无效，不错误变成未配置；任务或存储已配置但对应记录缺失时告警快照也不声称完整。

有效位表达“对应来源与快照完整”，不是所有设备都正常。完整快照可以报告离线、过期或故障；未接入的电池、机械臂、DI3、制动等不能伪造正常数值。告警完整性还要求选中轴故障反馈新鲜。

使能字段只反映现有接线约定下的软件使能寄存器回读，不是独立硬件SON。CLI等模式没有持续使能回读时可能显示未知，本轮不新增伺服查询。

## 4. 启动日志与下载

启动身份服务在CAN、HMI初始化前执行，每次MCU启动最多写一条现有64字节日志，沿用原配置指纹、令牌块与CRC/最后提交标记；运行期不擦写。

CAN关闭但HMI运行时仍需启动身份，仍写一条日志。这取代旧的“CAN关闭不写身份区”约束；CAN自身不创建任务、不重复分配身份。

现有日志及16位通信令牌块约束下最多支持2048个启动槽（含部分写入消耗），本轮不扩大编号或修改格式；频繁复位测试应提前检查剩余日志容量。

下载必须保留Flash扇区11的080E0000～080FFFFF；代码链接仍限制前896KiB。不自动擦除，不回绕；部分写入槽不复用。日志耗尽或损坏时先停机维护，清除双方历史缓存后才允许重新编号。

失败时HMI启动号FFFFFFFF、001C=0，通过USART1的hmi status查看identity_result；CAN拒绝新会话。不因身份故障新增遥控/CLI停车。

## 5. UART5接收与诊断

ISR保存字节及DWT到达时间，不清零CYCCNT；1750us静默确定边界，任务延迟不伪造静默。每轮最多64事件、2帧、200us；快照服务不计入收帧解析预算。溢出/UART异常后丢弃残流，等待新边界；未运行超过CYCCNT回绕周期丢弃旧流。

屏幕应按主站规则等待上一请求应答后再发送下一请求；若在TX未完成时连续发新请求，主控不阻塞排队响应，记录tx_busy。

USART1命令：

    hmi status
    can status
    can stat
    remote servo status

hmi status显示只读状态、启动号、身份结果、发布序号及合法请求、正常响应、异常、CRC、帧错误、半帧、溢出、发送忙和失败统计。无需持续打印UART5每帧。

## 7. 实物验收步骤

1. 使用独立12V给屏供电，UART5 TX/RX交叉、共地，LVTTL不接RS485及12V；车辆固定后进行低速测试。
2. 抓取六区请求与应答：R0=0000/64、R1=0050/32、R2=0070/32、R3=0090/32、R4=00B0/32、元数据=0200/24。
3. 检查地址1、03H、字节数、CRC、端序、发布号递增、R0和元数据启动号一致；主控100ms快照不等于屏幕整轮100ms刷新，以实测记录为准。
4. 上电、按键、软件、K2真实看门狗复位后确认新启动号；安全恢复按原策略，不恢复旧授权。看门狗测试固定车辆进行。
5. 验证待机、遥控正反向、CLI速度/位置/脉冲、K1保持、单轴离线、位置断续、双轴错时；不得为显示测试改变实际安全逻辑。
6. CAN上层接入/断开，验证任务、摄像、存储能力与记录过期；未接入外围显示未配置/未知。
7. 测试主站仅暂停某区轮询，该区过期而其他区继续刷新；正式固件不加停发布注入。
8. 拔掉屏幕，确认遥控与伺服原行为不变；屏端抓帧全程只有03H，不发生写入。
9. 记录USART1丢弃、USART2错误增量、UART5统计、CAN Bus-off、NRF状态、任务心跳和栈高水位，检查无新增异常复位。

## 通信恢复补充（2026-10-11）

UART5已增加挂接核验、RX/TX隔离恢复、发送超时及完整hmi status诊断。R0至R4、元数据和业务有效性规则不变。诊断需保存全部输出，原两行不足以定位停收/停发。详细字典及30分钟验收模板见同目录《UART5通信恢复改进与实物验收说明》。恢复只保证主控继续处理后续有效请求，不能使停止轮询的屏幕主动恢复请求；实物问题仍须双向抓帧确认。
