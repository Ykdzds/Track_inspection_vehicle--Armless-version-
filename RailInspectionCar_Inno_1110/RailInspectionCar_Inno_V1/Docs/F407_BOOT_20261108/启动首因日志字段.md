# 启动和停机首次入口日志

实现标识为`link5-boot-r2`。只要公共诊断启用，已挂钩入口会在修改状态前请求冻结首条快照。快照最多24个32位字，固定槽不超过128B；成功输出前不得覆盖，失败输出重试，输出后仍保留到下一次诊断初始化。后续入口只增加`merged`。

**STARTUP表示本boot首个已挂钩的启动失败/停机入口，不保证是启动失败。** 运行后的首次正常受控停车完成也可能进入该槽。应结合source、reason、阶段和其他停车记录判断。它记录软件入口及缓存现场，不能单独证明驱动器、供电、布线等物理根因。

## 行格式和组装

```text
LD <capture_ms_hex> <boot_hex> <serial_hex> STARTUP part=<hex> parts=<hex> count=<hex> merged=<hex> w=<hex words>
```

当前版本每页8字、共3页，`count=18`是十六进制24。`capture_ms`是冻结时刻，可能明显早于串口打印时刻。所有页按boot、serial、capture_ms共同关联；三页不是三次独立故障。缺页、同页冲突或未知魔数不得拼接为完整诊断。

`tools/analyze_link5_log.py`输出`startup_first`数组及完整性、缺页和冲突说明。它不会将普通STATE/HEALTH分页当成同一原子快照，也不会凭邻近行强行关联事务。

## 24字布局

| word | 内容 |
|---:|---|
| 0 | 魔数`53540118`：版本1、24字 |

| 2 | detail，按source和reason解释 |
| 3 | 捕获uptime，单位ms |
| 4/5 | 左/右阶段：startup_stop高8、boot_zero次8、hold次8、cold_clear低8 |
| 6/7 | 左/右action高8、step_index次8、step_count次8、reading_back低8 |
| 8 | 当时待处理事务ID |
| 9 | cancelled高8、pending_axis次8、pending_tag低16 |
| 10/11 | 当前寄存器高16、期望第一字低16；无活动步骤时为0 |
| 12/13 | 左/右原始有符号速度RPM高16、驱动器故障码低16 |
| 14～16 | 左速度、故障、使能缓存年龄，单位ms；FFFFFFFF表示没有有效样本 |
| 17～19 | 右速度、故障、使能缓存年龄，单位ms；FFFFFFFF表示没有有效样本 |

## 来源和原因码

| source | 名称 |
|---:|---|
| 0 | UNKNOWN，未细分入口 |
| 1 | STARTUP，启动检查或启动动作 |
| 2 | BOARD_KEY，板载按键 |
| 3 | REMOTE，遥控 |
| 4 | HMI，车载屏 |
| 5 | CAN，上层CAN控制 |
| 6 | HEALTH，健康/安全监控 |
| 7 | DRIVER，驱动服务 |

以下reason使用十六进制，仅适用于source=STARTUP。代码相同的大类仍需结合阶段、轴和动作解释：

| reason | 含义 |
|---|---|
| `0101` | 启动停车失能写失败 |
| `0102` | 启动停车失能确认失败 |
| `0103` | 启动停稳超时 |
| `0104` | 启动配置、期限或锁存条件失败 |
| `0105` | 启动阶段发现真实故障 |
| `0201` | 上电设零准备失败 |
| `0202` | 上电设零写入失败 |
| `0203` | 设零后新位置确认失败 |
| `0204` | 上电设零安全状态异常 |
| `0301` | 启动保持准备失败 |
| `0302` | 启动保持写零失败 |
| `0303` | 启动保持使能失败 |
| `0304` | 启动保持反馈或固定期限失败 |
| `04xx` | 冷启动preflight，低字节为`servo_cold_clear_failure_t` |
| `0501` | 启动序列响应失败；detail为实际`modbus_status_t`，格式不匹配为`MODBUS_FRAME_ERROR` |
| `0502` | 参数读回不匹配；detail高16寄存器、低16实际不匹配字 |
| `0503` | 启动序列提交失败；detail为`SERVO_QUEUE_ERROR`，尚无已发送事务号 |

source=BOARD_KEY时，reason是按键事件类型，detail高16是KEY_ID、低16是事件处理时采样的引脚电平。KEY2为PD10。采样电平不能代替按键驱动已完成的消抖/长按判定。

响应处理触发的记录保留原响应transaction ID，即使普通pending已经进入清理。`0501`的detail使用Modbus状态域，不能把该数值直接套用为`servo_result_t`；本记录没有完整原始响应，应结合RS485事务及协议校验日志分析。

其他source的reason由各调用点传入，不能套用上述STARTUP原因表。UNKNOWN可说明存在未细分的直接入口；不应自动推定为按键或通信故障。

| startup_stop | 0 skipped，1 waiting，2 disabling，3 waiting_zero，4 configuring，5 verifying，6 done，7 failed |
| boot_zero | 0 skipped，1 waiting，2 preparing，3 writing，4 verifying，5 done，6 failed |
| hold | 0 disabled，1 waiting，2 preparing，3 writing_zero，4 enabling，5 verifying，6 ready，7 failed |

## 其他诊断变化

RS485正常成功消费最多按200ms采样。`accepted=1/matched=0`可能只是有限诊断关联信息已经替换，此时只增加替换计数；业务accepted值仍以真实消费结果为准。不能把这种诊断匹配失败当成参数拒绝或迟到响应。RS485摘要最后追加该替换计数，总计22字。

MEM、STACK、TIMING等周期页只有成功发送后才前进。拥塞期间应等待同页重试；重新采样的不同周期页属于独立观察，不应拼成原子快照。未输出完整启动过程、缺少周期页或存在丢弃时，验收必须保留证据缺口。
