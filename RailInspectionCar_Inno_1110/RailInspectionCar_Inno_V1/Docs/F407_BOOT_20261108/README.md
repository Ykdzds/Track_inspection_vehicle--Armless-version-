# F407上电停留BOOT修复交付

本轮仅修改F407。遥控端、F103、34号和37号屏保持原版本，未执行实物烧录或推送。

基线提交：`0080780 feat: 增加LCD与人工调试资源裁剪并缩减HMI和位置缓存`。修复实现标识：`link5-boot-r2`，定义于`APP/app_link_diag.h`。本轮修改尚未提交时，必须同时保留源码摘要，不能只用HEAD或某个编译单元的构建日期识别固件。

## 问题与证据范围

现场表现为红灯、HMI停留BOOT、双轴未使能。原生产路径在双轴多步参数配置期间持续优先执行配置事务，速度、故障和使能反馈缺少刷新机会；使能前再检查时可能已超过500ms。随后安全停机清除核验/使能标志并锁存，初始化条件不能完成。

直接使用生产伺服驱动、Modbus和独立安全监控代码的探针已复现该路径。6/8/10ms是测试注入的合法回复延迟，不能当作现场总线实测耗时。现场旧日志缺失部分启动记录，因此本轮同时保存状态清除前的首个启动失败/停机入口，用于确认实际失败分支。不能仅凭修复的复现结果宣称已证明现场物理根因。

## 修复行为

- 启动停稳、上电设零和启动保持的配置/核验序列，在完整参数步骤（包括规定写入及读回）完成后，允许插入一个到期关键反馈。优先缺样及最陈旧项目，同等条件轮转；不修改配置索引或比较结果。
- 上电设零写入确认后的新位置读取优先取得启动调度机会；配置以外的启动确认阶段可继续刷新，不依赖配置步骤令牌才能获取反馈。
- 尚未使能且反馈仅陈旧时保持零目标、失能，等待刷新；沿用原固定启动期限，不以等待重置期限。使能前核对新鲜零速、无故障、核验及失能证明；使能后仍要求新反馈。
- 独立安全事务、紧急失能保持优先。真实故障、非零速度、读回不匹配、实际通信失败及期限届满继续拒绝或锁存；已使能后的500ms反馈保护保持原样。
- 在启动失败或已挂钩停机入口清除状态前，冻结24个32位字的首次快照。固定槽不超过128B，成功输出前不覆盖，输出后保留到下一次初始化。字段与解释边界见[启动首因日志字段](启动首因日志字段.md)。
- 正常成功消费记录采用200ms采样。业务已接受而诊断关联信息被下一事务替换时只计替换数，不将其当作业务拒绝。周期摘要仅在成功发送后推进页号，失败时重试。

32项公共事件队列、USART1 DMA、串口字节缓存和6000B/s总限速均保留，不新增任务，不在运行期申请内存。诊断仍由公共worker格式化和发送。

## 软件验证与构建

在工程根目录运行：

```powershell
python -B Tests/run_boot_regression.py
pwsh -NoProfile -ExecutionPolicy Bypass -File Tests/build_boot_startup.ps1
```
