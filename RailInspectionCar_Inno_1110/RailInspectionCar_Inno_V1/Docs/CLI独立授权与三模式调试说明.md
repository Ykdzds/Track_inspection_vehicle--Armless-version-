# CLI独立授权与三模式调试说明

> 2026-10-13按键迁移：物理K5短按受控停车、长按授权；K6短按看门狗测试（默认关闭）；K7/K8短按上一页/下一页。K1～K4无功能但三类事件仍上传。两端固件必须配套升级，升级期间禁止运行；协议无版本协商，旧新混用会功能错位。内部K1枚举/接口及旧文件名仅为兼容保留，实际由K5触发。

更新日期：2026-10-07。

## 1. 适用范围

USART1 CLI新增单轴独立调试会话，支持RS485速度、RS485位置和外部脉冲位置测试。无需关闭上电使能待机或遥控功能宏，CLI调试不参与双轴实际速度P同步。

本轮保留现有现场配置：LEFT_ONLY、Kp=0.30、既有停车减速度及同步开关不变。当前固件只能申请左轴；RIGHT_ONLY只能申请右轴；BOTH固件可以运行时任选一轴，但不能同时调试两轴。

本功能仅用于固定车辆的台架调试。串口断开不能立即检测，电机可能继续运行到保活超时；模式切换时目标轴会短暂失能，不能视为全程具备保持力。软件停车不替代机械固定或独立制动链路。

## 2. 配置

| 宏 | 默认值 | 含义 |
| --- | --- | --- |
| `APP_SERVO_CLI_DEBUG_ENABLED` | `1U` | 允许创建独立CLI会话，只允许0或1 |
| `APP_SERVO_CLI_DEBUG_TIMEOUT_MS` | `30000U` | 从申请受理或最近匹配保活开始计算的超时，单位ms |

调试宏为0或只读配置时不能授权运动，查询、停止、失能和急停仍允许。

## 3. 授权命令

```text
servo debug on left
servo debug on right
servo debug status
servo debug keepalive <session_id>
servo debug off
```

`on`只提交申请。返回示例：

```text
servo debug on=queued result=0 session_id=1
```

收到`queued`不表示已授权。通过`servo debug status`确认`state=ready authorized=1`后才能发送运动命令。状态显示控制权、会话号、控制代次、轴、会话阶段、剩余保活毫秒数、调试模式、退出原因和最近结果。

上位机建议每1秒发送一次匹配会话号的保活，例如：

```text
servo debug keepalive 1
```

旧会话号不能续期新会话。`status`、运动命令、周期打印都不刷新期限；进入会话阶段也计时。停止及恢复阶段不接受保活，以各自安全确认期限控制退出。

## 4. 三模式操作

以下以左轴为例，右轴在支持的固件上替换为`right`。

### 4.1 RS485速度

```text
servo debug on left
servo debug status
servo debug keepalive 1
servo left speed 150
servo left status
servo left stop
servo debug status
servo debug off
```

必须使用实际返回的会话号，并持续保活。速度正负值表示正反向。速度0按停止请求处理。

已核验的RS485速度零速待机可直接接管，不先失能。停止请求立即撤销普通运动权限；写入零速并取得两次新零速反馈、无故障确认后，失能目标轴，重新进入会话`ready`。此时会话仍存在，下一条运动命令重新准备并使能。

### 4.2 RS485位置

在会话`ready`、当前运动已停止后：

```text
servo left position 1000 50 500
servo left status
servo left stop
```

命令格式为：

```text
servo <left|right> position <distance> <speed_rpm> <accel_ms>
```

三个数字的含义如下：

| 参数 | 示例值 | 单位 | 含义 |
| --- | ---: | --- | --- |
| `distance` | `1000` | 驱动器位置指令单位，当前为指令脉冲 | 相对当前位置移动的距离；正数和负数分别表示两个方向，不能为0 |
| `speed_rpm` | `50` | rpm | 本次位置段的最大运行速度，范围为1～600 rpm |
| `accel_ms` | `500` | ms | 驱动器位置段的加减速参数，表示从0 rpm到1000 rpm的时间，不是本次动作总时间，不能为0 |

因此：

```text
servo left position 1000 50 500
```

表示左轴从当前位置开始，沿正方向移动1000个驱动器位置指令单位，最大速度50 rpm，位置段加减速参数为500 ms。位置段是相对位移，不是绝对位置值。当前工程会在后台异步完成位置模式配置、失能、参数写入、重新使能和触发，CLI返回`queued`只表示请求已受理，不表示已经到位。

在当前项目按10000指令脉冲/电机转、1:1传动比和185 mm轮径估算，1000个指令脉冲约为0.1个电机转，对应轮缘理论距离约58.1 mm；该换算只有在驱动器位置指令单位已经确认与当前10000脉冲/转配置一致时才成立，正式测试仍应以位置反馈和实际行程标定为准。

`accel_ms=500`不是“500 ms完成整个位置动作”。按照驱动器定义，它是0～1000 rpm的加减速时间；实际动作总时间还取决于目标距离、最大速度、驱动器内部位置规划和到位处理。

### 4.3 外部脉冲位置

```text
servo left pulse forward 1000 1000
servo left status
servo left stop
```

命令格式为：

```text
servo <left|right> pulse <forward|reverse> <frequency_hz> <pulse_count>
```

三个参数的含义如下：

| 参数 | 示例值 | 单位 | 含义 |
| --- | ---: | --- | --- |
| `forward` | `forward` | 无 | 运动方向；使用`reverse`表示反向 |
| `frequency_hz` | `1000` | Hz | 主控输出PUL脉冲频率，决定运行速度；当前允许范围为100～100000 Hz |
| `pulse_count` | `1000` | 个脉冲 | 本次输出的目标脉冲总数，决定理论位移，必须大于0 |

因此：

```text
servo left pulse forward 1000 1000
```

表示左轴正向输出1000 Hz的脉冲，共输出1000个脉冲后停止。按当前10000脉冲/电机转、1:1传动比和185 mm轮径估算，1000个脉冲约为0.1个电机转，对应理论轮缘距离约58.1 mm；实际距离还要结合驱动器电子齿轮、脉冲输入配置和现场标定确认。

在上述配置下，1000 Hz对应理论转速约6 rpm，计算式为：

```text
转速(rpm) = 脉冲频率(Hz) × 60 ÷ 每转脉冲数
```

脉冲数是主控外部PUL输出的计数，不等同于位置监控模块读取的伺服内部反馈计数。脉冲输出完成后，工程还会结合脉冲计数、位置反馈、速度为0及位置稳定性进行完成确认；不能只根据“已经输出了目标脉冲数”判断伺服已经到位。

在不同模式之间切换前，先停止并等待会话恢复`ready`。也可使用：

```text
servo left mode speed
servo left mode position
servo left mode pulse
servo left enable
```

模式准备完成情况通过`servo left status`读取。`servo debug status`中的会话`ready`与模式准备完成是不同概念。

## 5. 互斥与安全行为

| 场景 | 行为 |
| --- | --- |
| 遥控授权、准备或停车中 | 拒绝CLI授权 |
| 遥控K5人工停车锁存、零速使能保持期间 | 拒绝新CLI会话；回中并新长按K5解除遥控锁存，不能借CLI绕过 |
| CLI进入、运行或退出期间遥控长按K5 | 消费事件，不抢占、不留给下一轮授权 |
| CLI期间无线失联 | 不单独终止CLI，以串口保活和伺服安全反馈为准 |
| CLI期间收到新的遥控K5短按 | 立即撤权、关闭本地输出、尽力失能并锁存，不走遥控受控斜坡 |
| 非会话轴运动、模式、使能及维护写入 | 拒绝；查询不受限制 |
| 人工停止 | 优先取消旧请求，异步停稳后保留会话 |
| 人工失能、急停、保活超时 | 撤权、尽力失能并锁存，不自动恢复使能待机 |
| 真实故障、反馈过期或通信异常 | 安全锁存，不能通过新的`on`绕过 |

停止、失能、急停不因无授权而拒绝。非会话轴的停止在活动会话内按整组急停处理，避免忽略安全请求。

CLI会话自身的人工/K5/保活超时锁存可通过新的`servo debug on left`显式申请恢复，但必须先确认选中轴均失能完成、零速、无故障及全部启动门禁。新会话号变化，不恢复旧目标。`servo clear`不能替代CLI会话的显式重新申请。此规则不适用于遥控K5人工锁存：遥控保持完成后须新的K5长按恢复，不能创建CLI会话解除它。

参数核验、设零、保存仅允许当前会话轴，并继续受原有维护及失能门禁约束；本轮不提供全局`servo maintenance on`绕过会话。

## 6. 正常退出

`servo debug off`异步取消请求，进入`stopping`；5000ms内必须取得两次新零速反馈、新鲜无故障反馈及失能确认，失败进入不可绕过锁存。

统一使能待机适用时，继续进入`restoring`，恢复目标轴RS485速度模式、速度0、使能及反馈核验，成功后才变为`idle`并释放控制权。另一轴保持零速使能待机。2026-10-08起，适用范围包含上电、按键、软件和看门狗复位成功后的待机。

待机开关关闭或待机不适用时，正常退出后保持失能。退出和恢复期间拒绝新运动；查询正常。恢复失败不能自动重新使能。

CLI退出后，恢复遥控必须摇杆回中并产生新的K5长按。原32字节无线协议不变，CLI显示现有速度、位置、脉冲、停车或锁存状态，不冒充遥控授权或上电待机；未取得CLI确认命令值的无线字段使用协议无效值，遥控端应显示`--`。

位置与轮转里程继续采集；CLI授权不会建立遥控双轴相对位置差基准。

## 8. K5运行期保持诊断补充

2026-10-09起，正常遥控K5受控停车成功后保持原零速使能，不再以底层真实故障锁存表达正常人工停车。CLI期间K5仍执行原失能锁存，不采用该保持流程。

`remote servo status`新增`k1_hold`行，显示阶段、有效性、选中/确认/使能/零速掩码、扰动和失败原因。`valid=1`不等于授权，只有同时`zero=mask`才是当前零速保持；扰动时仍保持使能但不可授权。

详细字段、无线显示和实物验收表见`Docs/K1停车零速使能保持与验收说明.md`。
