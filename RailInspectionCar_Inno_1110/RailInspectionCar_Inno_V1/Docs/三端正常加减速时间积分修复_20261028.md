# 三端正常加减速时间积分修复 — 实施与现场验收

## 已实现

正常斜坡按健康控制服务的实际时间推进，不再按双轴事务完成次数推进。HMI、遥控、CAN在等待上一批应答期间只推进内部浮点状态；已锁存批次继续按原逐轴应答关联规则提交。相同目标保活不重置积分，新目标重建时间边界。每次服务最多计入50ms，超出的真实服务停顿直接丢弃并记录，不积压追赶。

软件加速度仍为0.15m/s²、正常减速度仍为0.30m/s²。驱动器参数、协议、仲裁、分级停车、急停与失联停车门限未修改；换向进入原过零路径前丢弃尚未发送的正常斜坡进度。通信降级或写入被限幅时按受限命令重新建立基准。

新增`ramp status`，仅访问缓存，一次输出小于1024字节，不增加驱动器轮询、不启动周期日志。输出owner、source_authorized、phase、目标/内部积分/锁存批次、已成功命令及时间、反馈及采样时间、参数回读与掩码，以及当前会话的service_max、clipped、dropped、integrated、batches、batch_max。phase是对应控制源的原状态枚举，不是跨源统一编码。service_max等单位为ms；batches是完成的速度批次数，包含首零事务；停车不使用正常积分统计。正常事务可能由多个Modbus请求组成，不能将batch_max当成单帧响应超时。

完整status中的`control owner`现在区分hmi、remote、can；`cli_authorized`明确指维护CLI，不能据此判断HMI授权。position=waiting作为独立问题保留。

## 复现和验证证据

- `before_timing.log`：生产控制器旧实现，异步串行应答模型，约120ms双轴批次。HMI 0→1000rpm为58213ms、0→1600rpm为93133ms，复现与现场相近的慢斜坡。仅能证明软件缺陷；现场批次耗时仍以UART记录为准。
- `timing_final.log`及`host_complete.log`：三端×左/右/双轴×同步开/关×6个正负目标×4种延迟/抖动×正常加/减速，共864个计时样本。固定延迟30/60/100ms逐轴串行，双轴批次约60/120/200ms；另覆盖30/100ms交替抖动。以最后一轴应答到目标计时，容差max(500ms,两批周期)。覆盖活动事务不变、整数斜率误差、目标保活、120ms真实服务停顿只计入50ms且不追赶。
- 120ms模型的正向加速：HMI 500/1000/1600为12.254/24.374/38.894s；遥控为12.250/24.370/38.890s；CAN因mm/s转换量化为499/999/1599rpm，耗时12.260/24.380/38.900s。
- 同模型1000rpm正常回零：HMI 12.248s；遥控12.250s；CAN 999rpm回零12.250s。以上均为模拟命令时间，不是实测伺服速度或急停时间。
- `driver_delayed.log`：真实AIMtor驱动+真实Modbus生产代码，25ms延迟回包（低于原50ms超时），等待期间模拟控制任务继续服务，背景轮询保持启用；6种轴/待机配置×6个目标。双轴最长批次448ms，正常积分service_max=3ms、clipped=0、dropped=0，1000rpm最终应答约24.984s，偏差在两个实际批次周期内。此处不能强行按500ms绝对误差验收。
- `safety_final.log`、`guards_final.log`：安全停车6配置和生产门禁；`snapshot_final.log`、`transport_final.log`：统一快照/传输；`rxlost_final.log`：遥控端兼容与通信恢复；`node_final.log`：当前25号屏全部282个Node测试通过，屏端未修改。
- 数学测试补充Tick回绕、截断统计和无积压。异步故障覆盖HMI写失败撤会话、遥控K5抢占后迟到应答不恢复授权、CAN写失败后拒绝旧目标。既有回归覆盖首零/人工授权/急停/跨源K5/快速STOP/ER.994/降级/USART1完整输出。

`source_*_phase_*.csv`和`simulation_curves.svg`为模拟命令曲线。CSV中的sim_actual为测试桩跟随值，绝不可作为实物速度证明。
