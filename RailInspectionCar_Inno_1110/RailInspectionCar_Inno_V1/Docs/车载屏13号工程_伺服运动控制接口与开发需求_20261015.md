### 2.1 运行链路

~~~text
屏端Modbus主站
 → UART5 RX中断 → 带到达时间的接收事件环
 → HMI任务（2ms）→ 帧/CRC/03H或10H校验
    ├─03H：只复制已有快照，不发起伺服控制
    └─10H：完整邮箱提交，UART5返回接收回执
 → 伺服通信任务（1ms）
    → 仲裁 → 驱动/RS485服务
    → 遥控 → CLI → HMI控制 → CAN控制
 → 斜坡/逐轴事务 → USART2 RS485 → 驱动器
 → 真实反馈 → 100ms快照 → UART5回传屏端
~~~

服务执行顺序不等于“遥控优先”。授权以仲裁队列成功预约顺序为准，先取得owner者控制。同一调度时刻并发，以主控实际串行提交顺序裁决，不定义一个可抢占的优先级。

## 3. 控制权与停车统一规则

### 3.1 运动授权与停车责任分离

1. 授权成功前不运动，申请成功也不自动执行历史非零目标。
2. owner占用时其他来源申请立即拒绝，不预排队等待释放后自动接管。
3. 取消、急停、失联、目标超时：立即撤销接受非零目标的运动授权，清空旧速度待发项。
4. 停车期间原owner保留“停车责任占用”，阻止其他来源启动；不代表原owner仍可调速。
5. 所有参与轴真实反馈确认停稳、零速使能确认后，清会话，owner=NONE。
6. 此后任意来源须发起新的主动授权；不自动恢复旧目标、旧会话或旧排队申请。

严禁“先释放owner再停车”，防止另一接口在减速中启动。

|---|---:|---:|

### 3.3 事件矩阵（13号目标）

| 事件 | 减速度 | 减速中调速 | 停稳后owner | 停稳后使能 |
|---|---:|---|---|---|
| 正常滑块减速/回0 | 正常调速，目前0.30m/s² | 有效 | 保持 | 保持 |
| 再按授权取消 | 0.4m/s² | 无效且不缓存 | NONE | 零速使能 |
| 屏软件急停 | 0.5m/s² | 无效且不缓存 | NONE | 零速使能 |
| 屏掉电/UART5断线/会话超时 | 0.4m/s² | 无效 | NONE | 零速使能 |
| 目标刷新超时，即使心跳正常 | 0.4m/s² | 无效 | NONE | 零速使能 |
| 0.4释放减速中再按急停 | 升级0.5m/s² | 无效 | NONE | 零速使能 |
| 新跨源软件急停 | 统一快速停车0.5m/s² | 所有来源无效 | NONE | 健康时保持 |
| 驱动故障/RS485失联/停车失败 | 尽力停车并报告失败 | 无效 | 不可新授权 | 不能保证 |

“安全急停”按钮实际是**通信型受控软件停车，不是STO、物理急停或安全认证功能**。断主控电、断驱动电、驱动故障或RS485完全断开时，软件不能保证指定减速度和零速使能。不能把无反馈当停稳；本文不另设计硬件安全系统。

### 3.4 非owner接口与跨源急停

HMI控制时，遥控未开机/无线失联/CAN未接入不得撤销HMI；遥控控制时屏掉电不得影响遥控。只监控当前运动授权源的通信时效，真实驱动故障和新急停事件除外。

**急停不等于抢占：新急停可要求当前owner停车，但不给急停来源运动权。** 主控应把新急停交给当前owner停车服务，不并行启动另一套速度写入。遥控旧estop_latched与未参与无线旧离线状态不能永久封锁屏授权；只清理成功停稳的普通软件急停历史，不自动清真实故障。

### 4.3 滑块与授权行为

- 进入页面初始0，未授权不发速度；不持久保存旧非零目标。
- 控件若只支持非负范围，用0～3200，rpm=控件值-1600；中点1600，显示仍为有符号rpm。
- 授权成功先保持0；只有授权后的新用户滑动才开始非零目标，授权前残留值不自动执行。
- 值保持不变也须周期刷新新序号目标；不能只在触摸变化事件发一次。
- 正负切换交主控过零处理，屏端不直接写方向。
- 取消/急停开始后滑动无效，不发送、不缓存；触发时位置可暂留，主控目标立即读回0。
- 主控确认停车成功后回中一次。程序回中事件必须与真实用户滑动区分，不触发新运动。
- 失联立即作废滑动；可本地显示0，但同时标“停车未确认”，本地回中不代表机械停稳。
- 他源占用时只读，不能积存待授权目标或在对方释放后暗中重试。

### 4.4 不设屏端急停锁

成功停稳释放后按钮回未授权，用户再次点授权即可申请。不增加“解除急停”“解锁”“长按确认”“时基资格”等步骤，不复制其他版本的专用普通急停锁6。

## 5. 当前已实现的UART5线协议

### 5.1 传输约定

| 参数 | 约定 |
|---|---|
| 主从 | 屏为Modbus RTU主站，底盘UART5为从站 |
| 串口 | 115200bit/s，8数据位，无校验，1停止位 |
| 地址 | 1，非本站/广播不作为控制入口 |
| MCU引脚 | PC12=UART5_TX，PD2=UART5_RX；当前TTL直连接线及电气核对见19.1，不假定接线已经实测验证 |
| 功能码 | 03H读保持寄存器；10H一次写完整邮箱 |
| 寄存器字节序 | 每个16位字高字节先发 |
| CRC | 初值FFFF，多项式A001，CRC低字节先发 |
| 帧间隔 | 主控按1.75ms静默判帧；屏至少留2ms及调度裕量 |
| 读数量 | 1～125，不能跨读区白名单 |
| 写数量 | 0100H起一次24寄存器，整帧57字节 |
| 不支持 | 06H单写、04H读输入寄存器、拆分邮箱写 |

全部为零基协议地址；0100H=十进制256，不是十进制100。设计器若使用40001风格必须明确换算。**10H正常回执只证明邮箱已提交，不代表授权/运动成功。**

### 5.2 当前读区白名单

## 6. 13号邮箱契约：HMI13-R2（本轮实现）

### 6.1 版本与兼容

定义协议主版本1、字典修订2，简称HMI13-R2；本工作区已实现，须烧录对应构建固件才可使用。

- 原只读地址和单位不变，08仍可读六区。
- 新增0021H共同RPM命令，不重定义旧0020H的mm/s含义。
- R2邮箱axis_mask固定0，主控内部解析为编译期控制轴，屏端不覆盖选轴。
- 不兼容R1运动写入：字典1或旧0020H不能预约、不能执行；原03H只读继续保留。
- 0202H新增能力bit4=RPM目标、bit5=新控制状态、bit6=停车释放语义、bit7=主控隐式选轴。完整控制版保留低4位时为00FFH；屏端检查(能力 & 00F0H)==00F0H，不要求整体恰好FF。

### 6.4 跨源急停与授权不确定性

R2允许0010H的session=0表示“对当前控制源全局受控停车”，仍要求正确boot、完整格式、字典和新序号；无需运动授权。授权结果丢失时也可用它消除未知运动。

- HMI令牌匹配：本会话急停；HMI结果未知时session0也可请求停车。
- REMOTE/CLI/未来CAN为owner：统一停止代理通知原owner停车，原owner保留停车占用；屏不取得运动权，不建第二写入流。
- ownerNONE且所有参与轴确认零速使能：可直接成功，无授权副作用。
- ownerNONE但初始化/恢复未完成或运动状态未知：不伪造成功，沿用主控恢复/故障处理。
- RELEASE只取消本会话，不释放他源；他源下返回OWNER_BUSY或NO_SESSION。

**静态复核例外：以上ownerNONE的核验是目标契约，当前源码仍有未核验即返回成功的缺口，详见20.1；屏不能凭该回执确认停稳。跨源owner的最终完成应读持久停车事件，不能保证0120H结果槽持续更新，详见19.7与20.2。**

急停在通信可用时始终可请求，包括0.4停车期间升级。重复急停不重置停车总期限、不降低已有更强制动。本轮通过独立停止槽转发给当前owner；HMI、遥控和CLI各自执行原owner停车，不授予急停请求方运动权。

### 7.1 结果和业务错误

状态：0 NONE，1 ACCEPTED，2 RUNNING，3 SUCCEEDED，4 REJECTED，5 FAILED，6 EXPIRED。

|---:|---|---|
| 0 | NONE | 无错误 |

| 3 | NO_SESSION | 按钮回未授权 |
| 4 | SESSION_EXPIRED | 已撤权/停车，滑块无效 |
| 5 | OWNER_BUSY | 他源占用，申请失败，不自动重试 |
| 6 | SAFETY_DENIED | 显示主控具体不可运动原因，不增屏解锁 |

### 7.2 序号与幂等

- 当前最后接受序号属于一次主控启动全局，而非每个HMI会话；释放不重置。
- 仅当序号仍等于主控最后接受序号时，同序号同24字邮箱可幂等重发，不重执行，也不刷新目标时效/租期。当前不是历史结果缓存；一旦接受了更大序号，再重发旧包会返回OLD_SEQUENCE。
- 同序号异内容拒绝；周期刷新即使rpm一样也必须新序号。
- 拒绝请求未必推进当前主控最后接受序号；屏仍不复用已分配序号。
- 屏重启但主控未重启时，先读R2 last_accepted_seq，再从下一值开始，不能盲目从1。
- boot变化清旧会话、速度、待发包、结果缓存，重新读取序号；新boot下也不自动运动。
- 同boot不允许32位序号回绕；接近FFFFFFFF时停车维护，不回1。
- boot/seq/command匹配的结果才能完成当前操作，其他结果不改变按钮。

结果当前是单槽，心跳/速度会覆盖上一命令。关键申请/释放/急停串行确认；释放/急停开始后停止速度和普通心跳。新增持久停车事件避免迟到拒绝覆盖完成信息。

10H回执丢失或业务确认超时属于“执行结果未知”，不能直接认定申请失败后重发另一份新申请。先读结果和新状态；必要时完全相同邮箱幂等重发，或用新序号session0急停消除未知运动。明确拒绝后不自动重试申请，用户下一次主动按键才是新申请。

屏下一个序号取本地已分配最大值与主控last_accepted_seq较大者再加1，不因主控读回滞后倒退。拒绝结果不能把停车中的按钮恢复为有效授权。

|---:|---|---|
| 0 | IDLE | HMI未授权，全局可能他源占用 |
| 1 | ACQUIRING | 预约/准备中，不运动 |
| 2 | AUTHORIZED_ZERO | HMI有效授权且目标0 |
| 3 | ACTIVE | HMI有效授权且非零目标/输出/运动 |
| 4 | STOPPING | 已撤权，仍停车占用 |
| 5 | VERIFYING_ZERO_HOLD | 确认零速与使能 |
| 6 | FAULT | 停车/驱动条件失败 |

停车完成回IDLE，但事件字段保留结果，不能要求屏必须碰巧读到瞬态“已停”。

### 8.3 flags

bit0接口支持控制；bit1 HMI运动授权有效；bit2全局停车事件进行中；bit3所保留停车事件成功且零速/使能确认掩码一致；bit4反向过零等待；bit5/bit6当前实现均随HMI FAULT置位，不能独立用来区分故障类型；bit7当前编码固定置1，不代表所有反馈有效或通信新鲜；其余0。

授权自锁显示必须结合当前boot、已确认会话、owner=HMI、bit1及通信新鲜度；HMI停车时bit1=0、bit2=1，owner=HMI不表示可调速。bit3来自主控停车事件记录，不由屏计算，也不以斜坡输出归0提前设置。它可在下一次授权后继续为1，不能单凭bit3回中、弹起授权按钮或宣称当前车辆仍停稳，详见19.5。

### 8.4 停车原因/阶段与事件保留

原因：0无，1取消，2屏急停，3目标超时，4会话/链路超时，5新跨源急停，6驱动/反馈异常，7执行失败，8返回主页释放。

返回主页同样发0003H，没有返回原因载荷时主控统一记1；8仅供主控确实能区分时使用，不占保留参数偷偷编码。

阶段：0无，1减速，2等待新鲜零速样本，3确认零速使能，4完成，5失败。当前对非HMI owner进行中的停车统一发布阶段1，屏不能据此认为遥控/CLI已具备2/3阶段的细粒度显示。

下一停车事件前保留stop_event_seq/result/completed_ms，不因读请求/普通心跳清空。急停升级更新请求关联，保留原事件编号和起始期限；被升级的RELEASE也可通过该同一停车事件结算。跨源事件完成标识必须来自当前停车责任模块，不由HMI仅读几次速度自行推断。

结算停车匹配当前boot、本次新stop_event_seq和请求序号/命令，不把上次保留的成功当本次完成。若其他源在释放后迅速授权，可凭匹配事件确认自己的释放成功，同时显示新owner，不要求必须碰巧读到短暂ownerNONE。

## 9. 超时、停车和反馈确认

### 9.1 时间参数

| 项目 | 目标契约 |
|---|---|
| 目标发送 | 推荐100ms；按真实UART发送时刻，正常负载最大间隔目标≤200ms |
| 目标有效期 | 500ms，须有新序号目标 |
| 会话租期 | 1000ms，合法新目标/新心跳续租 |
| 新状态读取 | 控制期间100ms，正常负载最差≤200ms |
| 接收事务超时 | 08的50ms为初值；实测调优但不侵占速度刷新预算 |
| 授权准备期限 | 沿用当前2000ms上限 |
| 轴反馈新鲜 | 速度和故障年龄均小于500ms |
| 停车总期限 | 最大可信速度/减速度，再加≥2000ms反馈及使能裕量 |

本轮记录每条0111H有效期（1～500ms），从请求接收时间计时，13号固定发500避免歧义。授权完成后首目标同样500ms；普通读和重复帧不刷新。

目标超时后迟到目标/HEARTBEAT不能取消停车。500ms开始的停车已必须是“停稳释放”；1000ms租期到期不能因stop_requested已置位而漏掉释放升级。

### 9.2 停车顺序

1. 识别事件后撤销非零目标资格，清旧目标缓存和未提交批次。
2. 保留停车轴掩码和内部停车写能力，使用aimtor_set_stop_velocity_rpm()，仅允许绝对速度不增加、不换向。
3. 初值考虑反馈、已提交输出、未完成写可能达到的最大绝对速度，不只看滑块。
4. RELEASE/失联用0.4，ESTOP用0.5；正常调速仍用正常参数，不靠全局改成0.5替代分类。
5. 升级急停只加强制动，不重新增速、不重置起始时间、不放宽原停车期限。
6. 各轴最后零速写入完成后，至少收到两份不同采样序号的新鲜实际0反馈；重复读同快照不累计。
7. 所有编译参与轴在线、无故障、非忙、实际0，使能反馈有效且为1；软件enabled不能冒充反馈。
8. 全部达标后才清会话、释放owner、发布成功；双轴一轴停不算成功，未参与轴离线不阻塞。
9. 写入失败、反馈过期或期限到期发布FAILED，走真实故障处理，绝不假报成功。

不能屏端自行采用“±5rpm就算0”。若真实驱动噪声需阈值，应由主控定义、同步契约和测试，不能另设屏端判停标准。

### 9.3 正常过零与取消不同

正转目标切负转：主控先0并确认再反向，保留授权。正常滑块回0也保留owner；只有取消/急停/异常撤权释放后别源才能接管。不能混淆“正常0目标”和“取消授权停车”。


## 10. 屏端状态机与通信调度

### 10.1 页面状态机

| 状态 | 入口动作 | 可用操作 | 退出条件 |
|---|---|---|---|
| 未连接/身份待更新 | 本地无授权、速度无效 | 返回、只读等待 | 当前身份/状态有效 |
| 未授权 | 目标0、按钮弹起 | 授权、急停、返回 | 申请/停车 |
| 申请中 | 一次ACQUIRE，等待业务结果 | 急停；返回须取消未决申请或全局停车 | 成功新会话或拒绝 |
| 已授权 | 立即周期目标0，接收新滑动 | 滑块、取消、急停、返回 | 撤权/失联/停车 |
| 释放/急停停车中 | 清旧速度队列，按钮不显示有效授权 | 急停升级、只读；返回记为待执行 | 主控停车成功或失败 |
| 停车成功 | 回中一次、清会话 | 再授权、返回 | 下一动作 |
| 通信中断/停车未知 | 不续租旧运动、不重发旧目标 | 只读主页、重连查看 | 重连真实状态，不自动授权 |

申请失败按钮弹起，提示“遥控占用/CLI占用/主控尚未就绪”等；不要求屏端额外解锁。按钮连点去重，不提交多份并行申请。

### 10.2 返回主页

- 未授权且无未决申请：直接返回。
- 已授权：等价取消，0.4停车确认释放后返回。
- 停车中：记返回请求，成功后返回；急停仍可升级。
- 申请未决：取消待申请或session0急停，确认无幽灵占用后返回，不能销毁状态机后不管。
- 已断线：允许回只读主页，标“停车未确认”；重连继续查主控，不恢复旧非零目标。

通信、计龄、停车跟踪全局运行，不依赖P8可见。也不能离开页面后继续后台续租旧运动授权。

### 10.3 单一事务调度

08号六条只读：0000/64、0050/32、0070/32、0090/32、00B0/32各200ms，0200/24为1000ms。**不能让旧自动轮询与滑块事件裸串口写并行竞争。**

13号使用唯一发送入口、同时一个在途事务。将自动轮询并入调度，或确认厂商组件能统一串行03H/10H；不得留第二个无约束发送者。优先级：

1. 新急停/停车升级。
2. 取消授权/返回释放。
3. 关键命令业务确认及停车状态读取。
4. 到期目标刷新，必要时暂停普通读。
5. 新控制状态、身份、基础状态。
6. 低优先只读诊断。

滑动只更新一个“最新共同目标”，不按像素变化排队。停车删除旧速度待发项；已在发的帧完整收尾，不剪半帧，下一事务停车。主控必须防迟到旧包。

关键申请/释放/急停结果可50ms轮询；100ms目标不阻塞等待实际达速。速度ACCEPTED后继续调度，以新状态验证目标/输出/反馈。

### 10.4 推荐轮询与预算

| 区域 | 未控制 | HMI控制/停车 |
|---|---:|---:|
| 0460H新状态64字 | 200ms | 100ms |
| 0120H结果20字 | 关键命令时读 | 关键动作50ms；普通目标可由新块关联 |
| 0200H元数据24字 | 1000ms | 200～500ms，可用新块身份维护关联 |
| 0000H基础64字 | 200ms | 200～500ms |
| 其他四个32字区 | 200～1000ms，按页面 | 500～1000ms，低优先 |

线速参考：57字节目标帧约4.95ms，8字节ACK约0.69ms；64字读取请求8+响应133字节约12.24ms，另加静默和响应调度。理论可满足200ms预算，但不是Visual-PIX吞吐实测。

必须核对实际定时器属性及UART5抓帧：不能未经核实把interval=5说成5ms，不能把理想10ms模型当实际50ms周期。开发时验收调度，不增加让用户等5秒“时基资格”的人机门禁。

### 10.5 厂商API边界

08可追溯入口是mod.modbusBufferCheckStatus()、interruptCode、bcaddr/bdaddr/bdcount/bdindex/bdbuf及bytesToShort(...,1)。其“Modbus中断只读解析.txt”只处理六区读取，未处理10H回执和控制结果。

下一阶段使用安装版Visual-PIX与本地官方指南确认真实10H多寄存器写或原始RTU接口，不编造未经核实的mod.writeRegisters()等API，不用本地数组改值冒充真实发帧成功。

CRC错、短响应、截断必须实通信验收。bdcount可能表示配置数量，仅比较数量不足以证明底层已拒绝短载荷；08已有风险核查，13不能继承“必然拒收”的未经验证假设。

## 11. ±1600rpm与全局运行限速（已冻结）

当前轮径0.185m、减速机3:1、大链轮18齿、小链轮16齿，总传动比3×16/18≈2.6666667。

~~~text
轮周长 C = π × 0.185 m
车辆速度 v(m/s) = motor_rpm × C / (60 × 2.6666667)
电机变化率 rpm/s = 加速度(m/s²) × 60 × 2.6666667 / C
~~~

- 换算约275.295rpm/(m/s)，0.4m/s²约110.118rpm/s，0.5约137.648rpm/s。
- 1600rpm约5.811946m/s，即20.923007km/h。
- 本轮APP_OPERATION_MAX_MOTOR_RPM固定1600，APP_OPERATION_MAX_VELOCITY_MM_S按精确周长和当前传动比向下取整为5811；实际反馈换算四舍五入可能显示5812mm/s。
- 全局运行和驱动绝对保护共同以±1600rpm为界，P同步补偿也不得突破该边界。
- 1600rpm理想停车0.4约14.53s、0.5约11.62s，另加确认时间，不能固定2秒超时。

**界面制作±1600，不允许屏擅自放大主控上限，也不允许1600悄悄钳成1531却仍显示接受1600。**

用户已确认完整支持±1600rpm，并同步提高统一运行上限；不再同时承诺20km/h硬限速。主控接受的是电机rpm，屏端不自行换算或截断。

主控effective_min/max发布−1600/+1600；±1601返回OUT_OF_RANGE并保持上一次已接受目标。边界已做自动化/模拟验证，高速实物尚未验收，须单独分阶段记录。

## 13. 端到端时序

### 13.1 授权调速

1. 全局通信读取身份、R2、owner、新状态，本地目标0。
2. 点授权，发送ACQUIRE：当前boot、session0、axis0、新seq。
3. 主控校验后预约HMI，按编译模式准备，期间他源不可取得运动权。
4. 屏收到10H回执后查业务结果：SUCCEEDED、新会话非0、ownerHMI才确认授权；允许100ms快照滞后，不靠本地自锁认定。
5. 立即100ms周期发新序号目标0；新滑动后发送最新共同目标。
6. 主控斜坡执行，屏分别显示目标、输出、真实反馈；ACCEPTED不等于达速。

### 13.2 取消

1. 再点授权，屏使滑动无效、清旧速度，发RELEASE。
2. 主控立即撤运动授权、目标0、停车owner保留，0.4减速。
3. 他源申请均拒绝占用，不预排队自动接管。
4. 所有参与轴确认实际0且零速使能后：成功、ownerNONE、session0。
5. 屏回中、按钮弹起；此后各源可重新主动授权。

### 13.3 急停/升级

1. 急停立即0010H，无二次确认；清旧速度队列。
2. 0.4释放中升级0.5，保持原停车事件和期限。
3. 成功释放后回0，无解除屏锁步骤。
4. 他源控制时session0请求，由原owner停车，屏不取得运动权。

### 13.4 失联恢复

1. 500ms无有效新目标，主控0.4停车释放，读请求/心跳不代替目标。
2. 屏掉电由主控期限检测，不依赖页面退出事件。
3. 迟到旧速度不复活，重复停机不延长期限。
4. 重连先读boot/last_seq/owner，清旧会话，不自动授权/恢复滑块。
5. 主控仍停车则显示停车；正常释放后用户可重新授权。

- 普通撤权由原owner保留停车责任；真实故障入口使generation失效并发布失败，不伪造零速使能成功。
- 通信源掉线且驱动健康时用受控停车，不直接用会失能的aimtor_emergency_stop()冒充“0.4后零速使能”。
- 新控制状态快照应采用原子复制/稳定版本校验等既有风格，避免跨任务拼接出相互矛盾的session/owner/授权。

## 17.1 本轮主控实施结果补充

本节用于区分“底盘主控软件已经完成的实现”与“车载屏/实物尚未完成的联合验收”，不能将下面的主机测试结果替代13号屏工程开发和车辆运动证据。

### 17.1.1 已落地主控能力

- **HMI13-R2控制入口**：UART5保留原Modbus RTU从站和03H只读访问；R2使用0100H起24字完整邮箱，0021H表示共同目标电机转速，axis固定为0，字典修订为2。R1运动写入和旧0020H速度写入不进入运动执行。
- **共同目标与编译选轴**：屏端和遥控端均只提交一个共同目标rpm；主控依据`APP_SERVO_CONTROL_AXIS`选择左轴、右轴或双轴，屏端不发送左右轴速度、不提供轴选择控件。
- **控制权仲裁**：新增统一控制权和停车责任管理。空闲时主动申请按主控实际串行受理顺序先到先得；已占用、授权准备中、减速停车中和零速确认期间，其他来源不能抢占，也不会缓存为后续候补。
- **授权准备**：授权申请通过完整校验后进入准备阶段，主控按编译选轴完成速度模式、使能和反馈确认；准备未完成前不会显示真实运动授权，准备过程中取消/急停不会留下幽灵会话。
- **共同斜坡与双轴同步**：共同目标先经过正常加速度/减速度斜坡，再使用独立的双轴P同步状态实例生成逐轴执行输出；同步补偿受统一±1600rpm边界约束，不消费遥控器运行状态。
- **事务完成跟踪**：伺服写入返回`SERVO_OK`只代表事务提交；主控继续跟踪写序号、完成序号和完成结果。写入长期未完成、反馈无效、使能反馈无效或停车失败时，发布失败结果并进入真实安全处置。
- **撤权和停车**：释放/返回主页按400mm/s²受控减速，目标/会话超时和本源失联按400mm/s²处理，软件急停按500mm/s²处理。停车过程中滑块目标无效，急停可以升级已有较弱制动但不重置停车期限。
- **零速确认与释放**：停车成功必须满足参与轴零速写事务完成、每轴取得至少两份不同采样序号的新鲜零速反馈、反馈有效且无故障、驱动在线非忙、使能反馈有效并为1；全部满足后才清除会话并释放控制权。
- **跨源隔离**：HMI占用时遥控普通按键、历史锁存和无线离线不产生另一套伺服写入；遥控占用时HMI掉线不影响遥控；跨源急停只请求当前owner停车，不把运动权转给急停来源。
- **状态与诊断**：状态区扩展为0460H起64字至049FH，发布共同目标、逐轴目标/输出/真实反馈、实际有效性、使能确认、零速确认、停车事件、原因、阶段、期限、结果和错误。CLI增加只读命令`hmi status`，不产生授权副作用。

| 项目 | 当前对接要求 |

| 屏端端口 | 核实所用的是本次配置的业务串口，不是其他COM口、下载口或调试打印口 |
| 链路独立 | UART5接屏；USART2/RS485接伺服驱动器。两条独立链路不能因都使用地址1而混为一条总线 |
| 屏访问地址 | 屏只访问UART5从站1；屏上的轴1/轴2不是让屏轮询UART5从站1/2 |
| 调试设备 | 接入USB串口主站测试时停用或断开屏的主动发送，避免两个主站同时驱动主控RX |

本工程UART5代码使用中断收发，未在HMI通道实现软件DE/RE切换。当前TTL直连不需要因使用Modbus额外配置485方向控制；将来改用转换器时另行核验其电气、方向和收发时序，不把未来接线方案当作今天的已验证接线。

### 19.2 最小无运动通信闭环：先证明能读，再接控制

主控持续更新状态快照，**不主动向屏推送业务帧**。只有屏正确发送03H请求，主控才返回数据；未授权、滑块为0、遥控器未开机，不是停止只读轮询的理由。

现场先暂停运动写入和多区自动轮询，仅保留一个主站，逐步验证以下请求。CRC按本工程`hmi_modbus_crc16()`同算法重新核对；以下只读请求无授权副作用。

| 步骤 | 请求帧（十六进制） | 期望与用途 |
|---|---|---|
| 1 | `01 03 02 00 00 04 45 B1` | 读0200H起4字，正常响应13字节，前缀`01 03 08 52 49 00 01`；当前字典随后为能力字、0002H |
| 2 | `01 03 00 00 00 40 44 3A` | 读旧基础64字，正常响应133字节，前缀`01 03 80`；确认原页面读取通路 |
| 3 | `01 03 04 60 00 04 45 27` | 读R2头4字，正常响应13字节，前缀`01 03 08 53 4D 00 02`，随后boot高字/低字 |
| 4 | `01 03 04 60 00 40 45 14` | 读完整R2状态64字，正常响应133字节，byte_count=80H；确认屏接收缓存能容纳整帧 |
| 5 | `01 03 01 20 00 14 45 F3` | 读结果20字，正常响应45字节；尚无命令时结果槽可以全0，不能因此判串口断线 |

步骤1成功、步骤4失败时，优先检查R2固件、白名单、133字节响应处理和缓存长度，不直接认定接线全错。步骤2成功但轴反馈无效时，应继续检查USART2驱动通信、编译参与轴及反馈年龄，而不是重新申请HMI授权来“解锁数据”。步骤1都没有响应时，优先检查物理层、端口、波特率、主从、地址、CRC和帧间隔。

每一步保存TX/RX原始十六进制及时间戳。屏幕截图只能证明显示现象，不能证明主控是否收到请求或返回了正确数据。

### 19.3 响应匹配、静默间隔与迟到帧

1. 每个在途事务保存端口、从站、功能码、起始地址、数量、发送结束时间和期望长度；收到完整且CRC正确的响应后才更新业务缓存。若厂商组件代办底层校验，必须以已核验的组件行为为依据，不再凭`bdcount`等配置值猜测帧完整。
2. 03H正常响应**不携带起始地址**，不能从响应字节中寻找0460H再分发；必须依据唯一在途请求的地址与数量分发。对于相同字数的旧区响应，更不能只看byte_count就猜来源。
3. 03H正常响应长度为`5 + 2×数量`；10H正常回执固定8字节，校验回显起始0100H和数量0018H；异常响应固定5字节，功能码为83H/90H等。异常帧不得落入03H数值解析。
4. 不以字符串结束符解析二进制，不丢弃数据中的00H；不添加CR/LF、ASCII空格、文本前缀或屏下载协议包头。十六进制示例中的空格仅供阅读，不上线路。
5. 一个RTU请求必须连续发送。当前主控以≥1.75ms静默作为收帧边界，屏不能把57字节邮箱按若干寄存器分别发送并在中间停顿。事务完成后再留至少2ms及调度裕量进入下一请求；即使TTL全双工，也不允许流水并发多笔请求。
6. 事务超时后不可立刻把迟到响应算到下一笔相同长度的03H请求。调度器应进入有界排空/静默隔离，再选择重试同一读或推进下一读；厂商接口无法区分迟到帧时应明确记录限制。隔离和重试预算不能挤占目标刷新；预算不足时本地撤销调速，不无限等待。
7. 50ms仅是单笔响应超时的联调初值，不是授权总超时、停车总超时或已实测保证。正常响应、5字节异常、超时、CRC错分别统计；有正常异常响应说明链路有往返，不能一律显示“串口断开”。
8. 保持单一接收通路：厂商Modbus组件与裸串口处理不能同时消费同一响应。若自行发送完整RTU帧，就不能再由组件重复加地址、功能码或CRC。

### 19.4 上电、重连与序号恢复的确定顺序

建议屏启动流程固定为：清本地授权/非零设定/未发运动包 → 开全局只读调度 → 读0200H元数据 → 核对字典能力 → 整块读0460H状态 → 建立boot与last_accepted_seq → 等待用户主动操作。

- 元数据应满足magic=5249H、主版本1、字典2；控制能力检查高4位00F0H，不把只读固件或不支持R2的固件变成“所有旧页面不可用”。
- 新块应满足magic=534DH、revision=2、参与轴1/2/3。元数据与新块的boot不同，可能跨越了复位或不同发布时刻，重新读取，不拼接成同一会话。
- 快照可能每100ms才发布一次，同一序号重复读取不等于通信断开，也不是新驱动采样。需要同时维护“最近有效响应接收时刻”和“最近一次snapshot_seq确实前进的本地时刻”。
- boot是身份值，按U32比较，不根据高低大小推断时间。FFFFFFFFH表示身份异常时保留只读诊断，禁止构造运动邮箱；这属于协议有效性，不增加用户解锁流程。
- 新命令序号取`max(本地已分配序号, 主控最后接受序号)+1`，按U32无符号规则处理，不能因脚本有符号整数把80000000H解释成负数而倒退。
- 两份数据分次读取可能相差一个发布周期，不能要求结果即时更新与周期快照始终同时变化；但也不能无限以“快照滞后”解释授权不一致。
- 屏重启发现主控仍有HMI会话时，不凭读出的令牌自动接管旧运动；停止旧目标续发，跟踪其超时停车，必要时发送新序号session0软件停车，确认后再接受新的用户授权。
- 屏自己的本地计龄用单调时钟，不直接用“屏当前毫秒−主控uptime”计算年龄。主控U32毫秒时间差按无符号差处理，计时回绕不等于boot变化。

### 19.5 显示值、运动状态与历史停车事件必须分开

| 显示内容 | 读取依据 | 禁止推断 |
|---|---|---|
| 屏与主控通信 | 屏最近一次合法响应及事务统计 | 不由任一伺服在线、owner或授权位代替 |
| 快照更新状态 | 当前boot及snapshot_seq前进情况 | UART5有回复不代表状态发布任务仍在更新 |
| 轴参与 | 0469H掩码；旧接口可参照配置说明 | 未参与不显示“故障离线”，不补0假装正常 |
| 轴实际rpm | 0477H/0478H、0479H与048EH/048FH | 不用滑块、目标、输出或上次缓存冒充实际转速 |
| HMI共同目标 | 0472H | 他源占用的7FFFH不表示32767rpm，也不表示0 |
| HMI最终目标 | 0473H/0474H | 非HMI owner时不能拿遥控目标填入该字段 |
| HMI执行输出 | 0475H/0476H与0499H，并结合当前owner/会话 | 当前未导出逐轴写完成序号，不能标成“驱动已执行/实际达速” |
| 使能 | 047AH有效掩码与047BH状态掩码；旧区0029H/0033H依原规则 | 使能未知不等于失能，软件配置不等于独立STO/SON实体反馈 |
| HMI有效授权 | 当前确认的boot/session、owner=1、flags.bit1、有效响应与快照计龄 | owner=1或会话非0不能单独证明可调速 |
| 当前正在停车 | flags.bit2、当前停车事件result=2及owner | 不能只看047FH非0或stop_phase=4 |
| 某一次停车已完成 | 同boot、事件编号及请求关联、stop_result=3 | 不能把上次成功事件当作本次完成或当前仍停稳 |

S16解码先检查7FFFH，再做补码转换；例如F9C0H为-1600，不是63936。S32哨兵7FFFFFFFH不得当作有效位置或里程。FFFFH只在字典明确指定的状态/年龄字段表示未知，不能全局把FFFFH都当未知：S16的FFFFH在允许范围内可能是-1。

特别注意以下当前实现事实：

1. `flags.bit7`目前固定置1，不能替代0479H/047AH或屏的通信超时检查。
2. `flags.bit3`、047CH、停车原因、减速度和完成时刻均可能保留上一事件。下一次新授权甚至非零运行后，旧事件仍可显示成功；只能放入“上次停车结果”，不能持续触发滑块回中或清除新授权。
3. HMI执行输出记录在他源接管时也应由屏依据owner屏蔽，不能只见0499H置位就沿用旧HMI数值。
4. 新块实际反馈对编译参与轴持续有效，与HMI是否拥有控制权无关；他源运行时可显示真实rpm，但HMI目标应显示“不适用”。
5. bit5/bit6当前一起随HMI FAULT置位，不足以细分驱动离线、写失败或安全故障。显示具体原因要结合业务结果、旧故障字、有效位及CLI日志，不能编造主控未提供的详细子错误。

### 19.6 授权后首目标、定速刷新与关键命令的预算

- ACQUIRE确认使用匹配boot/seq/命令的SUCCEEDED结果及新会话；owner、bit1用新状态交叉核对。取得成功后尽快发目标0，首个零目标建议在100ms内发出；不能等待额外一轮低优先页面全刷新而耗尽500ms首目标期限。
- 正常控制每100ms发送一个新序号0021H，rpm不变、用户不触摸也发送。只有“授权后新的真实用户滑动”才修改共同设定；屏控件程序性初始化/回中、页面加载均不得改变非零设定。
- 快照中的`last_accepted_seq`是最后接受的任意HMI命令，不专属于速度。若期间发了心跳或停车，不能仅凭序号变大认定某目标已接受；还需结合当前会话、共同目标以及本地命令记录，必要时读结果区。
- 普通目标通常不必逐笔等待0120H，关键申请/释放/急停才串行确认。进行中的业务结果查询必须有截止时间和退避，不能以第10.3节优先级3为由无限抢占到期速度刷新。
- 推荐正常目标真实发送间隔≤200ms，500ms是主控撤权期限，不是屏端可贴边运行的调度周期。旧页面查询、日志输出、资源加载、动画和触摸连发均应计入最坏预算。
- 屏端建议在控制状态响应或快照前进连续500ms未获得有效更新时，立即使本地滑块无效、清待发运动包并进入“通信/状态未知”。这是新增的屏端实现要求与联调初值，不是声称屏程序目前已经具备；只读页可采用较宽的显示过期提示，但不能继续显示运动授权有效。
- 通信未知后不再续发缓存的非零目标或心跳。若串口仍可发送且boot可信，可请求session0停车；发送失败或回执丢失仍显示“停车未确认”，不推断机械已停。
- 页面重绘和切页不能创建第二个目标定时器。正常回0仍继续新序号零目标，保持授权；取消/急停开始后则停止普通目标和心跳，不能混为一类。

### 19.7 取消、急停升级与跨源停车的结算

1. 触发前记录当前boot、已有stop_event_seq、发出请求序号/命令及本地动作代次；动作开始即封闭本地调速、清未发目标，不能等到下轮快照才禁滑块。
2. HMI本会话RELEASE/STOP可跟踪0120H的RUNNING到最终结果；同时读0460H整块。10H ACK不表示已经撤权或停稳。
3. session0急停作用于REMOTE/CLI时，**当前0120H不保证随后被原owner更新为最终SUCCEEDED**。以新出现且关联本次请求的0490H～0497H停车事件为主要完成依据，不无限等待单槽结果变化。
4. 释放升级急停保持事件编号。请求关联可能改为急停序号，屏应把本地未完成RELEASE和后续ESTOP关联到同一事件；不能因RELEASE旧序号不再出现而永久卡在“释放中”。
5. 其它来源的更强或同强度停止也可能更新该事件关联。若发现请求关联无法唯一归属，应继续显示当前停车状态并保存日志，不凭历史bit3结算；必要时查询当前事件/owner和主控诊断，不造一个屏端已完成结果。
6. 同一事件成功只处理一次“回中/按钮复位/待返回导航”。下一次用户授权开始后，旧完成事件不得再次触发这些动作。建议以`boot + stop_event_seq + 本地动作代次`记录已处理结算，而非只记布尔“已停”。
7. 观察到匹配事件成功后，他源可能已经立即取得新owner。可以结清本次释放并显示新owner，不要求必须读到瞬时ownerNONE；反之，仅ownerNONE不能证明本次停车成功，真实故障也可能清owner。
8. 本页无授权且他源运行时“返回主页”不停车、不抢占；“安全急停”才请求跨源停车。授权准备中返回不能只取消本地尚未发送的副本：已上线路的申请须走session0停车和状态确认，参见第20节竞态边界。

### 19.8 原页面及诊断数据的兼容边界

保持原六区地址、单位和原有有效性解释，不将旧只读页面统一绑到“已取得HMI授权”条件。未授权、遥控占用、CLI调试均应继续读状态，按真实可用性显示。

- 原0022H/002CH是mm/s，新0477H/0478H才是电机rpm；机械减速比变化由主控换算，屏不再按旧3:1自行推导新状态单位。
- 模式0021H/002BH：0未知、1 RS485速度、2 RS485位置、3脉冲位置；使能0029H/0033H：0/1/FFFFH。轴在线、反馈有效、控制模式、使能必须独立显示，不能以“未授权”统一替换成“断开”。
- 故障码0只有在相应反馈有效时才表示无故障，FFFFH不能显示“无故障”。旧C4/C5是位图，先排除FFFFH再解释各位；不得以按位测试FFFFH得出速度/故障都有效。
- 位置与里程0070H～007FH保持原字典：位置计数、净位移mm、累计路径mm、分段路径mm不是同一个概念，结合007CH各有效位及来源检查。HMI取消/重新授权不自动要求清里程；主控复位、位置连续性丢失或基准变化按位置模块发布结果显示，屏不拼接旧boot累计值。
- 本工程已有的转矩、平均负载、相电流、母线电压采集及无线0x89回传，**目前未在`app_hmi_state.c`中映射为UART5 HMI寄存器**。原HMI“伺服诊断页面”兼容，不等于新增的四个无线诊断量自动可读。
- 无线帧类型0x89不是HMI寄存器0089H；当前0089H是同步相关右轴反馈年龄。屏若要显示上述四个新增诊断量，双方应另行冻结新增字典、单位、有效/陈旧位与测试，不能占用049AH～049FH保留字或直接访问驱动0BxxH寄存器。
- 当前未提供的实体DI3、STO、机械制动反馈和告警历史，不以其他软件状态冒充，显示“未提供/不适用”。

### 19.9 “未知/断开”的分层排障与证据包

在不申请运动的情况下执行两次`hmi status`，间隔若干秒，保存完整文本并比较增量；不要只截owner/session两行。

| 观测组合 | 优先排查方向与不能越界下结论的地方 |
|---|---|
| 屏TX有请求，主控rx_bytes不增 | 端口、TX→PD2路径、共地、电气匹配、UART5挂接；CLI检查armed/arm_fail/错误 |
| rx_bytes增，requests不增 | CRC、本站地址、帧间隔、短帧、截断或非法范围；结合crc/frame/partial/ignored，requests不是全部收到字节数 |
| exceptions增 | 主控已返回协议异常，查83H/90H及异常码，不等于无通信 |
| requests增，responses不增 | 检查tx_busy、tx_errors、发送恢复及tx callbacks；再抓PC12实波形/响应，不能只凭业务计数断定屏已收到 |
| responses增，屏仍显示断开 | 主控只证明正常响应TX完成，尚不证明屏RX收到；查PC12→屏RX路径、接收端口、缓存和在途请求分发 |
| 元数据/R2 magic正常，轴值未知 | UART5通信已建立，分开检查USART2驱动通信、参与轴、反馈有效和年龄 |
| 正常响应持续，但发布序号不前进 | 检查快照发布/任务及屏缓存更新；不要用重复响应续“反馈新鲜” |
| R2只读正常、10H ACK后授权失败 | 查0120H业务错误、owner、驱动模式及主控条件，不把业务拒绝归为串口接线故障 |

`hmi status`中的region=0～5依次对应旧基础、通信、位置同步、告警、外围、元数据；新R2状态、结果和邮箱目前归region=6“其它”，不是漏统计。响应统计在发送完成后更新，且快照每100ms发布；不能要求某一张快照的请求数与响应数即时完全相等。

## 20. 当前主控待闭环边界：不能靠屏端猜测弥补

本节由2026-10-15当前源码静态复核得出，**不是新一轮修复或实物测试结果**。原第14、17节的“已实现”只能按已有专项覆盖范围理解，不涵盖下列尚未证明的边界。本文不改线协议、不分配新寄存器，不为让屏适配而掩盖主控偏差。

### 20.1 无owner的session0急停可能过早报告成功

`app_hmi_control.c:process_request()`在CMD_STOP且session=0时调用`app_control_arbiter_submit_stop()`，未检查返回值；当ownerNONE时，当前仲裁函数不会创建停车事件，而结果选择分支可能直接发布SUCCEEDED。该路径没有在此处证明所有参与轴已完成初始化、实际零速且使能反馈有效，和第6.4节的完整目标契约存在缺口。

屏端处理：不能把这份SUCCEEDED当作机械停车证据，不结算一个根本未创建的新停车事件；继续显示“无控制源，停车状态需确认”，读取初始化/轴反馈。后续主控应明确提供“已核验空闲成功”或“未就绪/失败”结果，并补覆盖ownerNONE、恢复中、未知反馈和安全故障的测试。

### 20.2 全局停车事件关联与CLI非速度模式信息不完整

跨源停车由REMOTE/CLI执行，但0120H最终结果目前不是所有owner统一回写；第19.7节要求屏读持久事件。CLI位置/脉冲模式沿用旧停止与恢复路径，现有代码可将事件记为result=3、内部error=9；此事件error目前未单独映射到64字状态区，0484H是HMI最近业务错误，不能替代它。

屏端处理：CLI占用下统一使用“停车处理/已结束，减速度保证依模式”，不宣称该模式已满足0.5m/s²，也不将内部error=9伪装成屏已读出的细分结果；需要更细结果时，双方应先补主控快照/协议能力及测试，再实现准确提示。

此外，当前仲裁记录未导出独立停车轴掩码：CLI通常只停所选调试轴，而0469H表示编译参与轴。跨源CLI完成时不能机械套用“HMI所有编译轴零速位必须全齐”的结算公式，完整轴级停止证据应结合CLI路径确认。

### 20.3 授权准备取消后不能留下有效会话窗口

`prepare_service()`处理准备取消时会设置内部session后进入`begin_stop()`，需特别核查授权准备期间急停、驱动准备动作在途、代次改变与返回请求的组合。当前已有准备取消专项，但不等于任意并发时序下均已证明不会在后续`execute()`出现反馈/权限失败或留下占用。

后续主控补测应明确验证：取消请求到达准备各阶段时不发布可运动授权、不执行旧目标；在途动作得到清理；最终为可信停车释放或显式FAILED，不能只以“某次测试最终ownerNONE”代表所有时序通过。屏端仍应按真实结果显示，不添加密码或用户二次确认绕过此问题。

## D. R2通信与调度冻结

- 屏为唯一Modbus RTU主站，主控UART5为从站；屏端只访问从站1。
- 只配置一个Modbus组件和一个串行事务调度器，同时只能一笔事务在途。
- 允许的业务API为厂商安装版确认过的 `modbusRead`、`modbusWrites` 或其等价Buffer接口；不得混用裸串口发送、第二个自动轮询器或并发发送入口。
- 运动邮箱固定为 `0100H`起24字，使用 `10H`完整写入，完整请求57字节；`axis=0`，共同目标S32 rpm范围 `-1600～1600`，命令 `0001H/0003H/0010H/0021H` 分别申请、释放、急停和共同目标。
- 状态块固定读取 `0460H`起64字；元数据读取 `0200H`起24字；结果区读取 `0120H`起20字；辅助状态按本页需要读取 `0000H`起64字。
- 授权成功后必须在100ms内发新的0rpm目标；已授权时共同目标即使不变化也必须持续刷新，实际目标帧最大间隔不超过200ms。停车开始后停止普通目标刷新。
- `10H` ACK仅代表邮箱提交，不代表授权成功、不代表目标已经执行、不代表机械已经停稳。
- 0460H状态和结果区的字序严格按本文R2字典；邮箱/状态U32高字在前，结果区U32低字在前。
