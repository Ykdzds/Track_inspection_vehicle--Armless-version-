# 遥控器按键迁移与配套升级说明

更新日期：2026-10-17。

## 1. 正式映射

| 物理按键 | 功能 | 无线上传 |
| --- | --- | --- |
| K1～K4 | 空闲；不停车、不授权、不复位、不翻页 | 保留短按、长按、双击及DBG提示 |
| K5短按 | 原人工受控停车、锁存、零速使能保持 | 松手消抖后优先上传，不等待双击窗口 |
| K5长按 | 新运动授权或停车后的恢复授权 | 上传；沿用原安全门禁 |
| K5双击 | 无独立功能 | 扫描器不生成；连续短按分别停车 |
| K6短按 | 看门狗复位测试 | 上传；测试开关默认关闭 |
| K6长按/双击 | 无功能 | 保留上传；不触发复位 |
| K7短按 | 上一页，1到7循环 | 仅本地 |
| K8短按 | 下一页，7到1循环 | 仅本地 |
| K7/K8长按/双击 | 不翻页，仅DBG提示 | 不上传 |
| K9～K12 | 保持原行为 | 不变 |

K7/K8同时短按不翻页。纯本地事件不增加上传批次号；混合上传事件仍保留。七页顺序保持OVR、SRV、POS、SYN、DIA、VEL、DBG。

## 2. 参数与兼容

主控`APP/app_config.h`：

```c
#define APP_REMOTE_STOP_AUTH_KEY_INDEX (4U)
#define APP_REMOTE_WATCHDOG_KEY_INDEX (5U)
#define APP_REMOTE_SERVO_K5_STOP_DECEL_MPS2 (0.50f)
#define APP_WDG_TEST_K6_SHORT_ENABLED (0U)
```

正式调参只使用K5/K6新宏。旧`APP_REMOTE_SERVO_K1_STOP_DECEL_MPS2`及`APP_WDG_TEST_K2_SHORT_ENABLED`仍兼容外部定义：只定义旧名称时新名称采用旧值，只定义新名称时旧名称成为别名。同一参数的新旧名称同时由外部定义，即使值相等也编译报错。旧宏不会恢复旧物理按键功能。

正常加速0.15、正常减速0.30、失联停车0.40、K5停车0.50 m/s²保持不变；当前机械链路为3:1减速机加18:16链轮，总传动比8/3，车辆硬限速对应1529电机rpm。H06计算、看门狗独立恢复策略保持不变。H06及配置校验引用新K5宏。

`REMOTE_STOP_K1`、`servo_k1_hold_*`、`CLI_EXIT_K1`等内部标识和枚举数值保留，实际由物理K5触发。用户可见停车原因显示`k5`，保持诊断显示`k5_hold`，看门狗开关诊断显示`wdg_test_k6_enabled`。告警0x02及原锁存位数值不变，现说明为“K5人工停车锁存”。

## 3. 协议与安全边界

32字节控制帧、CRC、序号和物理键位不变：K1对应bit0，K5对应bit4（0x0010），K6对应bit5（0x0020），K7/K8分别对应bit6/bit7（0x0040/0x0080）。本地过滤仅使用0x00C0，不改写成旧按键位。

K5停车不改写正在发送的帧；在下一发送机会使用新事件批次优先发送，清除旧K5长按/双击，延期保留其他事件。累计计数回绕、重复包、恢复历史消费仍沿用原逻辑。

K5短按与长按同批到达优先停车，并消费长按；停车中长按作废。恢复必须摇杆回中并产生新的K5长按，还须反馈新鲜、实际零速、模式使能核验及原门禁通过。真实故障、反馈失效、通信异常、停车超时仍升级原急停/失能路径。

遥控K5重复停车规则（2026-10-17修复）：

- 减速、零速确认、保持确认期间的重复短按合并到当前停车，不新建停车事务、不延长原期限。
- 人工停车完成且底层保持有效时，任意多次短按均幂等消费，保持零速使能，不再次进入失能急停。保持有效但有轻微速度扰动时也不因重复短按失能，仍由底层补零与安全监测处理。
- 停车中长按、短长同批及无线恢复前的旧长按都不能作为停稳后的授权；必须停稳、摇杆回中后重新长按。扰动或未回中时的长按被消费，条件恢复后仍须新长按。
- 新授权继续经过统一仲裁和保持释放门禁，目标从零开始，更新控制代次，不恢复旧速度；不能抢占HMI、CLI或CAN。
- 故障、保持失败、反馈失效、停车超时和看门狗仍优先，不通过重新使能、清故障或配置模式绕过。该修复仅作用于遥控K5，不调整HMI/CAN跨源停止行为。

软件证据及待实物验收项见[本次验证记录](K5重复停车与恢复授权修复验证记录_20261017.md)。软件通过不代表现场故障已解决。

本功能是受控停车，不是STO或硬件断能急停。K6测试开启时仍优先撤销运动授权并退出CLI，再进入原看门狗测试流程；关闭时只消费事件，不改变控制。

## 5. 部署与现场验收

两端固件必须配套升级，升级期间禁止运行。无线协议没有版本协商，旧新固件混用会出现按键错位，不能依赖自动检测。

1. 支撑台零速验证K1～K4无功能，K7/K8循环、同时短按不翻页。
2. 支撑台验证K5短按锁存、停车中长按作废、回中后新长按授权。
3. 分别验证左单轴、右单轴、双轴；参数和映射必须相同。
4. 低速验证停车、失联、反馈异常和停车超时；不直接高速试车。
5. K6仅在明确开启测试、支撑台及受控环境执行。正式交付恢复默认0并重新构建下载。

本任务不修改GPIO、接线、协议版本、页面数量、机械参数或运动算法，不自动提交或推送Git。
