## 修复内容

1. 对合法 `0x0460..0x04BF` 读取，复制最新已发布系统源，并仅编码96寄存器；全量编码调用相同函数，字段、哨兵和单位转换保持一致。关键编码不修改告警状态、不查询伺服、不续租、不修改控制目标。
2. 完整缓存与关键缓存分别保存源时间及序号。关键刷新不能给旧完整缓存续鲜；后台50ms刷新以源采样时间为基准。先处理接收队列及半帧，再执行后台完整编码。
3. 源有效性仍为100ms，复制后再次复核；源真实过期仍拒绝。原子 `app_system_snapshot_read_with_meta()` 使读取判定和拒绝证据来自同一次采样，避免Health在失败后更新造成误记。
4. LCD的50ms期限从真正启用DMA发送前开始；最终超时判定重新采样错误、完成及SPI尾部状态。保留真实超时、缺中断、错误优先、DMA缓冲隔离与2/4/8/10秒恢复退避。
5. LCD任务栈896→960 words，额外256B从既有48KiB FreeRTOS堆分配。这不代表静态RW+ZI再增加256B；现场需要重新建立堆基线。

100ms源有效期、屏端300ms门禁、500ms目标TTL、1000ms租约、邮箱消费顺序及STOP规则均保持原值。

## 编译与诊断

宏 `APP_HMI_LINK_DIAG_ENABLED` 位于 `APP/app_config.h`，默认1。设为0关闭新增自动文本输出，功能修复仍生效。原 `hmi status`、`hmi trace`、`lcd status` 保留。

USART1为PA9 TX、PA10 RX，115200、8N1。串口助手在上电前开始保存原始文本。新日志继承HLD前缀，字段解释见 `日志字段.md`。

- `SNAP_REJECT`：冻结首次拒读的真实原因、源及缓存年龄、完整和关键序号、复制及编码耗时；成功输出前不覆盖。
- `SNAP`：每5秒输出最近/最大复制和编码耗时。DWT周期数含任务抢占，不是纯CPU执行时间。降低该新增正常摘要频率是为了给原事务日志留出6000B/s预算；异常记录立即安排。
- `TIMING`新增 `tc=last/max`：请求最后字节捕获至UART TC完成的最近及历史最大周期数，包含完整回复发送。用该行的时钟频率换算；168MHz时除以168000得到毫秒。
- `LCD ui/first/last/count`：UI变化及传输首次/最近故障，每组4行、每秒最多1行。每行带原始发生时间或分组revision，不能按输出相邻就认定事件同时发生。组未输出完成前保留，后续变化合并并补发最新状态。

FIRST、SCREEN及拒读记录优先于LCD；总输出不超过6000B/s、单行小于256B。检查LOGGER的fifo_lost/uart_drop以及SNAP/LCD合并计数。长期接近带宽上限时，LCD组可能延后输出；记录时间仍是实际采集时间。
