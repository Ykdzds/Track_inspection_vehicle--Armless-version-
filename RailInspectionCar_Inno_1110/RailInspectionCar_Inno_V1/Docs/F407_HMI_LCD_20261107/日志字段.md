# 新增HLD日志字段

保留上一轮所有HLD字段和FIRST/SCREEN协议。行首三项仍为十六进制：主控输出/事件时间、boot ID、事件或分组编号。不同boot禁止串接计算。DWT为32位周期计数，168MHz时约25.6秒回绕，差值用无符号32位计算；长时间卡死后的跨多圈值不能独立作为准确时延。

## SNAP_REJECT（冻结首条）

除 `why/ex` 为十进制外，本行数字均为十六进制：

| 字段 | 意义 |
|---|---|
| at | 拒绝发生时主控毫秒时间 |
| req | 请求起始地址/寄存器数量 |
| why | 1非法范围、2未发布源、3读取时源过期、4编码后源过期、5无完整缓存、6完整缓存过期、7非法参数 |
| ex | 实际路由使用的Modbus异常码，当前2 |
| cache/source | 读取前对应缓存年龄/读取判定时源年龄（毫秒）；FFFFFFFF表示无有效观测 |
| seq | 读取前对应缓存序号/同次系统源序号 |
| full/critical | 拒绝时冻结的完整/关键缓存序号 |
| age | 编码前/复制完成复核后的源年龄；未编码时为该拒绝阶段观测值 |
| cycles | 源复制/关键编码耗时（DWT周期，包含抢占） |

同一条未输出记录不被后续拒绝覆盖；合并数量由SNAP的merged给出。普通E事件 `EB`（事件kind十进制11）同时记录 `start,quantity,reason,exception,source_age,cache_age`，全部为十六进制，可能在拥塞时丢失，因此以独立冻结行优先。

## SNAP（每5秒）

所有数值均十六进制：`seq=完整/关键序号`、`src=两份源时间ms`、`copy=最近/最大复制周期`、`critical=最近/最大关键编码周期`、`full=最近/最大完整编码周期`、`age=最近关键编码前/后源年龄ms`、`rejected=累计拒绝次数`、`merged=首条待发期间合并次数`。

复制及编码周期包含中断和任务抢占。最近值与最大值不是同一事件；需结合SNAP_REJECT冻结值定位具体异常。

## TIMING增补

前5个逗号字段保持上一轮定义，末字段为时钟Hz。新增 `tc=最近/历史最大完整响应周期数`，均十六进制。计算：`周期数 × 1000 / 时钟Hz = ms`。仅在请求接收generation与发送完成generation一致时更新，错误/恢复中断的响应不纳入。

E1仍含请求捕获周期，E5含响应提交周期，EA含UART TC周期；同一boot与串行事务顺序可进一步关联具体请求。

## LCD（仅变化）

每组最多4行，单独限速每秒一行，组号为冻结UI revision。数字字段除寄存器外均十进制；寄存器 `sr/cr1/cr2/dma/flags/err` 为十六进制。

- `ui`：at是UI状态发布时间，ready/stage/page是已发布状态；rebuilding表示正在尝试，start/end是最近重建开始/结束（ms），end=0表示仍在进行；rebuild是已返回尝试次数，gen是成功显示代数；clear/reason/clear_at是清屏次数/原因/记录时间；retry是下一重试时刻。reason：1启动清屏、2重建清屏、3切页清屏。
- `first/last`：传输模块整个启动期间首次/最近错误；at是错误时刻，elapsed是真正DMA启动以来耗时，len/left是字节总数/剩余量；reason：1参数、2忙、3轮询、4DMA启动、5DMA或SPI错误、6超时、7DMA停用失败、8重初始化失败。
- `count`：冻结时错误总数、DMA启动/完成数、轮询数、最大传输时间、初始化清屏数及merged。

merged表示输出尚未完成时CLI观察到后续状态变化的累计次数。新的完整组会补发最近状态；首组不被覆盖。UI和传输统计各自原子发布，发布时间不同，不能把它们理解为同一指令的同步快照。首次/最近原始错误时间用于判断先后。

LCD的历史错误位可能持续存在；不能把diag位再次打印的时刻当作新的故障时刻。
