# 主控启动安全停车与上电设零测试

日期：2026-10-03。

## 启动行为

每次主控启动均执行，包括上电、按键复位、软件复位和看门狗复位。2026-10-08起，看门狗恢复在本序列之前执行：支持且核验通过的带速RS485速度轴先保持使能，按独立H06_06参数减速并确认实际停稳；失败禁止继续本流程和使能待机。

1. 关闭本地脉冲和公共门控，不恢复旧运动授权。
2. 选中轴首次有效通信后强制写失能，不信任软件默认使能状态。
3. 获取失能寄存器为0的反馈，以及失能确认之后两次新鲜零速反馈，间隔至少20ms。
4. 所有选中轴停稳后，保持失能配置速度模式，清除速度给定及旧位置触发，并核验。
5. 仅POR启动继续现有H05_30=6设零；非POR跳过设零。
6. 本停车序列自身保持失能；待机开关开启且非只读时，后续统一待机流程使能并确认零速，各类复位均等待新授权。

只读配置不写入。单轴配置不访问未选轴。失能最多提交三次，失败间隔至少100ms；写入有效应答后只重试读取确认。离线等待不消耗次数。首次在线后的失能与停稳阶段限时10秒，模式配置和核验另限时10秒。

## 诊断

USART1发送`status`：

```text
startup_stop ready=1
L startup_state=done attempts=1 disable_ack=1 off_confirmed=1 zero_confirmed=1 failure=0
R startup_state=done attempts=1 disable_ack=1 off_confirmed=1 zero_confirmed=1 failure=0
boot_zero ready=1
```

失败码：1失能写入失败，2失能回读未确认，3停稳超时，4模式准备或核验失败，5驱动器故障。

未完成或失败禁止使能、运动和遥控授权，查询、失能及急停可用。`servo clear`不重新启动本流程。排查后重新启动；上电设零失败仍需排查后重新断电上电。

## 现场测试

1. 在安全工况下让驱动器低速运行，保持驱动器供电，仅主控断电再上电。
2. 抓取USART2报文，确认普通启动停车阶段失能优先、零给定在失能状态下写入；后续待机阶段才允许写使能1。看门狗带速恢复阶段按专项文档确认减速核验、写零、停稳在失能之前。
3. 测量从主控上电到实际停稳的时间，确认两轴停稳后才开始配置及POR设零。
4. 确认H0B_07随H05_30=6清零，`startup_state=done`且`boot_zero ready=1`。
5. 测试按键复位：仍执行停车，但不发送H05_30=6；不恢复旧运动。
6. 覆盖单轴离线、应答丢失、持续非零反馈、驱动器故障，以及后续遥控、速度、位置、脉冲控制。

本方案不保证主控断电期间停车；需另行配置经厂家确认的通信超时停车或独立硬件安全链路。失能应答也不等于机械瞬间静止，实际停车和安全性必须现场测量。
