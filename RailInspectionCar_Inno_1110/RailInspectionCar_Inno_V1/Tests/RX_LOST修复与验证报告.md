# 遥控端 RX / LOST 修复与验证报告

日期：2026-10-23。交付状态：双端软件补丁、针对性回归、兼容回归、固件构建已完成；尚未烧录和取得实物日志，现场底层触发源及全部功能实物验收待确认。

## 1. 结论及证据边界

RX 表示遥控模型最近接受过新的有效状态，不代表上行控制发送成功。上行仍持续而回传超过 300ms 没有新状态，电机可以继续运行、遥控显示 LOST。不能仅由显示状态推断控制链路整体断开。

本次修复两个可在生产代码中复现的软件缺陷：

1. 原模型在 LOST 恢复分支放过重复、旧序号，单个同序号旧载荷可以反复恢复 RX。现同会话、同序号始终拒绝，不刷新在线时间和业务数据。
2. 原主控在 ACK 机会稀疏时按固定优先级选择状态，后台类型可能长期不发送。现采用快速帧有界突发、非快速类型按等待年龄/周期排序及轮转，并优先处理新告警事件。

第二项缺陷本身不必然造成 LOST：只要新 0x81 持续被接受，回传链路仍在线。实物究竟是 ACK 未装载、空口回传丢失还是重复/旧帧过滤，仍须双端同窗口日志确定。不将 ACK 生成、入队、装载当作远端收到或接受的证明。

## 3. 修复行为

### 3.1 遥控新鲜度

- 同会话相同序号：包括 LOST 后均拒绝。
- 相对最新接受序号前进 1～127：接受；255→0 正常回绕。
- 不同会话：保持原有清理缓存并接受规则。
- 同会话 LOST 后反向序号：建立候选；300ms 内第二个相对候选前进的序号才允许重建基准。相同候选不延长候选有效期；过期后重新建立候选。
- 空 ACK、重复帧、旧帧、长度/CRC/格式错误均不更新业务接受时间。
- 此候选机制用于兼容 8 位启动会话碰撞，不提供协议之外的重放鉴别能力；未改变既有协议。

### 3.2 公平调度

- 保持 0x81 目标周期 50ms；其他类型到期时最多连续两帧快速状态；快速等待达到 200ms 时优先。
- 其他到期类型比较等待年龄/目标周期，平分时轮转。首次未发送类型使用从调度开始累计的等待年龄，避免无限年龄偏置。
- 新告警/清除事件优先占用下一个非快速机会；恢复代次改变仅重建调度，保留当前启动会话和全局状态序号。
- 无数据源的 0x85 不参与调度；0x88 按原有开关启停；0x89 纳入公平选择。
- 受限带宽下不承诺所有字段保持新鲜，不扩大过期阈值。OLD/UNK 继续诚实反映数据年龄。

120 秒仿真、0x88 开启的代表性结果（间隔是可入队机会，不是实物空口性能）：

| ACK 机会间隔 | 0x81 最大入队间隔 | 0x86 最大入队间隔 | 启用类型是否均有进展 |
|---|---:|---:|---|
| 10ms | 50ms | 5020ms | 是 |
| 50ms | 100ms | 23100ms | 是 |
| 100ms | 200ms | 46200ms | 是 |

低频参数在受限带宽下数十秒才更新是本算法允许的真实降级。30 秒窗口不足以要求最慢类型至少发两次，回归改为 120 秒，保留全部类型进展、最大间隔、逾期计数断言/输出，不通过放宽 LOST 阈值获得通过。

### 3.3 ACK 修复边界

现阶段只增强底层可观测性，没有凭空改变 ACK 清理和恢复策略。`pending` 是软件等待装载；`fifo` 是已装载等待消费；`wait` 是成功装载前最大等待时间。`ack_clear_count` 是实际 ACK 清理完成数；`ack_clear_by_reason[RECOVERY]` 是故障重建/软件丢弃次数，不代表已完成一次硬件清 FIFO。

## 4. 诊断使用

两端当前默认打开，USART1，115200、8N1，代码配置 TX=PA9、RX=PA10。使用各板对应串口引出点、3.3V 兼容串口适配器并共地；采集仅接适配器 RX 到板端 TX 即可，不向车载屏、伺服或 CAN 口注入日志。主控复用原 CLI 的 USART1 TX DMA，遥控采用 USART1 TX 中断；不修改串口 RX/DMA 配置。

- 主控：`APP_NRF_DIAGNOSTIC_ENABLED=0` 关闭自动摘要。
- 遥控：`REMOTE_DIAGNOSTIC_ENABLED=0` 关闭自动摘要。
- 关闭后仍保留模型/驱动统计及修复，不改变无线功能。
- 忙时丢弃诊断，不等待串口发完。主控每次 CLI 循环最多提交一行，保留 512 字节队列余量；遥控每秒最多启动一次固定 1536 字节缓冲区发送，最多带 4 个事件。

### 主控摘要

每秒快照分 16 个低优先循环输出：

- `RF_BUILD`：构建标识、快照时间、诊断丢行数。
- `RF_RX`：上行有效控制数、最近年龄、最大控制间隔、无线恢复代次。
- `RF_ACK`：生成/软件入队/硬件装载累计数，pending 与 fifo 的标志/当前年龄。
- `RF_ERR`：DMA 超时、SPI 错误、配置巡检失配、最近失败原因、清 FIFO 数、最近清理原因、最大装载等待。
- `RF_STATE`：会话、全局序号、类型、告警代码 `code`（不是告警等级）、告警事件优先次数、快速限突发和紧急优先次数。
- 9 行 `RF_TYPE`：类型的生成、入队、最大入队间隔、逾期次数；0x85 无源及禁用类型为零是预期。
- `RF_CLEAR`：MAX_RT/超龄/TX_FULL/重建原因累计及事件环覆盖数。
- 最多一行 `RF_EVT`：事件自身时间、原因、类型、会话和序号。摘要繁忙丢行时事件留待下周期；其他摘要不重试。

主控事件 kind：1=MAX_RT 清理，2=超龄清理，3=TX_FULL 清理；16+`nrf_failure_t` 为重建事件，例如 18=DMA_TIMEOUT、24=FIRST_ACK、25=ACK_STALLED、26=CONFIG_CHECK。事件记录的头是当时软件 ACK 槽头，仅辅助定位，不证明对应空口载荷已到达。固定环覆盖时会丢失早期事件，不能只靠最后一条事件下结论。

### 遥控摘要

- `RC_DIAG`：TX 成功/MAX_RT/空 ACK/载荷数、错误与队列丢弃、能力探测失败；载荷到达数 `pay` 与最大间隔 `pgap`；新业务接受数 `acc` 与最大间隔 `agap`；重复 `dup`、旧帧 `old`、长度/CRC/格式、候选、失联/恢复、事件覆盖；诊断发送完成/忙丢弃/错误；最新头、接受年龄、告警等级/详情代码/详情年龄及当前显示快照第一行。
- `RC_EVT` kind：1=LOST，2=恢复，3=会话变化，4=重复，5=旧帧，6=恢复候选，7=长度，8=CRC，9=格式。
- `pgap/agap` 是已完成两次接收/接受之间的最大间隔；持续停滞期间应同时观察当前 `age` 和累计数增量。
- OLED 行是软件最近显示快照，不等于拍摄到的屏幕；`code` 是详情缓存原值，需结合等级、详情年龄及匹配判断，不能单独解释为当前告警。
- 为满足固定容量约束，事件可覆盖或因诊断启动失败丢弃；累计计数是主要证据。

### 分流规则

必须比较同一时间窗口的增量，不能把历史累计值与当前故障混用；两端 tick 是各自上电时钟，需要用串口采集机时间和人工工况标记对齐。

| 观测 | 优先排查 |
|---|---|
| 上行控制有效数持续增加，装载不增加、pending 年龄增长 | 主控 ACK 装载状态机 |
| 装载增加，遥控 `ack/pay` 不增加 | 空口回传、模块或接收驱动 |
| `pay` 增加，`acc` 停滞，`dup/old/CRC/format` 增加 | 模型过滤或异常载荷 |
| 恢复代次、DMA 超时、巡检失配增加 | 主控恢复路径 |
| MAX_RT 随距离/姿态显著增加 | 无线质量，并分开观察上下行 |

保留 A2/UNK 的含义：公共头等级为 2，但没有匹配有效详情，不能猜测具体故障。等级为 0 的在线分支为 A0/00，离线为 UNK；若照片确有完整 A0/UNK，先核实烧录版本、照片时刻与日志/OLED 快照，不能直接归因 0x87 丢失。
