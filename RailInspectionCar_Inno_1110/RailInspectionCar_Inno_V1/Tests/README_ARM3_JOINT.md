# ARM3 F407/RK 跨语言主机联测

运行：`Tests/run_arm3_joint_tests.ps1`。可通过 `-Compiler`、`-Python` 指定本机 GCC 与 Python。脚本在临时目录构建 C peer，退出时清理可执行文件；不修改配置文件、不访问 CAN/USB/串口或实体设备。

`arm3_joint_peer.c` 链接实际 `APP/app_arm3.c`、`Protocol/CAN/can_arm3.c`、`can_protocol.c`。Python 端运行实际 `Arm3Session` / `Arm3`。双方直接交换各自生成的实际业务记录，测试代码不另行编码动作、结果、manifest、owner、配置或证明协议。

主机平台与驱动为明确的模拟夹具：F407 平台返回已批准且健康的物理输入，RK 驱动生成独立的新反馈序号、实际采样时刻、写入事件及模拟姿态。左右身份不同。安全配置首次使用真实 kind5 响应做 CRC 校验并必须拒绝；测试随后显式批准此夹具响应的 CRC，等下一次实际查询完成校验，不直接修改协商、许可或配置有效状态。

8 项测试覆盖：

- revision 2 manifest / 5C、45/46 时钟、kind5 安全配置、双侧配置及四个预设、启动双侧运输证明。
- F407 申请/许可、遥控与 HMI 冲突、PC 经同一 F407 仲裁及独立 operation 分区。
- 双臂预设、单侧六轴、灯、非 owner 停止及真实终态传回。
- 遥控点动脉冲、输入失效撤许可并停止。
- 释放后必须收到引用新停止操作的双侧运输证明才能解锁。
- 旧停止重放不得中断后续新点动。
- 双臂动作一侧失败后两侧停止。
- F407 已缓存终态不得被迟到进度覆盖。

该联测验证软件业务记录互通及状态闭环。它不验证 CAN 分片调度、硬件 TX/RX 时刻、总线负载、实体安全输入、厂家停止能力、承载保持或实机运动。不得将通过结果作为实机验收或联合冻结证据。
