## 1. 版本范围

原受控停车实施同时修改主控和 `Remote_control` 遥控端。2026-10-09的K1保持补充仅修改主控，遥控端无需修改。32字节控制帧和冻结版V1.1状态协议的字段、字节序、CRC及单位不变。运行受控停车继续回传既有“停车中”状态；正常遥控K1停稳并确认使能后，保持使能、人工锁存，回传既有“K1急停”状态。

本说明区分主机验证、编译验证和实物验证。自动化通过不代表整车制动能力已经确认，不记录尚未进行的实物验收结果。本轮不提交、不推送Git。

## 2. 配置及理论值

配置入口为 `APP/app_config.h`。本节及第7节的0.5m/s²为2026-10-06原实施记录，非2026-10-09现场值；当前失联/K1参数均为10.0f，本轮保持原值不变，不据此宣称实车安全制动能力：

| 配置 | 当前默认值 | 作用 |
|---|---:|---|
| `APP_REMOTE_SERVO_LINK_TIMEOUT_MS` | 150U | 无线快照与运动入口共用失联期限 |
| `APP_REMOTE_SERVO_LINK_STOP_DECEL_MPS2` | 0.5f | 失联停车减速度，m/s² |
| `APP_REMOTE_SERVO_K1_STOP_DECEL_MPS2` | 0.5f | K1停车减速度，m/s² |
| `APP_REMOTE_SERVO_STOP_UPDATE_PERIOD_MS` | 20U | 新停车批次计算最小间隔 |
| `APP_REMOTE_SERVO_STOP_MAX_DT_MS` | 50U | 单次减速时间上限，延误不追补 |
| `APP_REMOTE_SERVO_STOP_CONFIRM_MARGIN_MS` | 2000U | 停稳及失能确认余量 |

正常调速仍为原20rpm共同斜坡步长、10ms更新配置；同步P参数、USART2、驱动器原加减速参数均保持现状，不在线修改H06_06。两个停车参数分别批准、分别整定，非法减速度不会产生受控运动。

换算使用现有轮径185mm、传动比1:1，传动比定义为电机转数/车轮转数：

```text
停车速率(rpm/s) = 减速度(m/s²) × 60 × 传动比 / (π × 轮径(m))
理论停车时间(s) = 初速(m/s) / 减速度(m/s²)
理论停车距离(m) = 初速(m/s)² / (2 × 减速度(m/s²))
```

600rpm约为5.812m/s、20.92km/h：

| 减速度 | 理论600rpm到0时间 | 理论减速距离 | 说明 |
|---:|---:|---:|---|
| 0.5m/s² | 11.62s | 33.78m | 本轮默认整定起点 |
| 0.75m/s² | 7.75s | 22.52m | 后续独立批准 |
| 1.0m/s² | 5.81s | 16.89m | 后续独立批准 |

上述值不含无线失联检测、按键消抖、帧发送、RS485调度和反馈确认时间，也不等于实际电机或整车停稳时间。通信延误造成限时步进时，命令停车可能更慢；确认期限不会因此延长。600rpm、默认参数的总停车期限约13.7秒，不改变启动待机10秒期限。

K1有效短按在松手消抖完成后立即上报，不再等待原300ms双击窗口；两次短按分别产生短按事件。约1秒长按保留，长按松手不追加短按。其余按键双击行为不变。无线重传沿用事件序号去重，正在发送的缓冲不被K1抢占改写。

## 3. 状态与安全检查

1. 已授权ARMED/RUNNING、速度模式核验通过、所有选中轴在线使能且速度/故障反馈新鲜正常、启动门禁正常时进入受控停车；正常未授权零速使能待机的K1也可进入保持确认，其余情况沿用立即急停路径。
2. 事件到达立即撤权、目标置0、关闭本地脉冲、停止同步补偿，并关闭普通运动写入口。未发送的旧批次取消；已发送速度事务只收尾、更新真实确认命令，不推进旧目标。
3. 独立停车小数进度按实际时间计算，每次最多50ms；指令必须逐轴不增速、不换向。双轴批次锁存后不重算，成功轴不重写，另一轴无需再等待完整20ms。
4. 每轴速度0写成功后须取得两次新序号的实际零速反馈，重复快照不得算两次；故障反馈必须新鲜无故障。停稳表示软件反馈确认，不是机械静止的独立证明。
5. 统一使能待机适用时，失联停稳返回使能零速未授权状态，包含各类复位成功后的待机；待机关闭或不适用时停稳后尽力失能并确认。
6. 正常遥控K1停稳后进入`hold_confirming`，异步回读各选中轴使能配置，全部新鲜有效后保持原使能并人工锁存。确认仍受原停车期限约束，不写失能、重新使能或模式配置；完成后重新回中并产生新的K1长按才可直接从零授权。CLI、模式准备和真实异常继续原失能路径。
7. 停车中链路恢复和长按均不恢复运动。失联停车中K1升级为K1保持结束动作，减速度取已有值和K1配置较大者，期限不重新开始。重复K1不能反复重启停车/保持确认。
8. 真实故障、反馈过期/离线、人工急停、停车写失败、确认超时优先进入失败急停。停车失败不得被后续K1事件改写成可恢复的人工停机；排查原因后按既有安全恢复流程处理。
9. 通信无法确认时只保证主控关闭本地输出、尽力发送停车/失能，不保证驱动器已经执行。仍需驱动器通信保护、机械制动或独立硬件安全链路。

## 4. CLI记录

执行 `remote servo status`，保留已有诊断，并检查新增两行：

```text
controlled_stop state=... reason=... decel=... generation=... elapsed=... timeout=... L_cmd=... R_cmd=... zero_mask=...
controlled_stop first_valid=... first_ms=... zero_valid=... zero_ms=... complete_valid=... complete_ms=...
```

| 字段 | 含义 |
|---|---|
| `state` | idle/decelerating/verifying/disabling/done/failed/hold_confirming |
| `reason` | link_timeout或k1，故障抢占另看原stop_reason |
| `decel` | 本次实际选用停车减速度，m/s² |
| `generation` | 撤权后的停车授权代次 |
| `elapsed/timeout` | 事件处理后的经历时间/独立期限，ms |
| `L_cmd/R_cmd` | 本停车批次锁存指令，不等同于已应答指令 |
| `zero_mask` | 已取得两次新零速反馈的轴，左1、右2 |
| `first_ms` | 事件处理到首条停车写成功提交的时间，不表示驱动器已收到 |
| `zero_ms` | 事件处理到全部选中轴零速反馈确认的时间 |
| `complete_ms` | 最终完成时间，正常K1包含新使能回读确认，失能路径包含失能确认 |
| `*_valid` | 对应时间是否有效；0时不能用数值推断成功 |

定期 `comm stat` 记录USART1 DMA丢弃、缓存高水位、USART2错误增量。长诊断响应沿用原2048字节非阻塞发送缓存，应核对输出完整性，不能通过阻塞运动任务等待串口发送来解决日志拥塞。

新增`k1_hold`诊断行及验收表见`Docs/K1停车零速使能保持与验收说明.md`。运行期保持与上电待机分别记录，`valid`不代表授权，扰动期间不能报告零速保持有效。

|---|---|---|---|---|---|---|---|---|---|
| 待填写 | 待填写 | 失联/K1 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |

另外记录控制帧间隔、失联次数、速度配对有效率、任务心跳/栈余量和USART1丢弃增量。正常无线运行不得因150ms期限引入新增误停车。

必须覆盖：遥控断电、NRF恢复代次变化、K1短按松手、连续短按、停车中长按、停车中链路恢复、失联中K1、单轴通信中断、真实驱动器故障、零速反馈不能到达、使能保持核验失败、失能路径核验失败、POR和非POR结束动作、重新授权必须回中且新长按。正常K1人工锁存点亮红灯但不新增持续蜂鸣；真正异常仍优先原报警。

若允许停车距离仍不能满足要求，应降低最高速度或增加机械制动，不仅靠继续提高软件减速度。本轮默认保留0.5m/s²，实物结果由现场另行追加。
