# F103串口日志降频交付说明

## 修改边界

仅修改两个适配工程的日志任务、日志配置、主机测试和交付资料。F4底盘工程、原始05回退工程未修改；两个工程的can_upper_protocol.c、can_upper_control.c、can_upper_ui.c、can_bus.c与旧哈希清单核验一致。保持115200波特率、500kbit/s CAN、100ms目标刷新和300ms目标租期；不改变协议判定、握手、授权、首零、停车、OLED或按键逻辑。

## 默认输出与配置

- 默认SUMMARY；普通0x180～0x188、0x300～0x302与心跳不逐帧输出。
- STAT和LOG每1000ms各一行；同类型有效记录最多5000ms一次，0x53同样适用，新boot/link token重置记录日志限频。
- RECORD包含type、seq、len、crc、token、match、接收时fresh、LINK；随后至多一行已解码字段。UNKNOWN不冒充有效传感器状态。
- 默认不展开+000/+008等payload。RAW或显式raw宏仅在本次启动前30000ms允许原始输出；帧仅选择UPPER_LOG_RAW_ID（默认0x185），之后回到摘要策略。
- READY/掉线、boot/token、motion token/控制状态、能力发布阶段/重试、命令受理/执行结果即时入队。重复错误同类型首次立即入队，此后1000ms内合并计数。
- 目标0x111每1000ms最多一个TARGET摘要；目标值、token或租期变化即时摘要，不对每个递增seq输出。
- QUIET不输出普通记录/目标摘要，保留关键事件、握手和周期统计。
- 有限静态FreeRTOS队列按错误、会话、运动、记录、普通帧优先级排序；满队列只允许更高优先级替换最低优先级，无法保留的关键事件累计event_drop。日志入队零等待，不在CAN/OLED任务执行UART发送。

配置位于APP/can_upper_config.h：UPPER_LOG_LEVEL、UPPER_LOG_RAW_FRAME、UPPER_LOG_RAW_RECORD、UPPER_LOG_PERIOD_MS、UPPER_LOG_RECORD_PERIOD_MS、UPPER_LOG_ERROR_REPEAT_MS、UPPER_LOG_TARGET_PERIOD_MS、UPPER_LOG_RAW_DURATION_MS、UPPER_LOG_RAW_ID。出厂默认SUMMARY、raw宏均为0。

## 计数解释

| 字段 | 含义 |
|---|---|
| log_drop | 日志队列实际丢失/被替换条目 |
| event_drop | 关键事件实际丢失，不能与主动抑制混淆 |
| frame_sup / record_sup | 普通帧/记录按策略主动抑制，稳定运行持续增加属正常 |
| error_sup | 重复错误合并次数，错误本身仍在协议/CAN累计计数 |
| uart_bytes | HAL_UART_Transmit返回成功的累计字节；超时的部分发送不计入 |
| uart_err | UART调用失败/超时次数 |
| last_error_id / last_error_time | 最近错误关联ID和毫秒时间；FFFF表示CAN全局错误或无具体ID |

能力日志tx_complete只证明F103发送事务结束，accepted=UNKNOWN，不宣称F4业务已接受；需对照F4状态和抓包。RECORD的fresh是生成摘要时的新鲜度，不作为运动安全依据。

## 修复前后对比

| 项目 | 原日志 | 本版本 |
|---|---|---|
| 普通帧/分片 | 大量RX/TX逐帧内容 | 默认仅统计 |
| 记录 | 每约1秒解码并完整展开payload | 每类型5秒摘要，无默认payload |
| 0x111目标刷新 | 可能逐帧打印 | 1秒摘要或目标/令牌变化 |
| 错误风暴 | 重复事件刷屏 | 首次即时、1秒合并 |
| 满队列 | 新事件可能挤掉关键旧事件 | 按级别保留并单独计event_drop |

两版实际日志代码主机测试：QUIET/SUMMARY/RAW共6种组合均通过。覆盖普通帧过滤、0x53摘要、时间0边界、错误合并、优先级与FIFO、token状态、目标摘要、UART计数和CAN心跳/启动帧节拍。模拟稳定流SUMMARY约844字节/秒，QUIET约358字节/秒；仅是特定合成输入下的软件结果，不等于现场串口吞吐保证。启动/故障突发可能高于平均目标。

原单元与F4/F103协议核心联合回归通过；低速授权/首零/正负目标/重复停车/跨源K5/失联/互斥回归通过。记录见Verification/unit.log、pair.log、logs.log、keil_build.log。
