## 3. 操作规则与提示

K2十档循环、短按选择/长按应用不变，100ms刷新、300ms租期、首零确认及±400rpm限幅不变。

| 显示 | 含义 | 操作 |
|---|---|---|
| `ZERO FIRST:APPLY 0`，ERR103 | 非零目标直接反向被拒，原目标仍刷新 | 主动选择0并长按应用；不是短按经过0 |
| `WAIT ZERO`，ERR104 | 已应用0，但参与轴实际反馈尚不满足归零条件 | 等实际归零，再主动长按应用反向 |
| `FB INVALID`，ERR104 | 参与轴反馈过期、失能、故障、模式或状态无效 | 排除异常，不能按键绕过 |
| `TX FAIL:n K3 STOP`，ERR110 | 当前令牌目标帧最终发送失败 | 保存日志；链路有效后按K3确认停车释放 |
| `FAULT:n K3 STOP` | 停车恢复期间仍有真实故障 | 不允许K1清锁，先排查再K3确认 |

- `SELECT`是候选档位，`TARGET`是已应用目标，`WIRE`是协议线速度目标；均不是实际速度。实际值在P4/6查看。
- 103/104分别存储为操作提示；成功应用新目标、主动取消/停车时清除；正常周期TX成功不会清除提示。
- 不缓存、不自动应用反向目标。对无效反馈的重新申请仍失败。
- K3在所有页面有效，仍是本源正常受控停车，不是硬件急停、全局急停或新增快速停车策略。
- 110后K1不清故障、不自动续权。K3幂等合并停止意图；确认新鲜零速、使能、控制权释放及无安全锁后才能恢复到RELEASED。之后用户主动K1重新授权、重新首零。

## 4. 发送实现与诊断

- `Core/Src/can.c`和CubeMX `.ioc`一致开启自动重传；单帧有效期仍从首次入队起100ms，硬件重传和进入邮箱不刷新起点。
- 单在途事务关联代次、邮箱、原始帧、时间、目标序号和令牌。邮箱不再pending不等于失败，等待对应终态。
- 到期取消后等待终态；20ms仍无法清理则停止会话发送并重建CAN。终态消费及硬件RQCP清理在临界区完成，之后才复用邮箱；错误邮箱回调被拒绝。
- 成功/取消竞争按真实完成回调记录。成功不会恢复已被停车/撤权清除的目标。
- 停车/撤权使用独立优先槽并取消在途目标，其他握手/心跳/最新目标优先于能力分片。原周期不改。
- 结果队列满有独立计数及粘滞失败结果，停止发送并触发会话重建，不能静默丢失后继续运动。
- 真实目标最终失败仍报110；主动取消和尚未提交的目标替换不报110。无ACK不是业务拒绝，不能仅靠照片定位物理原因。

`TX_FINAL`输出ID、序号、token、cause、事务代次、帧年龄、邮箱和TSR/ESR；`OP_REJECT`输出拒绝值、原目标、左右反馈及年龄。同类日志最多每秒一次。

| cause | 含义 |
|---:|---|
| 0 | 真实完成成功 |
| 1 | 正常停车/会话变化主动取消 |
| 2 | 未提交目标被新目标替换 |
| 3 | 排队过期 |
| 4 | 在途100ms期限到达，取消确认后最终失败 |
| 5 | 最终仲裁/传输错误或异常终态 |
| 6 | Bus-off |
| 7 | 结果队列溢出 |
| 8 | 20ms取消清理超时 |

TSR/ESR为软件生成终态结果时的寄存器采样，HAL可能已经清除RQCP等完成位，不能把TSR为0当成“没有发生过硬件错误”。HAL累计错误仍在CAN_ERROR/STAT路径记录。`TXSTAT`独立统计cancel、replaced、expired、timeout、result_drop、abort_timeout和recovery；策略抑制不等于真实丢帧。
