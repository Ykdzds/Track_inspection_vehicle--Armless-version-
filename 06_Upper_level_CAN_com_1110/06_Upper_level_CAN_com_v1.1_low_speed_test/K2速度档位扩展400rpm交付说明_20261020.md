## 2. 按键与目标

在P3/6速度控制页，K2短按只选择，长按约800ms应用；K1授权/取消和K3全页面正常停车不变。

```text
0 → +100 → +200 → +300 → +400 → 0
  → -100 → -200 → -300 → -400 → 0 → +100 → …
```

内部10项，循环长度取数组元素数；末尾0为下一轮起始0，不增加连续0档。上电、进入控制页、重新授权、停车完成、链路失效及故障后仍回0。

| 选择rpm | 当前机械配置对应CAN目标mm/s |
|---:|---:|
| 0 | 0 |
| ±100 | ±363 |
| ±200 | ±726 |
| ±300 | ±1090 |
| ±400 | ±1453 |

发送值由F407上传的轴、轮径和传动比实时换算，上表不是硬编码。配置宏与双轴换算限幅统一为400rpm，±401rpm拒绝；下层配置限速和新鲜0x11会话限速更小时，仍拒绝超限目标（本地ERR102），不因扩档绕过门禁。

正反向之间必须先应用0，并等待双轴新鲜反馈归零，再应用反向目标；短按经过0不等于已经应用0。正在减速时选择和应用反向目标仍会拒绝，不自动排队。

## 5. F407当前参数核对（只读，不修改）

| 场景 | 线加/减速度 |
|---|---:|
| 正常加速 | 0.15m/s² |
| 正常减速，包括目标0 | 0.30m/s² |
| 取消授权、K3本源正常停车 | 0.30m/s² |
| 心跳失联、目标租期失效 | 0.40m/s² |
| K5停止CAN控制 | 0.50m/s² |

心跳期限1000ms、当前目标租期300ms；断线时目标租期通常先触发，不能把1秒当作必然停车延迟。停车最大期限30000ms不是固定减速时长。

现有0x080是全局软件受控停车，不是硬件急停；CAN持权时strategy=0按0.30m/s²停车，跨源沿用被停止源的规则，HMI路径为0.50m/s²。strategy=1快速策略关闭。F103 K3使用0x110本源停车，不发送0x080。本次不新增急停功能；真实故障安全接管不能等同于上述恒定减速斜坡。

## 6. 烧录与现场测试

1. 只更新F103，核对HEX哈希。使用Keil现有uvprojx也可重建；不要混用Git基线旧HEX。
2. 不整片擦除启动计数保留的最后两页；沿用原下载配置。上电串口应同时包含AUTHFIX-20261020和SPEED400-20261020。
3. 先固定/架空车辆，确保运动区域、机械条件与实体停止措施适合本次最高速度。确认两端READY、双轴新鲜反馈、无故障及无其他控制源占用。
4. P3/6长按K1，先验证AUTH_PREP→AUTH_WAIT→FIRST_ZERO→ZERO_READY，F407有CAN授权、新motion_token且双轴保持0。
5. 先短按K2选+100，确认电机目标未改变；再长按K2应用，核对目标和实际反馈。按同样方式逐级测试+200/+300/+400，再应用0并等待双轴归零后测试负向档位。
6. 每级分别验证正常降速、K3、K1取消授权、重复停车、重新首零、失联停车和K5跨源停车；重新授权后必须从0开始，通信恢复不能恢复旧目标。
7. 400rpm当前约1.453m/s，需按场地和负载预留充分停车距离；先通过较低档测试再扩大范围，不因软件通过直接开展全速跑车。
8. 保存CAN抓包、F103串口、F407 can/control状态、双轴速度/使能反馈与视频，不只依靠绿色LED判断成功。
